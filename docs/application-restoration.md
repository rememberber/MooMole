# 手动更新后恢复旧版应用

2026-10-31：从确切的成功应用更新记录发起，独立检查、确认后交换完整应用包。旧版回到原安装位置，当前新版留在原先的旧版目录。两份包保留，原更新记录不改写，不自动启动、退出或强退应用，也不触碰包外文档、偏好和数据库；新版修改过的数据可能不兼容旧版，不能称为数据回滚。

新更新的最终 FULL 记录同时保存两端完整路径身份、内容/元数据及 inode 绑定摘要。恢复只接受这种可靠收据；旧历史可继续查看，但不通过重新观察后“认领”现有文件来补造原始收据。每次准备仅用原记录 ID，不接收前端安装或旧版路径；核对当前与旧版仍对应原更新的版本、架构/系统要求、完整静态签名、发布者连续性、Mole/用户保护、管理来源、运行状态、普通账户所有权、可写同一本地 APFS 卷与当前目录身份。

准备在内存中最多保留一份，两分钟到期、单次消耗；重开不保留授权。整包核验继续使用既有 10000 项、64 层、8 GiB 和有界读取规则。确认后复查原记录指纹与当前条件，先写独立 FULL intent，再用持有目录 FD 的 `RENAME_SWAP` 交换。交换后核对双方 inode、完整内容与元数据摘要、签名和路径。取消在交换前停止；已交换不自动反向操作。intent 后的故障或完成记录丢失保留为 unknown，重开不重放。

独立恢复记录最多 64 条，未完成/未知结果需人工核对才能继续本模块更新或恢复；已可靠恢复的原更新不再提供重复交换。停止与安装互斥、检查槽、任务请求所有权随真实工作线程保持至落盘结束。不会删除旧包、新版或历史，也不自动创建登录项/特权助手。

后端已用自建签名 Mach-O App 真正更新并交换恢复，分别验证可靠完成与交换后完成写入丢失；新版/下载源包、包外数据及原更新记录保留，关闭重开后分别读到 restored/unknown，未知阻断且不重放。取消、保护变化、过期、intent 保存失败和无原始收据的拒绝也已验证；没有启动样例程序或操作用户应用。证据在 `.cache/application-restoration-native-completed.json`、`.cache/application-restoration-native-lost-completion.json`。浏览器界面在下一节点接入，不能把原生核心测试称为实际 App 窗口验收。

实际 App 窗口、真实第三方应用数据兼容性、管理器/后台/特权应用、更多安装卷和格式、完整生命周期与便携记录归档仍在完整目标内。
