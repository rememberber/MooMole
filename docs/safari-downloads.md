# Safari 下载整理

2026-11-02：软件清理 → 附件、下载与离线 → 浏览器已完成下载新增 Safari。必须明确选择一份固定下载列表，再扫描、预览、筛选、逐项选择及单独确认移入废纸篓。默认零选择；切换列表撤下旧文件选择和确认资格，重新扫描后才能处理。本流程不删除浏览历史或下载记录，也不遍历整个账户。

## 来源及完成线索

`Standard` 表示 `~/Library/Safari/Downloads.plist`，`Sandbox` 表示 `~/Library/Containers/com.apple.Safari/Data/Library/Safari/Downloads.plist`。这是两处下载列表的来源标识，不是浏览配置名称，不声称区分 Safari 的各个浏览 Profile。只检测这两个确切路径的元数据，不读偏好、账户名、历史数据库、Cookies 或凭据；没有自动替换、合并或到其他位置补扫。访问受限、保护、链接、未知或超限明确保留。

来源布局与 `DownloadHistory` / `DownloadEntryPath` 结构参考作者维护的 [mac_apt Safari 解析实现](https://github.com/ydkhatri/mac_apt/blob/master/plugins/safari.py)。字节计数及取消错误标记参考原始研究 [Analyzing Safari 2.x Web Browser Artifacts using SFT](https://citeseerx.ist.psu.edu/document?doi=6747874323c2c136819071a2a64870e40c4d7537&repid=rep1&type=pdf)。这些资料不是 Apple 提供的稳定下载记录 API 或当代 Safari 兼容性保证；本实现另外要求明确的系统日期类型完成时间，不从相等计数单独推断成功。缺少相应字段的旧格式继续保留。

有界读取后的 XML 或二进制 plist 由系统属性列表解析器解码。候选必须有合理的 `DownloadEntryDateFinished`，接收量与总量均为非负整数且相等，并且没有错误、暂停或续传标记。同一路径出现多条记录时不任意选取其中一条；普通本地文件的当前大小还须与计数相符。布尔/浮点计数、无完成日期、未来或无效日期、部分下载、`.download`、缺失/歧义/未知结构不产生处理对象。对书签数据不做位置解析，不调用安全作用域书签接口，不联网或返回下载 URL。

下载记录只提供来源和完成线索，不认证文件内容、可丢弃性或再次下载能力。系统书签可跟踪已移动文件的范围本轮没有支持，不拿原路径之外的文件替代原记录。新清单正常写入不自动增加旧计划的处理范围；执行继续核对既有来源目录、确切项目身份、最新保护和正式 Mole 规则。

## 读取、处理和收尾

单份列表最多 8 MiB、最多检查 2000 条记录、十秒读取和遍历检查预算、结构化项目输出最多 7 MiB；达到数量或时间上限标记未完整覆盖。不把解析器或阻塞系统调用的预算检查当作硬实时停止保证，沿用软件内容任务的 worker、并发准入、取消及退出收集。

只在内存中读取列表快照，不建立 Safari 数据库副本或长期缓存。只接收固定浏览器/列表标识；文件须在本账户的普通个人位置、同设备、本地落地且为当前用户普通单链接文件。源列表和项目读取前后核对身份、目录、所有权及保护；计划和历史保存确切 Safari 来源，旧的无来源字段仍只解释为历史 Chrome/Default，不改变历史编码含义。

处理复用原有短期确认、明确勾选、逐项同步意图、原生废纸篓、取消/中断核查、持久结果和便携历史。未选文件和原下载列表保留，不清空废纸篓或承诺立即释放空间。恢复权限和完整生命周期边界与其他下载来源相同，不以下载记录代替实际恢复收据。
