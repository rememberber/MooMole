# 应用更新发现

应用列表中普通 App 的“检查更新…”先读取所选副本 Info.plist 中的 `SUFeedURL`、当前版本与构建号，显示确切来源。此步只读本机；用户明确点击“向此地址检查”才请求网络。没有支持的来源或无法比较的构建号时说明限制，仍可使用应用自身更新器或“使用已下载应用包…”。

第一条来源路线支持公开 HTTPS RSS Sparkle appcast。结果区分“此来源报告较新版本”“此来源未报告本机适用的较新稳定版本”“来源信息不足”，不据单一地址声称所有渠道已最新。只比较最多六段纯数字的机器构建号，按默认稳定频道、当前系统和架构、来源声明的最低更新版本筛选；显示独立的人类版本。非默认频道、已知不适用项跳过；无法解释的版本、未知要求或歧义条目使覆盖不完整。数字 `length=0` 视为大小未知，不当作下载大小校验通过。付费/大版本自动更新门槛仅提示用户进一步核对要求。

## 来源与网络边界

每次探测绑定保留的 Mole task/index、应用 bundle ID、物理副本及 Info.plist/主程序身份，有效五分钟；网络返回与打开地址前重查当前保护和原始清单。使用应用操作的共享任务注册、安装互斥与有界 worker。关闭页面撤销来源；迟到结果不授予继续操作权限。取消或等待超时不伪称内核读取已结束，工作线程直到实际返回才释放资源。

请求仅使用无账号信息、标准 443 端口的公开 HTTPS 域名；拒绝 IP、本地/特殊域名和私有/保留网络解析结果。核对全部解析地址后固定 HTTP 连接地址，正常 TLS 校验，不使用代理、不跟随重定向，不请求 release notes 或嵌入网页资源。HTTP 连接五秒、请求十五秒，响应最多一 MiB；XML 限 UTF-8/1.0、32 层、30000 事件、128 项，按命名空间解析，不支持 DTD/自定义实体。系统 DNS 调用可能等待，外层三十秒停止等待但实际线程资源不提前释放。

来源声明及 HTTPS 都不等于安装包签名或发布者认证。本路线没有实现 Sparkle 更新包签名校验，不将读到的版本、长度或链接变成安装许可。用户明确选择某条记录后，后端只接受当前探测和候选 ID，重查身份/有效期/公开地址，再交给系统默认浏览器。此后浏览器自行处理下载、重定向与其网络设置；成功只表示系统接受打开请求，不证明网页打开、下载完成或文件可信。开发验收不会真实打开用户浏览器。

## 接续实际更新

下载并解压可信的新版 `.app` 后，可从当前窗口进入[完整包更新](application-updates.md)。此后重新选择本地包，完整核对版本、签名、发布者连续性、保护、运行状态与替换范围，并另行确认。已有原生复制/交换、旧包保留、取消、持久结果与[恢复旧版](application-restoration.md)保持各自的独立授权边界。发现更新本身不修改已安装应用或用户数据，不自动退出应用。

## 验证与未完成范围

后端自动验证命名空间及旧/新版格式、频道、构建比较、系统/架构/升级要求、未知和歧义、危险 URL/网络地址、取消、来源变化、保护及过期。显式联网样例仅在自动回收的系统 TempDir 创建一份自有 App 声明，读取公开 Maccy appcast，核对结构化结果及原始 Info.plist 不变；不对真实已安装 App 授予更新权限，不下载安装包、不打开浏览器。精简证据收尾合并至 `.cache/verification/native-evidence.json`。

本轮取得一次真实 HTTPS 检查成功；其他显式重跑也遇到连接超时并返回“版本状态未知”。成功样例证明该来源的第一条读取链路，不能证明网络始终可达；不会自动重试或把失败当作已最新。默认后端全量 684 项通过、105 项显式忽略；忽略项不计作通过，联网成功记录单独保留。

界面完成普通 App 列表入口、显示来源、主动联网、结果/未知/过期、候选 ID 的浏览器接力和已下载包独立确认入口，中英日同步。11 项 WebKit 流程覆盖实际 App 列表路由、按来源检查、独立替换确认、未知/不支持/过期/错绑、确切取消、卸载页面后的迟到来源撤销及英日窗口；另有原有应用列表/使用线索/更新/恢复 25 项页面回归通过。前端全量 249 项、构建与语言检查通过。真实原生检查输出经正式 TypeScript 解析器接受；960×780 的中文、英文、日文截图已核对，均无横向溢出。这些页面验证使用浏览器传输夹具，不是打包 App 原生窗口验收。

实际打包 App 的更新发现窗口、浏览器接力和真实第三方应用升级仍待原生验收。应用内可验证下载、Sparkle 包/源签名、其他版本格式和更新框架、App Store/Homebrew/其他管理器对接、更多实际来源与故障矩阵继续保留在完整目标中。本节点只补齐第一条来源发现与人工下载接续流程，不将应用管理或发布验收标记为完成。

协议依据：[Sparkle 发布与 appcast 文档](https://sparkle-project.org/documentation/publishing/)，包括机器构建号、频道、系统/硬件要求、完整包与版本页面、签名和大版本升级规则。未实现的 Sparkle 能力不以“兼容 Sparkle 更新器”概括。
