## 2026-10-15 · 第二阶段：结构化清理审阅

继续围绕 Mole CLI 可视化推进，将清理页从原始终端文本提升为可逐项核对的候选列表，开发缓存测量保持为补充功能。

### 已实现

- 自有 Bash 适配器加载固定版本的原始 `clean.sh`，使用其现有 NUL ledger；不修改上游源码，不通过终端文案决定目标。
- 只读协议 v1，绑定引擎提交及完成标记；校验编码、数值、路径、重复项和父级覆盖关系。
- 任务独立临时目录及输出上限，文本预览不覆盖用户原有的 Mole 预览文件；禁止本流程请求管理员权限。
- 分类展开、搜索、大小/路径排序、状态筛选、每页 100 项、本页全选及逐项勾选审阅。
- 对所选子集重新计算父子覆盖；未知大小单独提示，不累计为零或重复计量。
- 从目录候选添加保护；通过字面路径和解析别名匹配重叠项目，实时取消父子项勾选；保留 Mole 自有白名单。
- 原始日志可展开，清楚标记 dry-run、范围可能不完整及勾选不执行清理。

### 验证证据

- `npm test`：5 项通过，包含选中子集计量、未知父项、字面通配符、同名前缀兄弟路径及解析别名保护。
- `npm run check:rust`：10 项常规测试通过；新覆盖协议截断、非法 UTF-8、版本、数值溢出、重复记录和错误父级关系。
- `npm run test:adapter`：隔离 fixture 通过，调用实际 Mole ledger 函数，验证特殊字符/换行路径、去重、父级覆盖及空扫描生命周期。
- `npm run test:e2e`：5 项通过，包含逐项勾选统计、筛选、日志展开和新增保护后立即排除已选父子项。
- 显式本机只读 smoke 测试通过：Mole 返回 953 个候选路径，Rust 结构化解码通过。
- 原生打包窗口完成真实扫描：953 个候选、已测量约 10.1 GB，显示 10 页；验证第二页访问、Homebrew 路径搜索、详情展开与 67.5 MB 条目勾选统计。验证后清空勾选，保留结果供查看，未更改用户保护设置。
- `npm run tauri -- build --debug --bundles app`：本地 App 构建通过，约 48.15 MiB；格式、TypeScript 与前端构建检查通过。

### 当前边界与下一步

本阶段仍无删除接口。候选 ID 和引擎去重键不作为可执行计划；勾选只存在当前页面内存中，离开页面清空。尚未提供逐项清理影响、完整权限证据、冻结身份或有效期；客户端保护限制审阅，未来执行端仍必须统一验证保护列表和 Mole 规则。

下一步建立持久化扫描/执行计划和执行前验证，在隔离目录覆盖目标消失、身份替换、路径换成链接、过期计划及保护变化，再开放与选中项严格一致的受控执行。无付费签名及手动 DMG 更新约束继续有效。

## 2026-10-15 · 第三阶段：持久化审阅计划与元数据复核

用户继续开发后，推进扫描结果与审阅计划的后端基础，仍不开放删除。

### 已实现

- SQLite v2，升级前通过 `VACUUM INTO` 备份 v1 数据库；保留既有设置与历史。
- 保存最近 10 份扫描及最多 20 份关联审阅计划，单份 JSON 上限 8 MiB；遵循历史保留期限，不保存原始 stdout 日志。
- 后端分配扫描命名空间及候选 ID；前端仅提交扫描 ID 和选中 ID，拒绝未知、重复或跨扫描项目。
- 扫描结束时核对 Mole inode 键，记录目标/祖先的设备、inode、类型/模式、所有者/组，以及目标大小、mtime/ctime 与纳秒。
- 保存和重新查看计划时复核有效期、版本、当前客户端保护、目标和祖先元数据；拒绝符号链接、特殊路径和无法确认的目标。
- 扫描后 15 分钟到期，保存计划不延长有效期；识别系统时钟回退。
- 清理页保存审阅计划，历史页查看和重新复核；重启恢复最近扫描，未保存勾选不恢复。
- 已保存保护目录即使消失/无法访问也保留规则，不再阻塞无关设置；新增目录仍须验证。

### 验证证据

- Rust 常规测试 16 项通过，另有 1 项显式真实扫描测试默认忽略；新增覆盖数据库 v1 备份升级、历史保留、扫描/计划重启恢复、外键及数量上限、失效保护规则保留，以及计划的过期/重复/跨扫描/替换/消失/链接/祖先变化。
- 前端单元测试 5 项、Shell 适配 fixture、浏览器交互测试 6 项全部通过；浏览器新增计划保存、选中范围及复核后变化提示。
- TypeScript、Vite、Prettier、Rust 格式及 diff 空白检查通过；本地 debug App 约 49.14 MiB。
- 原生 App 首次打开完成真实 v1 → v2 升级，生成 1 份备份，原有任务历史保留。
- 新的原生扫描返回 967 个候选、约 10.1 GB 已测量值；选中一份真实 Homebrew manifest（约 13 KB），保存计划并通过元数据复核。
- 退出并重启 App 后恢复 967 项扫描及原扫描时间，勾选为 0；从历史页重新打开同一份单项计划，再次读取元数据并显示未发现变化。

### 当前边界

该计划是只读审阅记录，始终标记需要 Mole 规则复查；元数据复核未变化不等于可执行或安全删除。扫描结束时的属性观测不构成扫描全程一致快照，目录根属性不能证明全部递归内容未变化，检查与后续文件操作之间的竞态也还未封闭。

下一步接入有效保护规则、活动应用与逐项影响复查，设计受限执行端，在隔离目录验证按选中项处理、递归内容变化、取消和部分失败后，再提供真正执行。当前没有删除或按任意路径执行命令的 IPC，也未改变系统安全设置或付费签名约束。

## 2026-10-15 · 第四阶段：可取消的 Mole 路径规则复查

先将上一阶段的结构化审阅及持久化计划提交为 `a0444f9`，再继续适配 Mole 保护语义。

### 已实现

- 计划弹窗新增“复查 Mole 规则”，展示逐项规则来源、原因及复查时间；历史查看仍保持轻量的本地元数据复核。
- 自有只读 Shell 适配器加载固定上游源码，直接调用核心保护、有效白名单、模型缓存、活动缓存和适用时的 SQLite 占用函数，不解析终端文案，不调用清理生命周期。
- 独立 NUL 请求/响应协议绑定 ID、路径、版本与完整结果；缺项、重复、未知状态和截断均报错。
- 尊重上游“活动或无法确认空闲”的合并语义；非法/不可读取白名单、占用不确定、探测错误均不作为通过。
- 复查注册为受限任务，支持取消、45 秒超时、退出清理进程组、私有临时目录与 8 MiB 报告上限。
- 探测结束后再次复核客户端保护、文件身份和有效期；规则通过不会覆盖本地失效。取消或失败清除旧的通过结果。
- 规则结果仅在当前弹窗内存中展示，保存的计划仍为只读，真正执行前仍须重新检查。

### 验证证据

- Rust 常规测试 19 项通过、1 项显式真实扫描测试默认忽略；新增协议绑定/截断/去重/非法状态、复查进程组取消、规则通过不覆盖新增保护或计划过期。
- 前端单元测试 5 项；浏览器测试 7 项，新增逐项 Mole 证据显示及取消后不保留旧通过结果。
- Shell 隔离 fixture 通过：特殊字符/换行路径、真实白名单及模型保护、被当前 Node 进程打开的测试数据库、未知占用、异常返回码、不完整请求、非法策略。所有 fixture 仅位于测试临时目录，未改写用户白名单。
- 原生打包 App 对既有单项 Homebrew manifest 计划完成真实 Mole 路径级复查，显示“本次路径级检查未要求保留”及复查时间；人工检查深色原生界面和浏览器弹窗布局。
- TypeScript/Vite、本地 App 构建、Prettier、Rust 格式及 diff 检查通过；debug App 约 49.29 MiB。

### 后续边界

当前路径级结果不等于完整清理规则审计，更不是执行授权。逐项影响、递归内容变化、执行时的竞态封闭和受限执行端仍待完成；下一阶段先在隔离目录验证按项处理和部分失败，再考虑开放真实操作。免费分发和手动 DMG 更新约束保持有效。
