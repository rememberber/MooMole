# 按项执行：隔离实验与上线边界

更新时间：2026-10-16。此文记录实验结果和后续设计约束，**不是已经开放的清理协议**。

产品继续以 Mole CLI 可视化及人性化扩展为主线。正式清理必须处理用户明确审阅的项目，不能再调用一次全量清理替代选中范围。

## 当前实现

`src-tauri/src/execution_sandbox.rs` 只在 `cfg(test)` 下编译，不进入 App，没有 IPC、页面按钮或访问真实清理目录的入口。每个实验自行创建临时私有根目录，只在其 `source`、`recovery` 和日志文件之间操作。文件、规则结果和故障均为 fixture；测试结束由临时目录所有者清理。

实验复用当前扫描捕获、选中项计划生成及 `review::check`，执行入口以保存的计划 ID 查找项目。只实验直接子级的普通、单链接文件；目录即使通过只读审阅也拒绝处理。规则证据必须明确为 `passed-fixture`，它不调用 Mole，也不能用于真实授权。

文件移动使用持有的目录描述符和 macOS `renameatx_np(RENAME_EXCL)`，目标已存在则失败，不覆盖。实验的 `recovery` 是同卷私有目录，**不是 macOS 废纸篓，也不表示已释放磁盘空间**。

## 按项结果与记录

| 状态 | 实验含义 |
| --- | --- |
| `Intent` | 请求同步写入该项处理意图，尚无完成证据 |
| `Moved` | 移入实验恢复目录，并核对目标元数据身份 |
| `Skipped` | 本地条件、范围或 fixture 规则不符合要求，没有尝试移动 |
| `Failed` | 意图写入前的注入失败，或文件移动返回错误 |
| `Cancelled` | 开始该项之前收到取消；已经完成的项保留原结果 |
| `Interrupted` | 意图没有最终记录，或移动后的身份无法核对；不能显示成功 |
| `NotStarted` | 发生不确定结果后尚未开始的后续项 |
| `RestoreIntent` / `Restored` / `RestoreFailed` | 独立记录恢复尝试、完成或明确失败 |

实验 NDJSON 记录绑定计划与项目 ID；普通文件身份记录包含设备/inode、权限、所有者、大小和修改时间。意图记录先于操作，完成记录后于实际移动及核对，写入时调用 `sync_all`。截断/损坏日志停止自动动作，未完成意图重读为中断。已有尝试记录的计划不会自动重放；中断项不自动恢复。

恢复仅接受完成的移动记录或明确失败的恢复尝试；先核对恢复目录中的目标与收据，再尝试原位置恢复。原位置已有文件时保留双方，不覆盖。恢复对象被替换、修改或换成链接时停止处理。元数据核对不是正文校验。

这里验证的是进程内故障注入及日志重新读取，不是断电持久性认证。磁盘满、只读卷、权限拒绝、真正进程崩溃、挂载消失、目录重命名持久性与 Apple 文件系统同步语义仍需专门验证。实验日志也没有接入用户 SQLite，不应描述为已经完成执行历史功能。

## 已验证的 8 组场景

1. 从三项中仅选择两项，实际移动并恢复；未选中的文件保留，支持中文、空格、换行及 glob 字符；未知计划被拒绝。
2. 中间一项与恢复目录中的文件重名，产生部分失败，其他项可完成；移入和恢复均不覆盖已有文件。
3. 第一项完成时取消，保留该项完成结果，后续项不开始，没有后续移动意图。
4. 当前客户端保护、计划到期和未知 fixture 规则阻止移动。
5. 目标消失、换成链接、增加硬链接或属于目录时跳过，不跟随链接对象。
6. 意图写入前、意图后、移动后最终记录前的故障注入；区分未尝试和结果不确定，不自动重放。
7. 最后检查后源名称被替换的竞态，操作后检测异常、停止后续项并保留现场。
8. 恢复对象替换、修改、换成链接，以及日志截断时拒绝自动恢复/继续。

## 实验暴露的竞态

第 7 组刻意在打开并观察原文件后，先将原文件改名，再在同一名称创建替代文件。按名称进行的移动仍可能移动替代文件；持有父目录描述符与禁止覆盖并没有把源名称锁定到观察到的 inode。

实验在移动后发现身份不一致，将结果标为中断，保留原文件和替代文件，拒绝自动回滚，且不再处理下一项。**测试通过表示能复现并识别这个问题，不表示已经防止错误对象被移动。** 因此不能把该实验提升成真实清理接口，也不能声称“先检查、再移动”已解决竞态。

## 只读观察的后续加固（2026-10-16）

扫描/计划现已复用路径观察 v2：逐级相对打开、保留祖先句柄、观察结束前验证路径绑定；目录摘要 v2 还复查子项与所选根绑定。隔离测试覆盖打开/遍历期间的源、父目录及内容变化，同时证明深层内容在观察后的晚期变化仍可能漏过本轮摘要。它没有接入修改器，也没有消除上文按名称移动的最后窗口。详细实现与边界见 [路径观察](path-observation.md)。

## 开放真实操作前继续完成

- 确定首批操作范围与处理方式，验证 macOS 废纸篓真实 API、同卷/跨卷、空间统计和 Finder 恢复行为。实验私有恢复目录不能替代该验证。
- 结合 Mole 模块级规则、活动应用语义和最终身份核对，确定并验证源名称替换、父目录替换、内容并发变化的处理策略。无法满足策略的范围不开放。
- 使用真实、当次的 Mole 规则结果；保护读取、权限判断和活动状态不确定时停止，不能复用 `passed-fixture` 或过往弹窗证据。
- 已新增生产记录层的 SQLite v3 迁移、事务及启动对账，详见 [执行记录协议](execution-journal.md)；尚未连接真实执行器。无法确定的结果保留待核实，不自动重试，取消仅停止后续项。实际进程崩溃/断电与真实磁盘满仍需验证。
- 将用户确认绑定不可变的计划、选中项、操作方式、影响及有效期；前端只传 ID，执行端再次验证。永久删除、清空废纸篓另设协议与确认。
- 补齐真实权限/卷/崩溃矩阵后，再提供可用的执行按钮和逐项结果界面。无付费 Apple 开发者签名能力仍是实现约束。

运行实验：

```bash
node scripts/cargo.mjs test execution_sandbox
```

该命令只创建和处理自己的临时 fixture，不运行真实 Mole 清理，不修改个人缓存或应用目录。

## 原生废纸篓兼容性检查（2026-10-15）

新增 `native_trash_tests.rs`，同样只在测试中编译。普通测试只在临时目录验证 URL 观察行为；真实废纸篓检查默认忽略，需显式运行：

```bash
node scripts/cargo.mjs test native_trash_tests::native_trash_round_trip_smoke -- --ignored --exact --nocapture
```

本机 macOS 27.0.1 / Apple Silicon 已验证：Foundation `NSFileManager.trashItemAtURL` 接收 2 个同名普通文件和 1 个含子文件的目录，返回各自的实际位置；核对设备/inode、类型与内容，使用 Foundation 移动接口恢复原位置。恢复遇到新建的同名文件时返回失败并保留双方，移开该新文件后显式重试成功。所有测试项均已恢复，随后清理自身 fixture 根目录；没有枚举其他废纸篓内容或清空废纸篓。

首次尝试通过 POSIX 描述符打开废纸篓目录后恢复，被系统以 `EPERM` 拒绝；改用 Foundation 移动接口后通过。首次失败的 3 个专用 fixture 也已逐个核对内容并取回。本结果只说明当前机器、账户及测试进程下的兼容性，不证明所有权限环境相同，更不证明正式 App 已具备完整恢复功能。

系统可能调整同名或特殊字符名称，必须使用 API 返回的实际目标，不能推测废纸篓路径。实验收据写入忽略目录 `.cache/native-trash-smoke.json`，失败时保留根目录及收据以便检查；它不接入用户数据库。

两个普通测试还验证：文件引用 URL 可以在同卷改名后继续定位原对象，但也会跟随对象移出原选择的父目录。因此引用 URL **不能单独作为路径范围授权，也没有证明 API 内部不存在名称替换竞态**。真实执行仍需当次 Mole 模块规则、范围/身份/活动状态复核和明确的并发变化策略。

依据：[Apple 文件定位说明](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/AccessingFilesandDirectories/AccessingFilesandDirectories.html)、[移入废纸篓接口](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:))、[移动接口](https://developer.apple.com/documentation/foundation/filemanager/moveitem(at:to:))，并核对本机 Xcode SDK 的 `NSFileManager.h`、`NSURL.h`。Apple 的文件引用说明明确区分进程运行期间的引用与跨启动的持久记录，本实验不将引用 URL 持久化为下次执行凭据。

同卷与当前账户的实验不能替代跨卷、Finder“放回原处”、普通账户/权限拒绝、真实发布包及干净机器验证；这些仍是待办。
