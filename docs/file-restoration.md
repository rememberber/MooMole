# 从操作历史恢复原位置

2026-10-30：个人文件整理和重复文件的可靠完成项目，可在活动执行历史中选择“恢复原位置…”。先重新检查当前收据位置与原位置，显示确切路径，再单独勾选确认，执行一项恢复。原收据只是核对依据，不直接授权恢复。

第一节点支持当前账户目录中的本地普通文件、同卷移回。原目录必须仍存在，原文件名必须空闲；同名冲突、目录缺失、文件变化、符号链接、共享硬链接、云占位或保护范围重叠时保留。不会覆盖、自动改名、创建目录、跨卷复制或关闭正在使用文件的应用。首批不接受缓存清理、应用包、未知结果或归档记录直接发起恢复；这些扩展仍在完整范围内。

恢复使用独立的结构化计划，绑定原批次、原项目、原快照摘要、实际收据和当前文件/目标目录见证。确认单次使用，墙钟和单调时间共同限制三十秒有效期。系统调用前重新读取原记录、保护和身份，沿用不覆盖的同卷原生移动。取消只阻止尚未开始的调用；已经移回不再自动撤销。未知结果不自动重试。

持久记录沿用 SQLite v8 的 move 方式，但快照来源独立为 `fileRestoration`，包含原收据关联。执行前先提交 FULL 同步的意图，另存恢复结果与实际位置；原处理记录保持原样。重启不重放，意图未完成按既有中断机制核查；恢复记录支持已有 v3 执行归档，不会从归档重建执行许可。

基本验证：自建文件先真实移动，再通过新恢复执行器移回，核对内容、原记录不变、一次性确认、重开数据库及 v3 归档读回；冲突、替换、保护、未知结果、父目录变化和提前取消有基本验证。前端新增选择、确认、确切路径和取消回归，并回归执行中断/归档，共十二项浏览器流程通过；203 项前端单元测试通过。arm64 release App 已构建并通过 ad-hoc、嵌套程序及 ZIP 解包校验，新入口的实际窗口验收仍待补充。

**尚未完成的废纸篓验收：** 自建样例真实移入废纸篓后，当前进程无法打开 `~/.Trash` 目录（macOS 返回 Operation not permitted），恢复检查因而拒绝；没有修改权限或绕过保护。样例通过测试专用的 NSFileManager 精确取回原路径，身份与内容核对后清理。该取回不算产品恢复成功。真实废纸篓恢复的显式原生测试仍保留为未通过的手动验收项，不把普通目录成功扩大为废纸篓成功。
