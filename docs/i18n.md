# 中英日界面与 README

2026-10-28：支持简体中文（zh）、英语（en）、日语（ja），设置入口为“设置 → 通用 → 界面语言”。默认 `system`：首次启动按系统第一首选语言匹配语言子标签（zh-Hant、zh-TW 也使用现有简体中文译文）；不属于三者则使用英语，不继续选择系统第二语言。手动选择持久保存，重新启动继续生效，也可恢复跟随系统。

## 实现边界

- 原生启动通过 Core Foundation 读取系统首选语言并随 bootstrap 返回，避免把 WebView 的语言当成唯一依据。浏览器预览使用 navigator.language。`src/i18n/locale.ts` 维护当前语言和区域格式，日期、数字与列表排序使用对应 locale。切换语言会刷新排序和搜索缓存，维护用途、任务类型与历史命令支持当前语言搜索，同时保留原文和固定 ID 搜索。
- 设置接口增加 `language`（system/zh/en/ja），SQLite 使用独立的可选 `language_preferences` 表保存，原四字段 settings JSON 不变，以兼容旧版的严格字段读取。旧库未存语言时默认 system，读取不建表、不提升数据库 schema。语言与其他设置在同一事务提交。保存失败不切换；保存成功后更新界面，保留页面、输入与任务状态。预览设置单独存储在浏览器 localStorage，不与原生数据库混用。
- `src/i18n/messages.json` 每行是 `[中文原文, 英文, 日文]`，中文作为来源键。JSX 运行时适配层只在 React 创建原生展示元素时翻译文本和可访问名称，不改变组件类型、key、ref、value、回调、结构化协议或执行对象。相邻文字与数字按完整句子匹配模板，保留空槽以维持后续元素的索引与状态。语言切换通过 React 重绘，不修改 DOM 中的文本节点、不重新挂载整个应用、不重复启动任务。
- macOS 菜单栏、原生目录选择、诊断保存、归档导入/导出标题按所选语言显示。菜单保留 Tauri 标准角色、快捷键与系统行为，仅更新文案。系统自行添加的菜单项和文件窗口标准按钮仍由 macOS 决定，App 提供的标题按所选语言显示。启动工作区失败时尚不能可靠读取设置，使用系统语言。
- 路径、文件/应用/进程名称、pre/code、mono 字段和显式 `data-i18n="off"` 保留原文。增加用户来源文字时应标记原文边界，不以翻译后的文本参与保护、身份、选择或执行判断。未知的上游日志、原生诊断与已有 AI 报告保留原始证据，不臆造翻译。新 AI 扫描按提交时的语言要求模型生成用户说明；JSON 键、枚举、证据 ID 与路径不变，切换语言不会重发模型请求。
- 开发时 JSX 运行时保持为源码模块，禁止依赖预构建产生另一份语言状态；React 自身运行时仍使用常规预构建。开发/生产共用翻译实现。

## 文案与检查

`README.md` 为英文入口，`README.zh-CN.md`、`README.ja-JP.md` 提供中文和日文；顶部互相链接，功能范围、风险、上游致谢、官方产品、免费分发、开发与恢复说明保持一致。详细开发文档目前仍主要为中文，三份 README 如实说明。

新增界面文案时补齐三语，并保留所有未知、过期、受保护、不可执行与恢复限制。`npm run i18n:check` 使用项目现有 Vite/Rolldown 解析器检查组件、工具函数和目录 JSON 的来源文案与完整 JSX 句子是否有翻译；构建自动运行。占位符一致性、语言匹配、展示边界和格式由单元测试检查。浏览器回归覆盖首次启动、英语回退、即时切换、页面输入保持、重启持久化、原生系统语言优先和保存失败。原始引擎输出不作为删除对象的决定来源。
