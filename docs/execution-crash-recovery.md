# 执行记录的进程崩溃回归与中断提示

2026-10-17 初版：SQLite v3，当时真实清理执行器尚未接入，先将记录层验证扩展到独立进程 SIGKILL。2026-10-20 已新增正式日志循环和 Foundation Trash 两侧关口的强杀验证，见本文末节；两类证据分别说明，不等同于发布 App 的完整故障矩阵。

## 实际验证方式

`src-tauri/src/execution/tests/crash.rs` 仅在 Rust 测试中编译。父进程创建独立临时目录、三个普通文件和 SQLite 扫描/审阅计划，仅选其中两项；目录先显式设为 0700，再捕获路径观察。测试副进程核对临时根、当前用户与启动 nonce，经过 `db::open_owned` 获取占用权，调用生产 `begin / intent / complete_item / finish` 记录接口。

测试驱动只在自己的 `source/recovery` 两个目录之间移动直接子文件，使用持有目录描述符的 `renameatx_np(RENAME_EXCL)`，不覆盖已有目标。它不是原生废纸篓，不调用真实 Mole 清理或规则，也不授权生产执行。源名称替换窗口仍与原隔离实验一样存在，不能由此声称已解决。

副进程到达指定检查点后通过原子发布的 marker 告知父进程，随后阻塞在管道上。父进程先确认第二次生产初始化返回 Busy，再使用仅只读连接观察已提交记录；之后确实发送 SIGKILL 并核对退出信号。只有确认子进程退出，才调用生产初始化接管和对账。全部子进程由 guard 在失败时终止并回收，未选文件必须保留，所有文件都属于测试新建目录。

## 八个终止时点

每个批次有两项，A 在前、B 在后；下表的状态均为 SIGKILL 后重新取得占用权并完成启动对账的结果。

| 强杀时点 | 批次状态 | A / B | 验证重点 |
| --- | --- | --- | --- |
| 批次已提交，尚无意图 | interrupted | notStarted / notStarted | 不虚构尝试，两份源文件保留 |
| A 意图已提交，尚未移动 | interrupted | uncertain / notStarted | 不把只有意图显示为失败或成功 |
| A 已移动，尚无结果记录 | interrupted | uncertain / notStarted | 源文件已不在原位置；不编造收据，不自动恢复或重放 |
| A 结果已提交，B 尚无意图 | interrupted | moved / notStarted | A 的实际目标收据、事件顺序与身份保留 |
| A 已完成，B 意图已提交 | interrupted | moved / uncertain | 保留 A，B 待核实；有在途意图时取消结算仍拒绝 |
| 两项结果均已提交，尚无批次结束 | interrupted | moved / moved | 不凭逐项完成擅自补造批次完成事件 |
| 批次完成已提交 | completed | moved / moved | 原最终状态及全部事件不变 |
| A 完成后取消已提交 | cancelled | moved / cancelled | 已完成项保留，未开始项保持取消 |

另外检查接管仍使用同一占用文件 inode、启动前后源/恢复目录的位置和正文不变、收据的设备/inode 匹配、已提交事件前缀不变、重复重启不重复追加对账事件。同一计划不能再建立批次；存在 uncertain 时另一计划也被记录层拒绝。整个测试不会根据实际位置探测并“补成功”。

运行方式：

```bash
node scripts/cargo.mjs test execution::tests::crash
```

三个 Rust 测试入口包括两个矩阵测试及一个受控子进程入口；正常全量测试也执行矩阵，不需要准备 Mole 引擎或启用忽略项。

## 用户可见行为

启动读取现有执行摘要时，任一 interrupted 批次或 uncertain 项会在各页面顶部显示提示，说明受影响批次数、待核实项数与已记录移入的项数。已经取消或成功的其他批次不计入该提示，也不会因普通只读任务中断触发。

“前往执行记录”切换到操作历史并将焦点与滚动位置定位到执行记录区域，随后仍由用户打开逐项详情。焦点定位只响应这次按钮操作，普通页面切换不会重复抢焦点。提示不自动继续、恢复或重新核查文件，也不增加解除待核实的写入接口。

执行列表刷新成功后同步更新全局摘要；刷新失败保留已有证据和提示。没有相关记录时不展示提示，保持正常只读检查。提示与 Mole CLI 原始日志无关，不按日志时间猜测恢复状态。

## 验证边界

这里验证的是当前机器、SQLite WAL/FULL 设置下，**明确提交边界处的进程死亡**。没有模拟设备断电、文件系统丢失写入、提交内部任意指令、磁盘满、跨卷或操作系统调用中途停止，也没有执行真实废纸篓接口。相关矩阵继续保留待办。

中断提示使用浏览器专用 fixture 验证，不向用户数据库写入模拟执行记录。提示只引导查看，不自动执行修改。当前受限日志的独立确认、规则与范围门槛已接入，运行详情还可按绑定批次请求停止后续项；完整权限/卷与 App 故障验收仍待完成。

## 正式日志循环与原生废纸篓的五个强杀关口（2026-10-20）

新增 `log_cleanup/tests/native_faults.rs`，在正式 `run_observed` 循环上增加仅 `cfg(test)` 存在的检查点。副进程重新获取临时数据库的独占权，重新建立一次性 fixture 确认，使用真实文件身份、权限准备和 Foundation Trash；正面 Mole 规则明确为 fixture，不等于真实占用检查通过。所有源文件均在专用临时 HOME 的单层 Logs 中；父目录先设为 0700，子进程核对当前账户、规范临时路径、控制 nonce 和选中范围。初次因临时根不是 0700 被子进程拒绝，修正创建方式后通过，没有放宽子进程准入。

| 强杀时点 | 重启后批次 | A / B | 实际结果 |
| --- | --- | --- | --- |
| 批次提交，尚无意图 | interrupted | notStarted / notStarted | 不虚构尝试 |
| A 意图已提交，尚未调用原生接口 | interrupted | uncertain / notStarted | 只有意图仍需核实 |
| A 原生调用返回，尚无 SQLite 结果 | interrupted | uncertain / notStarted | A 已移入，但 SQLite 不补造成功或收据 |
| A 结果提交，B 尚无意图 | interrupted | moved / notStarted | A 的已提交结果及实际收据保留 |
| 批次完成已提交 | completed | moved / moved | 最终状态不因重启回退 |

父进程等到明确检查点 marker 后发送真实 SIGKILL、核对退出信号并回收，再通过 `db::open_owned` 对账；子进程存活时另一个初始化必须 Busy。恢复前后比较源文件状态，启动不会依据路径或测试救援报告补成功；再次启动记录完全相同，同一计划无法重放。

为了取回自己的原生测试文件，测试检查点在原生 API 返回后、SQLite 写结果前，将实际返回收据写入独立且同步保存的 `rescue.json`。它只用于父进程按确切路径核对设备/inode 后取回自建文件，不是 App 数据或恢复能力，也不会导入生产记录。所有原始与未选文件的内容验证一致后才清理临时根；失败保留根与报告，不枚举或清空既有废纸篓。仅凭这项救援旁路的存在不能声称正常 App 已有可靠恢复收据：在第三个关口，正式 SQLite 仍必须显示无收据的待核实。

```bash
node scripts/cargo.mjs test --locked log_cleanup::tests::native_faults -- --ignored --nocapture
```

新增权限联验还在意图提交后，分别给自建 Logs 加扩展 ACL、不可更改属性或撤回写权限。生产最终门槛拒绝调用废纸篓，当前项 failed 且明确未修改、无收据；测试随后按绑定批次取消下一项，已有结果不丢失。执行器没有解除限制，测试所有者在验证后仅还原自己创建的限制。

这是生产日志循环与本机真实原生操作**两侧明确关口**的证据；不覆盖系统 API 内部任意指令、真实 App/TCC 身份下的隐私拒绝、Cocoa 退出、休眠/断电、跨卷或 Finder 放回。检查点、控制环境变量和救援路径仅进入测试程序；本轮 release App 二进制已核对不含 `MOOMOLE_LOG_CRASH_ROOT/NONCE` 开关。
