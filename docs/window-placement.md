# 窗口尺寸与位置恢复

2026-10-23，阶段 114。主窗口在正常退出时记住最近一次普通窗口尺寸和位置，重新打开时尽量沿用；不增加设置项或额外工具栏按钮。

## 用户行为

- 尺寸使用逻辑像素保存，位置使用系统物理坐标并保留当时缩放比例。启动按当前显示器工作区调整边界，菜单栏和 Dock 所占空间沿用系统报告，不从屏幕总分辨率猜测。
- 原窗口与当前屏幕重叠时选择重叠最多的可用工作区；原屏幕消失时优先主屏幕。尺寸受原有 960 × 680 最小布局约束，过大的窗口按当前工作区收小，位置调整到工作区内。不扩大为已完成真实混合 DPI、显示器热插拔或全部系统版本验收。
- 不恢复最小化、隐藏、最大化或全屏状态；这些状态不覆盖最近普通窗口几何。启动仍显示普通窗口，不恢复上次检查页面、滚动、选择或运行任务。
- 主窗口在后端取得数据目录占用权、尝试几何恢复后显示。重复实例或数据启动失败仍显示原有错误窗口及原生说明，不取得正常 AppState，也不保存窗口偏好。

## 存储和退出边界

窗口移动和调整尺寸时仅更新内存，退出才尝试写入 SQLite 独立 `window_preferences` 单行；不按拖动帧写盘，不写旧 settings JSON 或改变 user_version，不调用历史回收。保存采用事务，未知更新版本保留，已知版本的坏记录可在下次正常保存时替换。正文最多 1 KiB，尺寸、缩放、格式、缺字段和未知字段均校验；加载失败回到默认窗口，不阻止本机任务使用。

⌘Q、关闭最后窗口和 Cocoa 直接退出共用原退出流程。先启动既有任务退出期限，再尽力保存偏好；不等待应用数据库互斥锁，保存临时使用零 SQLite busy timeout 并恢复旧值。互斥锁仍被占用时可在最终 Exit 再尝试一次；已经尝试写入后不重复保存，不增加新的任务等待期限。失败只保留此前偏好和本机诊断，不阻止退出、不报告保存成功。

窗口位置属于便利偏好，不是任务持久化保证。强杀、数据库忙碌、存储失败或无法取得普通窗口时可能保持上一次记录；系统 I/O 挂起仍需实机故障验证，零 busy timeout 只保证不等待 SQLite 写锁，不保证任意磁盘系统调用都能立即返回。显示器工作区无法容纳最小布局时使用原默认窗口，不强行缩小到不可用布局。

偏好保存沿用安装准入锁：正在打开更新安装包时跳过这次保存，避免越过已经完成的数据保存检查；普通保存期间也不会允许安装准备同时开始。

## 验证范围

隔离测试覆盖普通窗口/异常尺寸与缩放、十轮 Retina 保存恢复不增长、工作区边界/原屏幕消失/负坐标/混合比例、无可容纳工作区、SQLite 重开与设置/任务不变、坏记录/超限/未来版本保留、只读/写锁/注入保存失败和 busy timeout 恢复。

原生证据和最终构建路径见 [开发记录](development.md)。真实多屏幕重连、缩放切换、低分辨率、Spaces、全屏/最大化切换以及系统/架构矩阵继续按 [发布路线图](release-roadmap.md) 验收。

实现使用当前锁定 Tauri 的窗口、显示器工作区和逻辑尺寸 API。设计参考官方 [窗口状态说明](https://v2.tauri.app/plugin/window-state/)，当前没有引入窗口状态插件。前端额外开放主窗口拖动所需的 `core:window:allow-start-dragging` 和兼容移动所需的 `core:window:allow-set-position`，几何恢复仍由后端完成。

## 窗口拖动

2026-10-28：修复默认窗口权限不包含 `start_dragging`、拖动标记只作用于元素自身而遗漏工具栏内部空白的问题。顶部工具栏、侧栏顶部空白和品牌标志区域使用当前锁定 Tauri 的 `data-tauri-drag-region="deep"`；Mole 结果、页面主体和列表仍保持普通选择/滚动行为。

沿用 Tauri 原生命中检查，按钮（包括图标）、输入框、下拉选择、链接和其他交互控件不触发窗口拖动，路径输入区域显式使用 `data-tauri-drag-region="false"`。移除不属于本项目 Tauri 拖动机制的 `-webkit-app-region` 样式，原生拖动成功时不接管窗口坐标或覆盖原生窗口管理。

macOS 27 的虚拟输入环境存在原生标题栏拖动失败的报告，见 [Apple 开发者论坛](https://developer.apple.com/forums/thread/834488)。本机 27.2 验收中，鼠标命中和双击缩放正常，但原生移动没有产生窗口位移。为此每次打开窗口先尝试原生拖动，并在拖动位移超过 4 个逻辑像素、32ms 后仍未检测到原生窗口位移时，使用当前窗口位置 API 进行兼容移动。原生已移动则退出兼容处理，不接管系统吸附。

若系统吞掉整个移动事件流，则仅在确实收到释放、初始位置已读取完成且原生窗口仍未移动时，按释放位置提交一次最终坐标；确认原生失效后，本次窗口会话中的后续单次拖动直接采用兼容移动，重启后重新尝试原生。单击、交互控件、失焦、取消及迟到的初始读取不补做移动，释放后不再持续跟随。更新串行合并，使用当前缩放比例计算物理坐标，不请求辅助功能权限、不安装全局输入监听或额外 helper。

兼容移动是有界降级，不承诺原生失败时仍具有系统吸附/平铺效果。自动化覆盖原生成功不接管、Retina 坐标、单击阈值、释放/迟到读取与更新合并，以及实际界面控件排除。混合 DPI 和跨显示器拖动继续留在发布验收矩阵中。

原生最终构建已验证真实坐标从 `(0, 642)` 移到 `(600, 702)`，尺寸保持 `961 × 680` 逻辑像素；重启后继续从工具栏和侧栏标志拖动，最终保存为 `(500, 622)`。另一次重启仅在路径输入框中输入和拖选文字，窗口坐标保持 `(500, 622)`。以上坐标为 2× Retina 的物理坐标；验收记录保存在 `local-artifacts/window-drag-validation.json`，应用构建为 `local-artifacts/MooMole-0.1.0-mac-arm64-mqedH3/MooMole.app`。
