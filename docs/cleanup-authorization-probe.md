# 清理占用检查：按次授权候选探针

本轮限定目标是验证免费 ad-hoc App 能否通过系统确认获得 Mole 所要求的进程可见性。当前只完成固定只读探针的实现与非授权实验，**尚未验证实际打包 App 的授权成功/拒绝/取消，也没有开放清理权限**。首发要求仍见 [三项真实执行验收](first-release-execution.md)。

## 机制取舍及证据

本机 Xcode macOS SDK 的 `ServiceManagement.framework/Headers/SMAppService.h` 明确要求包含 LaunchDaemon 的 App 公证；`Security.framework/Headers/Authorization.h` 也明确不再推荐 `AuthorizationExecuteWithPrivileges`。因此，本次不沿这两条路线引入常驻 root 服务或弃用的直接提权 API；这不等于断言所有免费授权路线都不可行，也没有增加付费证书发布前置条件。

候选使用 Apple [TN2065：do shell script](https://developer.apple.com/library/archive/technotes/tn2065/_index.html) 记载的系统管理员确认参数。程序从固定源码生成脚本，由 `NSAppleScript` 编译；没有向 Terminal/Finder 等其他应用发事件。文档还说明输出行尾转换、错误处理、环境继承和脚本相关的授权缓存，因此这些均列为协议及后续实机验证条件。该文档是机制依据，不替代当前 macOS、ad-hoc 签名及升级后的实际验证。

## 实际代码边界

实现位于 `src-tauri/src/activity_authorization.rs`，由 `lib.rs` 的 `#[cfg(test)]` 引入；仅测试依赖启用现有 Foundation crate 的 NSAppleScript 功能。正式 App 不编译该模块，没有新的 IPC、设置、授权按钮或运行入口。本轮原生编译测试只调用 compile，不执行授权脚本。

固定程序能力如下：

- 唯一检查是 `/usr/sbin/lsof -F pu -p 1`，对应固定 Mole `_mole_complete_lsof_mode` 的 PID 1/root 字段证明。没有用户文件路径、任意程序/参数、域、命令或密码输入，也没有删除、偏好写入、安装服务或修改 sudo/Gatekeeper 的操作。
- 命令先切换到 `/`，用固定 `/usr/bin/env -i` 清除继承环境，再运行系统 `/usr/bin/perl` 及核心模块；不按 PATH 查找替代程序，不安装缺少的运行时。依赖系统 Perl 是此候选的限制，需要在声明支持的 macOS 版本验证；缺失或模块不可用应报告不支持。
- Perl 监督器只持有一个固定 lsof 子进程，合并 stdout/stderr 为证据，关闭输入；使用单调时钟限制探测约 5 秒，字段输出最多 4096 字节。超时、输出过量或读取异常时，仅在尚未回收该子进程的情况下终止并回收它。没有异步延时 kill 的 PID 重用窗口，也不靠 lsof 是否保留继承的 alarm 来保证时限。该时限是监督循环的正常运行预算，不承诺系统挂起、不可中断内核调用或授权窗口在 5 秒内结束。
- 每次生成不同 UUID v4，并绑定协议头、有效用户、退出状态及唯一同组 `p1/u0` 字段；观察结果超过 120 秒不再接受。警告、缺字段、错误退出、超量、截断、未知版本、另一请求的响应均不能成为可见性证明。授权取消与失败区分，但相应原生实际返回仍待验证；本轮只验证协议输入。
- 正式实现仍需封装完整的原生执行/错误提取、串行与退出/取消生命周期、实际调用方和脚本来源约束。UUID 使脚本源码不同；是否每次出现系统确认、授权缓存及其失效行为尚未实测，不能据此承诺没有授权缓存。实验观察不是可复用授权令牌，也不能跨清理计划使用。

## 本轮验证

`node scripts/cargo.mjs test activity_authorization -- --nocapture` 的 6 项测试通过：固定授权源码由系统 NSAppleScript 编译；两层引号及字面特殊字符；UUID/用户/字段/状态/过期与异常协议；真实普通账户探测；隔离子进程退出/警告/超时及已回收检查；超量输出与关闭输出后仍挂起的进程。

超时和输出测试只在测试源码中替换固定子进程，并缩短预算；没有相应生产接口或环境开关。自建子进程输出的 `p1/u0` 只用于监督器和协议校验，不是系统权限证据。本机真正运行固定 lsof 的普通账户结果为 `IncompleteOrFailed`、退出码 1，继续要求保留目标。没有运行管理员授权、读取文件正文或修改个人文件/系统设置。

## 接入清理前仍须完成

1. 在实际 ad-hoc 打包 App 中提供由用户明确触发的受限验证，测试正常系统授权、取消/拒绝、失去前台、退出和重新启动；检查真实返回类型、行尾、错误、输出预算和缓存，不以 CLI/编译成功替代。
2. 扩成绑定后端计划及具体普通日志对象的固定检查：授权等待后核对请求有效期、用户、对象和祖先身份，再执行所选对象的有界占用检查，前后重验。PID 1 证明不能独自推出所选日志无占用；root 也不证明 TCC 或所有进程可见性。
3. 保留 Mole 路径/模块/白名单等规则，与普通用户废纸篓执行器交接；只允许当次符合条件的对象。完成完整结果、真实收据、取消/退出/重启和已验证恢复边界后，再按首发标准验收实用清理范围。

尚未满足上述条件，现有 no-auth 适配和 unknown 保留行为不变；清理、卸载和维护三个首发执行门槛均未因此完成。
