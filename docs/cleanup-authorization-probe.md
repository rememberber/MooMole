## 机制取舍及证据

本机 Xcode macOS SDK 的 `ServiceManagement.framework/Headers/SMAppService.h` 明确要求包含 LaunchDaemon 的 App 公证；`Security.framework/Headers/Authorization.h` 也明确不再推荐 `AuthorizationExecuteWithPrivileges`。因此，本次不沿这两条路线引入常驻 root 服务或弃用的直接提权 API；这不等于断言所有免费授权路线都不可行，也没有增加付费证书发布前置条件。

候选使用 Apple [TN2065：do shell script](https://developer.apple.com/library/archive/technotes/tn2065/_index.html) 记载的系统管理员确认参数。程序从固定源码生成脚本；测试由 NSAppleScript 编译，App 通过固定系统 osascript 进程执行，以复用自有进程组的取消/退出监督。没有向 Terminal/Finder 等其他应用发事件。文档还说明输出行尾转换、错误处理、环境继承和脚本相关的授权缓存，因此这些均列为协议及后续实机验证条件。该文档是机制依据，不替代当前 macOS、ad-hoc 签名及升级后的实际验证。

## 实际代码边界

实现位于 `src-tauri/src/activity_authorization.rs`；设置 → 关于 → 清理权限检查默认折叠。只有明确点击“授权检查”才调用无参数的专用开始 IPC；打开设置、读取快照、重载或重新打开均不触发授权。该入口是故障诊断，不产生文件处理确认或清理许可。Foundation 的 NSAppleScript 特性仍只在测试启用，自动化测试不执行管理员授权脚本。

固定程序能力如下：

- 唯一检查是 `/usr/sbin/lsof -F pu -p 1`，对应固定 Mole `_mole_complete_lsof_mode` 的 PID 1/root 字段证明。没有用户文件路径、任意程序/参数、域、命令或密码输入，也没有删除、偏好写入、安装服务或修改 sudo/Gatekeeper 的操作。
- 命令先切换到 `/`，用固定 `/usr/bin/env -i` 清除继承环境，再运行系统 `/usr/bin/perl` 及核心模块；不按 PATH 查找替代程序，不安装缺少的运行时。依赖系统 Perl 是此候选的限制，需要在声明支持的 macOS 版本验证；缺失或模块不可用应报告不支持。
- Perl 监督器只持有一个固定 lsof 子进程，合并 stdout/stderr 为证据，关闭输入；使用单调时钟限制探测约 5 秒，字段输出最多 4096 字节。超时、输出过量或读取异常时，仅在尚未回收该子进程的情况下终止并回收它。没有异步延时 kill 的 PID 重用窗口，也不靠 lsof 是否保留继承的 alarm 来保证时限。该时限是监督循环的正常运行预算，不承诺系统挂起、不可中断内核调用或授权窗口在 5 秒内结束。
- 每次生成不同 UUID v4，并绑定协议头、结束标记、有效用户、退出状态及唯一同组 `p1/u0` 字段；观察结果超过 120 秒不再接受。Perl 在系统确认之后、启动 lsof 之前还按同一系统单调时钟复核后端生成的截止时间；旧窗口延迟确认不再启动探针。警告（含外层解释器 stderr）、缺字段、错误退出、超量、截断、未知版本、另一请求的响应均不能成为可见性证明。
- 本机 `man lsof` 的 OUTPUT FOR OTHER PROGRAMS 说明 `f`（文件描述符）始终选中，即使指定 `-F pu`。原实现把实际附带的 f 字段误当异常，现改为 p1/u0 同一进程组之后允许已知普通描述符字段，仍拒绝 ferr/NOFD、其他进程、UID 重复、警告、未知字段和不合法描述符。用本测试进程的真实系统 lsof 输出复核语法；不根据这些描述符决定任何文件处理对象。
- 后端保留本实例内最新快照；关闭弹窗不终止工作，重开只读回，不写入个人文件或独立权限档案，也不跨 App 重启保留该观察。重复请求、过期取消 ID 和旧结果不能替换当前任务。开始/结束/取消共享任务注册表锁，纳入退出取消；持有更新安装的操作租约，并与日志执行互斥。前端严格校验版本、只读范围、身份、阶段/结果组合与时间，读取不明时撤下旧结论并禁用开始。
- “停止等待”取消本次自有解释器进程组；这不证明系统授权窗口或已授权的只读进程同时关闭。取消/异常后继续保留约 6 秒的正常探针预算，结果不能被随后到达的证明改回成功。仍显示的系统窗口须由用户取消，系统挂起/不可中断调用不在此时限保证内。实际系统取消、拒绝、App 停止等待及退出仍需分别记录原生证据。
- UUID 使脚本源码不同；是否每次出现系统确认、授权缓存及其失效行为尚未实测，不能据此承诺没有授权缓存。观察不是可复用授权令牌，也不能跨清理计划使用。该固定诊断不直接与所选对象或执行器交接；独立的按计划日志检查见下文。

### 第二次实际检查与 Darwin Fileport 解析修正

诊断版干净提交 `3999ba7` 的 App `OLXD1m` 已校验并实际启动，重新扫描、建立独立新计划 `0b643454` 后由用户亲自提交和授权。批次 `f9d59538` 仍为 noChanges，两项 skipped、无收据。具体诊断为视图退出状态 0、202 字节、root 成对字段 true、字段格式 false；没有继续精确文件查询。该结果将缺口缩小到视图字段解析，不能推断文件被占用，也不能据 root 字段存在放行。

Apple 的 [固定 lsof 源码](https://github.com/apple-oss-distributions/lsof/blob/7a8a1b2a3c0f35c30a5fcd0927f31d441c3e5255/lsof/dialects/darwin/libproc/dproc.c#L741) 使用 `fp.` 表示 Darwin Fileport，因此 -F 的描述符字段可为 `ffp.`。本机 lsof 4.91 的 man 页未列此项；以普通账户为自己的临时文件调用 fileport_makeport 后，真实系统 lsof 确实返回 `ffp.`，正常零退出、无 stderr，原 Rust 解析回归因此失败。没有读取 PID 1 的原始输出或请求额外系统权限，也不把自己的进程输出冒充 root 证明。

固定诊断 Rust 解析和所选日志 Perl 解析均仅补齐精确字面 `ffp.`；`ffp.x`、`ffp.1`、ferr/NOFD、警告、额外 PID/UID 及未知字段继续拒绝。增加真实自有 Fileport 测试并由 RAII 释放 Mach 端口，以及 Perl 正面/相似非法字段测试。原 root/完整视图、精确查询和最终对象门槛保持，实际修正后的所选日志成功仍待本人再次确认；不能仅凭复现合法字段就把前两批保留记录改成成功。
