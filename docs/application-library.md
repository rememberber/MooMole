# 应用清单：查看与对比

2026-10-18。固定 Mole 1.59.1 / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f`；当前功能只读，勾选不是卸载选择或执行计划。

## 使用流程

读取应用后，先看名称、安装路径、来源和上游大小。按名称、Bundle ID、完整路径或来源文本搜索，也可筛选普通应用、Homebrew、待确认来源，按大小降序或名称排序。每批显示 100 项，“当前显示”只勾选这一批，继续显示不会自动选中后续项目。

勾选用于对比应用包估算。筛选时保留勾选并显示未出现在当前列表中的数量；“只看已勾选”便于集中查阅。列表刷新失败时保留旧结果和勾选，成功接收新列表或离开页面后清空勾选，不将其带入新观察。勾选、筛选与排序均不持久化，也不调用任何卸载接口。

“位置与来源”提供完整路径、Bundle ID、Mole 原始来源及未知大小标记，可请求 Finder 定位。同名或同 Bundle ID 的不同返回路径分别展示和勾选，客户端不再合并；但上游已经去掉的副本无法从清单中恢复。Finder 请求仍走现有路径校验接口。

## 上游范围与证据

依据本地固定源码 `bin/uninstall.sh`：

- `main` 的 `--list` 分支在卸载路径前短路；`uninstall_list_apps` 返回 JSON，客户端继续使用现有只读任务运行器。
- `uninstall_print_app_search_dirs`：`/Applications`、`~/Applications`、`/Library/Input Methods`、`~/Library/Input Methods`、存在的 PlayCover 目录及可读取的 `/Volumes/*/Applications`。
- `_scan_discover_apps` 还合入安装收据识别的非标准安装位置，并跳过部分应用；`_scan_dedupe_bundle_ids` 根据 Bundle ID/应用包名等规则去重。因此这里不是所有系统应用、所有安装副本或关联文件清单。
- `uninstall_list_apps` 的来源仅为 `App` 或 `Homebrew`，`App` 在界面解释为普通应用，不推断 App Store 或安装者身份。未知来源显示“来源待确认”，保留原值。
- `uninstall_normalize_size_display` 会保留 `N/A`、Steam 管理等未知标记；大小可能来自缓存或受限探测，不表示完整关联数据大小。

大小格式依据 `lib/core/base.sh:bytes_to_human`，B/KB/MB/GB 使用十进制 1000，且已经舍入。客户端只将这些明确单位换算为排序/对比估算，保留原始单项显示；未知、非有限、过大或不支持的格式不计为零，也不参与已知汇总。明确 `0B` 与未知分开。全部所选大小未知时不显示 `0 B`，汇总超出安全数值范围时说明无法汇总。

此换算仅用于展示，不决定删除对象，不作为精确字节数、唯一物理占用或可释放空间依据。真实关联数据识别、共享内容、完整活动/占用检查、保护、个人数据默认保留、卸载计划与受限执行器仍待完成。原生应用图标已按下述范围接入，不改变此处的清单与执行边界。

## 原生图标

列表使用 macOS 的 [NSWorkspace icon(forFile:)](https://developer.apple.com/documentation/appkit/nsworkspace/icon%28forfile%3A%29) 获取系统关联图标，在独立 64×64 RGBA 位图中绘制为 PNG，按 32px 显示。系统可返回通用图标；它只辅助辨认，不证明 Bundle ID、签名、归属或可卸载性。失败、应用消失、不可读取或不支持的路径继续显示原有通用图标，不影响搜索、对比或 Finder。

- 只对进入视口附近 100px 的行请求图标，离开后释放当前行图片并取消尚未开始的排队工作。前端最多两个在途请求、64 个排队请求，超额回退；正在运行的原生读取不能通过取消观察强制终止。
- IPC 仅接收任务 ID 与原始清单索引，不接受文件路径、URL 或 Shell。后端只从短期结果缓存中的成功 apps 任务解析对应路径，不复制整份列表；未知/过期/淘汰结果、越界索引或异常字段回退。清单本身仍能显示，重新读取可取得新的观察及图标。
- 仅处理有界绝对 .app 目录；拒绝链接及可识别的链接祖先、网络卷和带 SF_DATALESS 的目标目录，不启动应用、不遍历关联数据。保留目录句柄，并在返回前比较目录设备/inode/ctime；变化时丢弃图片。这只是可选图片读取，不是抵抗并发替换的事务或后续卸载的文件身份凭据；系统图标服务的内部读取/缓存行为并不由客户端控制。
- 后端最多两个实际工作器；3 秒后停止等待，工作器持有名额直到真正结束，避免超时后继续无限增加阻塞线程。此等待期限不能打断挂起的系统 I/O。入口观察到安装准备或退出时不接受新的图标请求；已接受的纯读取工作不作为安装的数据保存任务或退出阻断条件。
- 每张 PNG 不超过 24KiB，前端只接收不超过对应 Base64 上限的 PNG data URI，拒绝其他 URL、SVG 与超长载荷；图片解码失败回退。保持现有 CSP，不开放 file/asset 协议、远程图片或额外 HTTP。所有路径均来自 Mole 已返回的应用清单。
- 图标缓存只在 WebView 会话内，按任务 ID/原始索引绑定，最多 128 项，图片字符串累计不超过 2×1024×1024 个 ASCII 字符（不是 JS 内存硬上限），条目 10 分钟后在下次访问时重新读取。成功和失败均缓存；任务刷新、排序或筛选不会把其他任务/条目的图片错误沿用，迟到响应忽略。缓存不落盘、不写 SQLite，刷新失败仍保留旧列表与旧任务上下文。
- 图标对辅助技术隐藏，应用名称、位置、来源和大小继续作为可访问内容。没有请求新增系统权限，也没有增加卸载/删除接口。
