# 维护设置的原值读取证据

2026-10-21。两项维护设置的手动检查现在同时读取六个固定键在当前用户 AnyHost 与 CurrentHost 明确域中的原始值。目的在于辨别有效设置与明确域值、观察原始类型和已发现的变化；不是备份或可恢复原值记录，不能据此开放维护执行。

## 固定范围与读取方式

沿用 `inspect_maintenance` 的六键白名单和单 worker。Finder 使用 `com.apple.desktopservices`，映像验证使用 `com.apple.frameworks.diskimages`，全局 App Nap 使用 `kCFPreferencesAnyApplication`；用户固定为 `kCFPreferencesCurrentUser`，主机仅 `kCFPreferencesAnyHost` 和 `kCFPreferencesCurrentHost`。前端不能传入任意域、键或主机范围。不枚举其他设置或用户，不读整个 plist，不为真实域写入实验标记。

使用 `CFPreferencesCopyValue` 读取明确域，与 `CFPreferencesCopyAppValue` 的有效设置读取分开。两个域各读两次，比较原始类型和值；前后再次读取有效设置及管理标记。观察到有效设置变化时有效值变为未知；管理标记变化保守视为受管理。比较不构成原子快照，也不能证明缓存已刷新、期间没有其他写入或外部修改后来没有恢复原值。

支持原生布尔、可精确转换的 i64 整数和最多 1024 个 UTF-16 单元的有效字符串。字符串比较保留空串、非 BMP 和嵌入 NUL；不经 C 字符串截断。整数 1 和布尔 true、整数 0 和布尔 false 不合并；浮点、其他类型、无效 UTF-16 或超长字符串暂不支持。原始数据只在本次原生调用内用于比较，随后释放；未发送给 WebView、记录日志或落盘。后续恢复需要另行设计持久证据，不复用这些摘要假装已保存原值。

## 返回的证据

观察 v4 的每键 `originalEvidence` 严格包含 `anyHost`、`thisHost` 两项，顺序固定。只返回 `scope`、`state`、`kind`：

| state | 含义 |
| --- | --- |
| observed | 两次均取得受支持原值，类型和值相同；kind 为 boolean/integer/string，仍未保存可恢复记录 |
| unconfirmed | 两次都未返回值；缺失与读取不可用仍无法可靠区分，不能据此删除键或证明原来缺失 |
| unsupported | 两次均取得暂不支持的原值，未比较完整内容，也不声称它们一致 |
| changed | 两次出现已观察的值、类型、可用性变化，或前后有效值/管理标记变化；需重新检查 |
| notChecked | 因固定范围校验、分配或时间预算等未发起本次观察 |

非 observed 的 kind 必须为 null。明确域未知不等于有效设置未知：例如有效值可来自继承。已发现的 changed 会阻断对应的“无需变更”判断；已知保护、访问限制仍优先保留。其他原值条件不授予修改权限；存在变更意图的键继续标记缺少恢复证据。

审阅升为 v2，绑定同一原生观察中的逐键证据摘要。前端拒绝缺少/重复/调换域、非法状态与类型组合、额外原始值字段、报告与审阅摘要不符，以及旧协议。`originalsCaptured` 始终 false：尚未建立完整、可持久恢复的原值证据，不能因本轮某个域读到值而改为 true。执行和冲突解决标记也保持 false。

后续 [跨进程恢复实验](maintenance-recovery-journal.md) 发现含 NUL 字符串的系统读取可能截断；原生只读捕获能够比较完整 UTF-16，不等于系统服务可跨进程精确恢复。当前 App 没有保存/恢复入口，仍不授予修改许可。

## 界面与验收边界

项目的设置观察和审阅弹窗均可展开“原值读取证据”；默认不增加技术详情。详情区分通用主机域、本机域、原始类型和未知/变化，说明继承、未保存恢复记录及非原子读取。主界面继续先显示结论和下一步。

原生对象单元测试覆盖类型、整数边界、UTF-16 字符串、浮点/异常/超长拒绝、类型差异、缺失不确定及内容不外传。前端与浏览器覆盖证据完整性、矛盾拒绝、变化保留、按需展开及 960px 布局。实机六键只读测试和实际 App 的证据另记于 [开发记录阶段 91](development.md)。不为了制造正面结果而更改真实 Apple 设置。真实域缺失证明、持久恢复记录、缓存一致性、跨进程恢复、并发写入和实际维护执行仍待解决。
