# AI 分析范围

2026-10-30：AI 深度扫描默认改为“只分析所选目录”，也保留明确选择的“Mole 常用清理位置与所选目录”。这让个人文件分析、解释与后续整理成为独立主流程，而不必先收集其他清理位置的候选。

## 用户操作与数据范围

- 默认只读取所选物理目录内有界的文件元数据，不启动 Mole `clean --dry-run` 候选扫描，不收集其他清理位置的文件清单。仍沿用三层、2,000 个访问项、400 条线索及五秒预算，以及隐藏/敏感位置、链接、跨卷和云占位保护，不宣称是完整目录或全盘检查。
- 扩大为组合范围时，界面明确说明 Mole 候选可能在所选目录之外。任一方向改变范围都会立即撤回原数据授权勾选；改变 Agent 或目录也继续撤回。默认不启动模型，仍须明确同意将本次路径/名称/类型/大小/修改时间交给所选模型服务，可能消耗额度；不发送正文。
- 运行中的报告保存开始时的范围，表单展示原任务的范围、Agent 和目录，不因重载后的默认表单值而变成另一个范围。完成/失败的历史消息标明范围；旧报告缺少范围字段时明确显示“未报告”，不推断为窄范围。App 重启仍只保留任务历史，不恢复模型请求。
- “只分析所选目录”不依赖 Mole 引擎可用，Agent、权限和模型调用仍需实际验证。组合扫描仍要求引擎就绪；文件处理、清理审阅等后续动作仍保留原有引擎与保护准入。不能把能进行分析解释当作已取得处理许可。

这里限制的是交给模型的文件清单来源，不声称整个 Agent 进程不会读取目录外的运行配置、认证或自身日志。Agent 的工具隔离、沙箱、认证、服务端数据政策及报告保留边界继续见 [AI 深度扫描](ai-deep-scan.md)。不修改全局 Agent 配置、不安装 CLI 或自动登录。

## 后端实现

`start_ai_scan` 接受 `includeMole`，省略时也默认 `false`，不因旧调用缺参数而扩大范围。范围写入本次内存 Snapshot，完成/失败消息按开始时的值记录，不从终端文案或模型回复推断。此前没有记录范围的异常历史继续按未知对待，不补造授权证据。

只有明确包含 Mole 时才调用候选扫描；窄范围在构建模型清单前还执行独立准入：不接受传入的 Mole Scan，逐项要求 `source=metadata`、无 Mole candidate ID 且位于选定目录内部。意外混入其他来源或范围外路径时整体停止发送，不静默扩展。目录本身依然使用 descriptor-relative/no-follow 检查，不跟随源内符号链接到外部文件。

Mole 成功的组合模式继续保存原始清单并使用原有清理审阅；组合模式的 Mole 失败会如实记录限制。仅目录模式不伪造失败，也不产生 Mole 清理 ID。普通文件线索按 [AI 个人文件整理](ai-personal-files.md) 的独立重扫、再次选择及确认流程进入真实操作；不改变旧执行/归档格式。
