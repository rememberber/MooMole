# 维护恢复记录：持久化与跨进程隔离实验

2026-10-21。本轮实现并验证测试专用的 SQLite 恢复记录、未完成意图对账和显式条件恢复。代码位于 `src-tauri/src/maintenance/preference_sandbox/recovery.rs`，随整个 sandbox 仅在 `#[cfg(test)]` 下编译。没有 App IPC、运行时开关、真实 Apple 设置目标或用户数据库迁移；不能将此实验视为正式维护恢复功能。

## 固定目标与记录

父测试先创建随机 `io.github.rememberber.moomole.preference-lab.<UUID v4>` 域、两种主机范围的所有权标记及无关 fixture 键。记录绑定此域、所有权 UUID、当前有效用户、明确主机范围、固定 `fixture-probe` 键、原始缺失/类型/值和期望值。只有已建立标记并通过键列表/两次读取的测试域可以确认缺失；真实域 NULL 仍不能成为缺失证据。

每个测试私有目录包含一份独立的 `preference-recovery.sqlite`，不是 App 的 `moomole.sqlite`。注册表保存域、所有者和 UID，单条不可重复插入的操作记录保存随机 ID、完整 JSON、SHA-256 及阶段。内容最大 32 KiB，域、标记、协议、固定键、主机范围、原始值和预期值均重新验证；非法 schema、额外字段、超长内容、变更摘要或注册表绑定不符均拒绝。布尔/整数不合并，无变化与等价表示转换不作为修改操作。

文件目录要求当前用户的 0700，数据库为 0600 普通单链接文件；拒绝末级符号链接、硬链接、过宽权限及打开期间已发现的身份变化，不自动修权限。先取得已有实例模块的内核目录锁，再打开 SQLite、验证和对账；活着的子进程持有时，父进程不能把它标为中断。连接先关闭，随后释放锁。采用 SQLite DELETE journal、FULL synchronous/fullfsync，与 App 当前 WAL 数据库的集成另需验证。

原始内容只落在测试自己的临时目录，不上传；日志只报告测试结果，不输出偏好内容。SHA-256 是损坏检测，和正文处于同一私有数据库，**不是签名或能抵抗同用户篡改的信任根**。注册表和标记的约束只允许恢复实验自己已注册的 UUID fixture 域，不能移植成任意域选择器或真实 Apple 域的所有权证明。

## 操作与重开语义

| 持久阶段 | 可作出的结论与下一步 |
| --- | --- |
| captured | 已记录原值/期望值，尚无修改意图；不等于已执行 |
| applyIntent | 修改意图已提交，真实结果可能尚未记录 |
| applied | 此次写后类型/值核对成功，结果记录已提交 |
| restoreIntent | 恢复意图已提交，恢复结果可能尚未记录 |
| restored | 此次恢复后类型/值核对成功，结果记录已提交；不证明之后没有外部变化 |
| uncertainApply | 取得目录锁后重开，遇到未完成修改意图；不自动重放，只观察 |
| uncertainRestore | 重开遇到未完成恢复意图；不从当前值相等推断恢复成功，不自动重试 |
| conflict | 意图提交后复查已发现变化，保留当前值，停止本次操作 |

意图事务成功提交后才调用测试 writer；意图提交失败不会写偏好。写入已经发生而完成记录提交失败时，保留原来的 intent；重开后进入结果未确认，不能把数据库报错描述成偏好未改变。阶段转换限定原 ID、原阶段及合法边，重复/错 ID/非法转换拒绝。

重开只对未完成阶段作记录对账，不触发偏好写入。观察区分期望值、原值、其他值或无法读取，不将“恰好等于期望值”认定成已知写入归属。显式恢复仅允许 applied/uncertainApply，且当前明确域值仍按原类型等于已记录期望值；先持久提交恢复意图，再重新核对，才有条件恢复原值或移除实验新增键。uncertainRestore 不自动认定成功，也不再次写入。

这些复查仍无法消除最后检查与写入之间的竞争窗口；已有 [非原子复现](maintenance-preference-lab.md) 继续保留。其他写入方没有共享这个目录锁，不能据此承诺不会覆盖并发变化。

## 跨进程实测发现：NUL 字符串仅可归档

此前同进程实验保存并读回了包含 NUL 的 UTF-16 字符串，JSON 记录也能完整往返。本轮首次从子进程写回、再由另一进程观察时，出现 NUL 及其后文本丢失；严格核对因此失败。后续独立子进程读取测试再次报告原值与记录不相等。该结果只描述本机测量，不能假定所有 macOS 版本都相同。

现在持久记录仍能无损保存含 NUL 的数据用于研究，但只要原值或期望值含 NUL，apply/restore 都在意图提交和写入之前拒绝，观察结果为 unsupportedOriginal。没有放宽核对、截断快照、把测试值换成相似值后声称问题消失，或用先删再写绕过限制。正面跨进程恢复只使用已通过的缺失、整数与不含 NUL 的 Unicode 字符串。

## 验证方式与边界

默认测试验证 18 组两种主机范围/类型记录的关库重开、私有文件、不可重复插入、阶段条件更新、事务失败、篡改/绑定/schema/范围/未知字段拒绝，以及 NUL 只归档策略，不写系统偏好。

显式实机测试在父测试创建的 UUID 域内进行：

- 子进程写入并同步测试键后，在写完但结果未提交的检查点停留；父进程先确认占用拒绝，然后仅通过所创建的 Child 句柄发送 SIGKILL 并等待回收。
- 新进程从 SQLite 重新加载原值，不持有旧的内存 Ticket/摘要；在条件仍匹配时完成恢复。实测缺失、ThisHost 的最小 i64 和不含 NUL 的 Unicode 字符串；无关 fixture 键保留。
- 修改意图已提交但写入前被杀、恢复写完但结果未提交被杀时，重开均保留不确定，不重放或凭相等值宣称成功。
- 意图事务失败、写后结果事务失败、恢复前变化，以及意图提交后复查前的变化，分别验证无写入或不确定/冲突保留。
- 含 NUL 的归档跨进程仍完整，但不可执行；子进程读取与归档不一致时不会尝试修复系统值。

```sh
node scripts/cargo.mjs test --locked maintenance::preference_sandbox::recovery --quiet
node scripts/cargo.mjs test --locked maintenance::preference_sandbox -- --ignored --nocapture --test-threads=1 --skip fixture_subprocess
```

内部子进程入口必须由父测试提供临时目录和模式，不单独运行。每个检查点/等待有父进程期限和 Child 回收保护；正常结束时验证清除三个 fixture 键。子进程临时文件放在父测试目录下，随测试目录清理；系统仍可能留下空偏好域/缓存痕迹。不删除整个域、用户文件或真实设置。

这是实际 exec/SIGKILL 与后续进程恢复实验，超过同进程通知丢失模拟的范围；**仍不是实际断电、系统崩溃、真实域缺失证明、App WAL 迁移、可跨机器恢复、正式 ad-hoc App 恢复或并发原子保证**。正式接入还需受限真实原值、用户选择/保护/引擎绑定、持久信任边界、启动展示与显式恢复交互；免费发行路线仍不依赖付费签名或常驻 helper。
