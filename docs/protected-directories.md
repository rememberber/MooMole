# 保护目录的选择与保存

2026-10-23，阶段 116。保护列表继续保存客户端保护意图，Mole 自有白名单保持独立；不改写其配置，也不因此允许处理其他项目。

## 用户操作

在“设置 → 保护列表”添加目录，系统窗口明确显示“选择要保护的文件夹”。等待选择期间可查看其他设置分类，但暂时禁用主题、历史期限、添加和移除保护等设置修改；选定后继续保持锁定，直到保存完成。选择与保存使用不同进度提示，防止把尚未选定的目录表示为已保护。

取消选择不保存、不回收历史，也不显示失败。系统窗口或保存失败时，显示原错误并允许重新选择；保存失败保留原列表。选择与已保存字面路径完全一致的目录时，提示“此目录已在保护列表中”，不再次提交设置。符号链接等不同写法仍交由原后端验证与规范化，不在前端猜测对象身份、大小写等价或父子覆盖。

选择结束并恢复按钮可用后，焦点返回“添加目录”，方便取消、重复或失败后继续用键盘操作；切换分类后没有该入口，或已关闭设置/出现另一模态窗口时不主动抢回焦点。首次原生验收发现系统取消后可能只回到页面容器，已在等待状态结束后的布局阶段补回。

关闭设置会撤销尚未提交的选择；系统窗口较晚返回的目录或错误被忽略，不能影响重新打开的设置。当前组件没有强行关闭系统窗口的能力，此处撤销的是返回结果的使用。已经提交的保存会继续完成，不把关闭弹窗当作数据库回滚；若上一次明确保存稍后完成，本次选择合并到最新设置，避免把主题等改回旧值。

## 边界与验证

同步操作令牌阻止重复进入，覆盖等待选择和保存两个阶段；关闭及卸载时使令牌失效。既有 Rust 保存入口仍负责新路径访问验证、规范化、排序去重和事务；已保存但暂时不存在的保护意图仍保留。本次没有新 IPC、数据库结构或文件处理能力。

隔离浏览器覆盖选择/保存等待、跨分类禁用、移除禁用、取消、选择失败、保存失败与重试、重复项不提交、重开后的旧结果/旧错误、之前保存较晚完成后的最新设置合并，以及重载后保存值。真实用户数据库不用于注入失败或增删保护目录。

原生目录窗口验收与构建证据见 [开发记录](development.md)。完整导入/导出、失效目录状态展示、系统/权限和符号链接矩阵仍按 [发布路线图](release-roadmap.md) 验收。
