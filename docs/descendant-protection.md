# 目录后代路径保护观察

2026-10-16，观察版本 v1。继续使用固定 Mole `1.59.1` / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f`、clean v2、rules v4、模块 v2、占用 v1、路径/目录观察 v2、SQLite v3；没有新增修改 IPC。

## 解决的缺口

Mole 的 `is_path_whitelisted` 已经将精确白名单路径的父目录纳入保护。本功能针对另一种情况：通配模式可以只命中深层后代，而根项目没有匹配。例如 `~/Library/Caches/*/deep/open.*` 可能命中 `app/deep/open.log`，根目录 `app` 本身却通过该判断。客户端不重新实现 glob，也不解析终端文字决定保留对象。

审阅计划现在展示独立的“目录后代路径保护”证据，说明命中的后代路径、Mole 来源与原因。它补充当前目录审阅，不将父目录的路径通过或有限模块通过当成后代全部条件都已满足。

## 范围与枚举

仅对当前本地复核通过、扫描来源契约与准确路径范围均属于已接入 userCache/userLogs 的目录准备后代输入。普通文件显示没有后代，未适配/混合/缺失来源不按路径推断模块。

`tree::inspect_paths` 复用目录摘要的同一次无跟随遍历：保留祖先句柄、相对打开子目录、核对身份及名称绑定，枚举包含隐藏项的普通目录/文件。返回目录摘要必须与保存计划一致，才接受整份后代路径。链接、特殊文件、共享硬链接、跨卷、无法表示为 UTF-8 的路径、读取错误、数量或时间超限均不发布部分路径。

列表仅用作当次探测输入，不写入持久计划。已有目录摘要的格式/算法不变，不需要数据库迁移或让所有旧 v2 目录计划失效。摘要仍不是原子快照；晚期深层变化窗口保留原反例测试。

## 探测与聚合

前端继续只提交计划 ID 和复查 UUID。Rust 从保存计划生成根项目输入，再为后代生成内部 ID；后代不是新候选，不接受前端额外路径，不获得扫描来源绑定。

根项目和后代共享 **500 条** rules 输入，优先保留根项目。各目录依次使用剩余额度；某目录超限时丢弃该目录的全部临时后代输入，其他目录仍可检查。后代枚举共享现有目录预算（10000 节点、64 层、系统调用间检查 5 秒）。规则仍只启动一个进程，沿用 45 秒进程期限、8 MiB 报告及取消流程；45 秒不是包括前后本地遍历的整体硬实时期限。准备与结束时的文件系统复核在阻塞工作线程运行，取消仍需等待有界遍历/当前系统调用返回。

后代使用现有 v4 `(id,path,binding=unsupported)` 请求，调用原版路径保护、白名单、编译模型、适用的活动缓存/SQLite 判断；不会为后代冒用根项目的模块契约，也不额外递归运行模块或占用 helper。Rust 只使用后代的 pathCode；`module=unsupported` 表示没有相应来源契约，并非这个后代的路径检查失败。

只有根项目路径及有限模块条件满足，且整组后代报告齐全时，才能聚合后代结论。结束后再次核对当前本地保护、有效期、身份和目录摘要；变化则放弃旧后代成功证据。根项目的附加占用未知仍可与后代路径检查结果并列，二者含义分别解释。

| code | 含义 |
| --- | --- |
| `checked` | 本次整组后代路径判断未要求保留；不代表完整模块规则或可执行性 |
| `protected` | 某个后代命中核心保护、白名单或编译模型保护，显示准确路径及来源 |
| `unavailable` | 超额、内容变化、读取失败、缺项、活动/SQLite 未知等；不能作为完成证据 |
| `notChecked` | 范围未适配，或根条件未满足而不发布后代完成结论；批量中可能已读取后代判断 |
| `notApplicable` | 所选普通文件没有目录后代 |

`checkedEntries` 是聚合时已核对的后代路径结果数；遇到首个保护/未知即停止聚合，不表示遍历或子进程只处理了这个数量。缺项和无效枚举不保留部分完成数量。其他项目原有保护、过期、内容变化或占用状态优先保留；只有原先未发现问题的项目才提升为“目录后代受保护/尚未确认”。

证据仅在当前弹窗中保留；重新复核、重新检查、取消、错误和过期均清除。字段/版本/状态无法识别时不显示检查通过。真实执行、恢复、永久删除和管理员授权仍未接入。

## 验证与剩余边界

Rust fixture 覆盖特殊字符、同次摘要一致性、不可传递名称、来源缺失/混合、后代保护/未知/缺项、根条件拒绝、整目录及多目录共享额度、空目录、普通文件、目录变化/链接、最终本地保护及过期。Shell fixture 使用原版匹配函数重现“通配规则只匹配深层文件”，确认根通过、后代白名单拒绝，适配脚本和上游文件不改写。浏览器覆盖命中路径/来源/计数、问题筛选、额度解释、取消、重新复核和自动过期后的证据清除。本机原生结果见 [开发记录](development.md)。

后代路径判断仍不是后代每个模块的完整规则、稳定锁、连续身份快照或删除权限。通配规则匹配结果也依赖当次有效配置；配置、句柄和内容都可能随后变化。源名称到实际移动对象的竞态、完整模块/锁策略和用户确认仍需闭合，之后再连接受限执行器。
