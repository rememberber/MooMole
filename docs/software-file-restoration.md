# 软件文件与真实废纸篓恢复

2026-11-03：可靠活动历史中的普通目录文件现可从“恢复原位置…”或勾选后“恢复所选原位置…”发起检查，支持浏览器下载、VLC 列表媒体、Telegram 导出附件和 Music 导出媒体。原记录继续保存，恢复另记一批；用户重新核对当前位置、原位置并单独确认，默认不选。软件清单、播放器资料库和浏览器记录不修改，恢复后应用是否立即识别文件需要另行核对。

每次按原批次/项目 ID 重读本机活动记录，要求原项目可靠 `moved` 且有真实设备号/inode/目的位置收据，并绑定原快照摘要。只读归档、缓存、永久清理、卸载、未知项目及没有实际收据的记录不产生权限。软件内容的原路径还须符合既有普通文件范围；Mail 的 Library/容器目录保持不支持本轮应用内恢复，界面引导按收据在 Finder 核对。跨卷、原目录缺失、同名冲突、保护或无法核对的身份/权限保留，不覆盖、改名或创建目录。

旧恢复路径要求以读取权限打开每层父目录，当前环境因此拒绝读取 `~/.Trash`。本节点对已知收据的源路径使用 Darwin 公开的 `O_SEARCH` 目录搜索模式，逐层 no-follow 观察确切名字；观察不枚举废纸篓或读取其中其他文件。系统仍判定搜索、元数据及最终改名权限，拒绝或未知即停止。API 模式见 [Apple XNU 的 open(2)](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/open.2)；常规扫描/归档路径继续用原有打开方式，不扩大它们的读取范围。

恢复的源见证继续绑定父链、设备/inode、所有者、权限和确认时的内容属性；目标沿用普通本地目录限制。系统调用前保留原记录/设置、源及目标身份、同卷、ACL、文件标记、只读卷、粘滞目录和有效账户写入/搜索权限复查。源目录在操作后仍以搜索模式重新打开核对名字，文件以 `RENAME_EXCL` 移回，核对目标身份/属性、原位置空缺及双端同步。无需枚举权限不等于授予修改权限，也没有修改系统授权、ACL、文件标记或隔离属性。

沿用既有三十秒、单次、墙钟/单调时钟确认；批量最多 20 项，每项独立验证和持久意图，部分成功后停止保留已完成项，无整批回滚。完成证据写入失败仍按既有机制保持未知、重开不重放。收据不是正文备份或旧版本快照，恢复的是当前位置中经本次核对的同一文件，不承诺还原处理前的所有字节。恢复仍尊重原位置的定期处理暂停要求。

持久计划/见证及恢复历史保持原协议和编码，不把搜索模式写成可移植授权。原批次不改写，恢复继续使用 `fileRestoration` 来源、move 方式及现有 v3 只读归档；导入记录不进入活动执行器。历史中新增的软件候选只提供检查入口，后端独立决定是否可提供确认。

验证：原先未通过的 `native_trash_receipt_restores_owned_file` 已在本环境实际通过生产恢复核心；样例改到项目 `src-tauri/target` 下的自动回收 TempDir，不再在 home 顶层建立目录。另从四种隔离软件账户结构经过生产扫描、明确选择/确认、正式 Mole 规则和原生废纸篓，共处理并通过产品恢复核心移回八份有效 WAV；浏览器/VLC/Telegram 使用整批恢复，Music 使用两次单项恢复。因为生产恢复要求原路径属于真实账户，这些唯一自建样例位于项目内受控构建目录，未读写真实软件数据库。
