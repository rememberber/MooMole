# 软件清理

2026-10-29：日常使用路线图的第一阶段已接入独立“软件清理”入口。用户按软件查看当前缓存候选，选择后进入正式的结构化计划、规则复查和最终确认，再由既有缓存/日志执行器实际处理。未新增任意路径删除接口。

## 用户流程

1. 顶部“扫描可清理项”或“重新扫描”调用 Mole 清理预览和应用清单；此入口不等待主目录大文件分析。扫描取消、失败及不完整结果沿用现有状态。
2. 按浏览器、聊天与协作、音乐与视频、邮件、系统缓存、其他软件或未归组候选筛选；可按软件名、名称或路径搜索。
3. 所有专项候选默认不选。用户逐项或按软件选择，筛选后保留选择并显示总数；单批仍最多 20 项。保护和过期项不能选择。
4. “清理所选”只提交本次 scan ID 与原始 item ID。重新生成计划并完成当次规则检查后，才显示最终确认；打开确认不执行操作。
5. 用户确认后复用正式缓存/日志清理、逐项结果、持久历史、取消/中断、未知核查和实际收据的 Finder 取回流程。

## 分类与执行边界

分类只匹配当前 HOME `Library/Caches` 直接子项的精确标识，并要求已有真实 userCache 来源契约。已列出的常见软件标识用于展示产品名；其他项目可按当前应用清单的精确 bundle ID 显示原始应用名。旧应用清单不用于补充名称。不会根据厂商前缀、名称子串、终端标题或安装列表缺项推导归属与删除资格。

目录标识匹配只是展示线索，不证明独占归属、未占用或可删除；未知项继续放在“未归组候选”。归组不扩大执行范围；清理时仍独立检查保护、权限、占用、严格目录树及身份变化。已有客户端保护、Mole 规则和个人数据保留语义继续生效。

聊天记录、附件、离线下载、邮件正文、登录凭据及应用支持目录没有因增加软件名而进入新的处理范围。软件专项的完整内容发现、预览、时间筛选和对应操作仍是后续任务；本阶段不标记整个软件专项或八方向目标已完成。
