# 应用实例与本机数据的占用权

2026-10-16。保护当前 SQLite 任务历史、设置、扫描/计划及执行记录的启动恢复；数据库仍为 v3，不增加真实清理接口或特权 helper。

## 修复的问题

过去每次启动都会打开 SQLite，把 queued/running 任务标为中断，并对运行中的执行记录进行对账。如果另一个 MooMole 实例仍在运行，第二个实例的启动恢复会误改第一个实例的现场。单条 SQL 事务及“最多一个 running 批次”索引无法区分正在运行的另一个应用和真正崩溃后的旧记录。

现在生产启动仅调用 `db::open_owned`。它先取得数据目录占用权，再打开数据库、配置 WAL、备份/迁移、恢复中断及执行保留期限清理。没有占用权时不进入 SQLite 初始化；原始初始化函数成为私有接口，独立连接/故障注入测试另用仅测试编译的入口。

## 占用与生命周期

数据目录使用固定 `.moomole-instance.lock` 普通文件。通过非阻塞 `flock(LOCK_EX | LOCK_NB)` 判定内核中的真实持有者，不解析 PID、时间戳、文件内容或“文件是否存在”来猜测进程存活。

- 新建文件使用 0600，必须是当前有效用户的私有普通文件、单链接；符号链接、硬链接、特殊文件、过宽权限及打开期间的身份变化均拒绝。
- 使用 `O_NOFOLLOW / O_NONBLOCK / O_CLOEXEC`，防止跟随末级链接、在 FIFO 上等待以及常规 exec 子进程继承占用描述符。
- 文件持续存在，释放时不删除或重建它。删除锁文件可能产生两个不同 inode 的锁空间，因此不提供“删除过期锁”或自动接管操作。
- SQLite 连接与占用句柄保存在同一个 `Database` 对象，AppState 的 Arc 克隆和后台任务共同保留它；先关闭 SQLite，再释放占用权。
- 释放时明确 `LOCK_UN` 后关闭描述符，避免并发 fork 在 exec 前短暂保留描述符副本而延长正常释放。正常 exec 仍由 CLOEXEC 隔断继承。
- 进程异常退出由内核释放；新实例取得占用权后按原协议标记中断/待核实，不自动重放任务或处理目标。

另一个实例持有时，后启动实例隐藏工作窗口，以原生说明提示切换到已打开的应用；关闭说明后退出该实例。初始化失败也提供原生原因并退出，不自动修复文件权限或删除本机数据。对话框使用已有 Tauri dialog 的非阻塞 API，主线程不调用 `blocking_show`。当前没有实现自动聚焦前一个实例。

## 验证范围

Rust 隔离 fixture 覆盖：

- 私有文件、目录别名、同一进程/独立进程互斥；文件内容不作为占用证据，重复尝试不截断文件，正常释放保留同一 inode。
- 符号/硬链接、过宽权限、FIFO 拒绝，测试目标正文与权限不改写。
- FD_CLOEXEC、真实 exec 子进程不延长占用，模拟 fork 共享描述符的副本不阻碍显式释放；旧副本关闭不释放新持有者的锁。
- 独立测试子进程持有真实 SQLite 任务，第二个启动拒绝且任务保持 running；正常退出及强杀后再启动才标为 interrupted。
- 占用冲突发生在 SQLite 创建之前；初始化失败释放占用权；后台共享句柄全部释放前不可接管。
- 合法计划的执行 intent 在第二个启动后仍为 running/intent，旧持有者退出后才变成 interrupted/uncertain，未开始项保留 notStarted，未操作任何目标。

所有子进程、标记、数据库及执行意图均属于测试临时目录。没有向用户数据库注入模拟记录。原生验证结果和测试计数见 [开发记录](development.md)。

## 边界与后续

这是同一数据目录下、遵守协议的 MooMole 实例之间的协作占用。它不是清理目标的锁，不阻止外部应用写目标，也不提供文件系统事务、连续身份快照、源 inode 绑定或执行授权。

旧版或绕过本协议的程序、手动删除/替换占用文件、敌意目录替换、跨用户或不支持可靠 flock 的文件系统不在该互斥保证中；不识别时失败，不通过 PID 超时强行接管。首次升级需正常退出旧版，再打开新构建。强杀不保证任意脱离组后代都立即退出；fork 后永不 exec 的额外后代仍可能保留描述符，这是整个进程生命周期的剩余边界。

仍须完成真实修改的目标范围排他策略、完整 Mole 模块/活动规则、最终源名称与实际对象绑定，以及确认和执行器接入。重复启动的自动聚焦、休眠/系统故障和正式免费 DMG 的多副本行为也需后续验证。无需 Developer ID、Apple 公证或付费发布服务。
