# 已下载应用包的手动更新

这是已安装第三方应用的独立更新流程，不改变 MooMole 自身 DMG 手动升级协议。

从保留的成功 Mole 应用清单中选定一个普通 App，以 task/index 取得后端目标；前端不能提交任意安装路径。用户另外选择已下载并解压的新版 `.app`，后端核对同 Bundle ID、纯数字版本/构建号递增、本机 Mach-O 架构和部署版本、完整签名与发布者连续性。证书签名要求相同团队且满足旧包 designated requirement；双方均为 ad-hoc 时只验证完整性，不宣称已确认发布者或 Apple 公证，须由用户核对下载来源。

第一条操作路线支持 `/Applications` 或本账户 `~/Applications` 根目录、当前账户拥有的普通完整应用、可写且空间足够的本地 APFS 安装卷。识别为 Homebrew、Store 收据、已知登录/后台/特权组件、系统/当前客户端/Mole 或用户保护对象不进入本路线。实际执行再次检查全部身份、内容、设置、权限和进程；不是所有服务与文件占用的证明，不主动退出、强退、提权或启动应用。

## 确认、执行与旧版

准备结果最多保留一份、有效 2 分钟，执行单次取走。旧、新两份包均完整有界读取；最多 10000 项、64 层、8 GiB，每轮 120 秒。只接受物理本地文件/目录和不逃出包的相对链接，不遍历链接；硬链接、特殊文件、云占位、不可变/只追加/set-id 与不能核对的 ACL 拒绝。读取可能等待 macOS 系统调用，取消不会伪称内核调用已经返回；工作线程持有准入与安装互斥直到实际结束。

使用 held-directory `openat`/`fcopyfile` 逐项复制到安装父目录内唯一的 0700 隐藏目录，保留数据、模式、扩展属性和隔离属性。比较整树内容和元数据摘要，再复查原包、新包、暂存包签名及当前保护。属性被系统重写也会使严格比较失败而保留原包，不通过去掉隔离属性来“修复”。目录子项计数纳入摘要，避免层级歧义。

替换前 FULL SQLite 日志记录 intent，再 descriptor-relative `renameatx_np(RENAME_SWAP)` 原子交换两个完整包。旧包保留为 `原父目录/.moomole-app-update-确认ID/原名称.app`，同步两个父目录，核对交换前后 inode、完整内容、签名与路径绑定。没有旧包删除、覆盖已有暂存目录或不确定时自动回滚。任何 intent 后的故障为 unknown，重开不会重放。

取消在交换前阻止后续步骤，已经产生的暂存包保留；交换临界点之后取消不能撤销结果。日志包括安装路径、暂存/旧包路径、结果与原因；最多 64 条独立记录，未完成/未知记录需人工核对后才能开始下一次本模块更新，并执行共享清理/卸载/维护日志准入。不会自动删除历史或旧包。

旧包仅包含应用程序；偏好、文档、数据库和外部辅助服务不随包恢复。当前恢复入口为显示安装位置及旧版目录、退出后手动替换；不能保证新版写入的数据适用于旧版。

## 验证与下一节点

原生核心已用两份自建、二进制 plist、临时签名的真实 Mach-O App 执行复制与替换，核对旧 inode/旧字节、新字节、源包不变、相对链接、签名、隔离属性，以及 SQLite 关闭/重开。没有运行样例程序或触碰用户应用。取消、保护变化与 intent 持久化失败均保留原包；记录未知、中断对账与拒绝重放另有测试。

应用窗口、来源选择/确认/取消/记录、构建产物在下一节点验收。自动发现/下载更新、管理器对接、需要管理员的应用、更多卷/版本格式、后台组件、原生恢复与完整实际应用兼容性仍在完整目标内。本核心验证不等同于打包 App 窗口验收或发布就绪。
