# 应用打开与正常退出

2026-10-30：应用列表中的普通 App 可选择“打开”或“退出…”，核对确切安装路径后确认执行。只从保留的成功 Mole 清单解析目标，不接受前端提供的路径、PID、命令或任意参数。

- 打开使用 NSWorkspace，已有运行副本时仅向相同位置请求显示。遵循 macOS 安全提示，不绕过 Gatekeeper。
- 退出使用 NSRunningApplication 的正常退出请求，核对包标识、安装位置和当前用户；保护目录、系统/客户端和后台专用应用不提供退出执行。没有强制结束。
- 请求前核对 App、Info.plist 和主程序的本地身份。退出可能被拒绝或出现保存提示，十秒内未确认则显示待确认；停止等待不撤销已经发出的请求。
- 每次操作在系统请求前写入任务历史，再保存观察结果。取消/失败不重试，重启不重放。完成后列表标记过期，刷新后才继续操作或卸载。此流程不产生删除或恢复收据。

基本验证：前端构建、203 项单元测试；7 项应用列表与操作浏览器回归；Rust 默认回归及专用原生样例测试。原生测试临时编译、自签和启动自建 App，观察打开、正常退出及原包保留；未操作用户应用。AppKit 的后台线程通知可能滞后，退出观察同时接受明确的 PID 不存在结果，权限不明不算退出。

尚待补充：实际打包 App 的新入口窗口验收、多窗口保存提示交互及更完整中断矩阵。关联数据处理、登录项/后台管理和更新仍属后续应用管理范围，不能以打开/退出代表完整应用管理完成。
