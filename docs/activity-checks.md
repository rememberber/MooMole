# 审阅计划的附加占用观察

2026-10-16。固定 Mole `1.59.1` / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f`，rules 协议 v4、模块规则 v2、附加观察 v1。产品继续以 Mole CLI 可视化与人性化解释为主线。

## 适用范围与含义

只有扫描来源绑定、准确路径范围、当前本地身份/保护、Mole 路径条件及已接入模块条件均满足时，才继续附加观察。目前限于 `clean_user_essentials` 契约下的用户缓存直接子项，以及其 `_clean_user_log_directory` 契约下的用户日志/单个诊断报告。混合、别名、缺失或未适配来源不会按路径补猜。

客户端复用原版 `_mole_container_cache_has_open_handle`：文件按准确路径、目录用 `lsof +D` 观察后代，沿用完整进程视图、超时、诊断及身份判断。这是客户端额外的只读观察，并非声称普通缓存/日志模块本来都运行这个 helper，也没有运行任何清理生命周期或操作 sink。

适配层在 helper 前后另行核对父目录和目标身份：上游对已经不存在的目标也可能返回 1，不能把这个早期返回当作“未发现打开句柄”。原函数对无匹配也要求空输出、正确返回值与身份一致；错误文字不会被当作空输出。发现部分打开记录仍显示占用。

## 状态与预算

| activityCode | 界面含义 |
| --- | --- |
| `busy` | 发现所选文件或目录后代的打开句柄，应保留；不自动关闭应用 |
| `noOpenHandles` | 本次完整视图、无匹配及身份核对未发现句柄；不是持续空闲保证或执行许可 |
| `unknown` | 无法取得完整视图、权限受限、超时、目标不存在或身份变化等，不能确认 |
| `budgetExhausted` | 本批额外探测预算已用完，此项未确认；建议缩小选择 |
| `checkFailed` | 缺少函数或适配调用异常，未可靠完成 |
| `notChecked` | 路径或模块条件未满足，没有运行附加观察 |

本批第一次符合条件时建立基于上游 Bash `SECONDS` 时钟的共享 5 秒探测期限；所有后续额外探测复用，不为每项重置，环境中的 medium timeout 不得扩大它。它约束附加 lsof 探测，不是整个批次的硬实时期限；原有路径规则、身份读取和调度仍有开销。整次规则任务继续最多 500 项、8 MiB 报告、45 秒外层期限及可取消进程组。信号返回终止本次报告，不生成完整成功结果。

整个规则批次清除继承的完整视图结论，并启用 `MOLE_TEST_NO_AUTH=1`。不调用 sudo 或申请新授权。普通账户不能确认完整视图时显示未知；不会因为空输出就报告空闲，也不因此要求用户开启额外权限。

## 数据与界面

`RuleCheck.activity` 分开保存 version/code/source/reason；它与路径结果、模块证据并列展示。`activityBusy`、`activityUnknown`、`activityUnavailable` 纳入“只看需要确认的项目”，且不覆盖过期、对象变化、客户端保护或模块拒绝。前端收到缺失字段、未知版本/状态时明确显示缺少可识别证据。

结果仅保留在当次弹窗内存。重新检查、本地复核、取消/失败、过期或关闭弹窗后不复用，不写入持久计划或数据库执行记录。旧 rules v1/v2/v3 资源清单和响应均拒绝；重新离线准备引擎并打包。clean v2、来源 v1、路径观察/目录摘要 v2、SQLite v3 不变。

## 验证与边界

隔离 HOME fixture 中真实打开文件和深层文件，通过仅测试的完整视图 override 验证准确/递归 lsof 能识别占用。这不证明普通账户具备 root 进程视图；完整视图未知分支另测。固定返回注入覆盖空匹配、诊断、部分字段、超时、信号、身份替换/消失、预算耗尽、缺失函数、异常状态、前置拒绝及禁止 sudo。所有替换与移除只作用于测试临时文件。

Rust 验证协议版本、状态/前提组合及本地状态优先级；浏览器验证解释、来源版本、问题筛选、预算提示、旧数据回退、取消及复核失败后的证据清除。本机原生结果见 [开发记录](development.md)。

没有锁定应用，也没有建立所有者租约、连续快照或操作授权。检查结束后可以立即出现新句柄；目录后代保护、其他模块条件、深层晚期变化、最终源名称与移动对象绑定仍未闭合。没有开放真实删除或恢复入口。后续须先确定首批可支持范围、并发/锁策略和执行前规则，再连接确认及受限执行器。
