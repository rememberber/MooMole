# 重复文件第一版

2026-10-29：先补齐大功能主流程，再统一深化。侧栏“重复文件”已实现选择目录、读取内容分组、查看路径、选择副本、明确保留至少一份、确认、实际移入废纸篓及共享历史。相似照片、连拍与视频对比仍在完整目标中，本阶段仅判断字节内容相同的文件。

扫描沿用个人目录的普通文件范围，先按大小筛选，再读取 SHA-256；同名、同大小和相似外观不直接算重复。不同位置可能有各自用途，不默认勾选，不自动挑“应删”的副本。筛选匹配组后显示该组全部副本，避免只看到搜索命中项而遗漏保留副本。

每组至少保留一份，前后端都执行此约束。确认页列出这批实际保留的路径。执行前再次核对所选文件与保留副本的内容，最终原生关口继续检查双方身份；保留副本变化、缺失、无法读取或取消时，不继续处理本项。普通个人文件的占用与恢复边界沿用 [文件整理](personal-files.md)，不把“内容相同”当作持续空闲保证。没有永久删除或清空废纸篓。

扫描可取消，目录遍历保持原 2,000 个文件等上限，内容读取另限 4 GiB / 120 秒，超出或无法读取明确显示范围有限。只对已核对的文件分组，空文件、隐藏/系统/应用/资料库、链接、共享硬链接、云占位与受保护范围不纳入。取消保留已取得的分组。预算在读取之间检查，不承诺中断挂起的系统 I/O。

重复文件有独立内存状态与来源 `duplicateFiles` / `MooMole.duplicates.v1`，共用既有确认、修改准入、取消、原生 Trash、意图/结果、未知核查与归档。保留副本证据随原始计划保存，不保存文件正文；SQLite 仍为 v8。旧客户端不认识此来源，应使用包含该功能的客户端读取对应历史。

本阶段验证：完整 Rust 默认回归 577 通过、72 显式忽略；前端 203 项单测和重复文件/个人文件的 8 项浏览器流程通过。另显式运行正式 Mole 规则与生产执行器，在三份自建同内容文件中实际处理两份，保留一份，按实际收据取回并核对全部正文，重开与归档结果保持（私有证据 `.cache/duplicates-native.json`）。独立 arm64 ad-hoc App `local-artifacts/MooMole-duplicates-sgHiP0/` 实际完成扫描、分组、选两份/留一份、明确确认、真实处理及历史来源查看。Shell 的废纸篓读取/移回受系统限制，未升级权限，使用 Finder 的正常取回流程后核对 inode/全部正文、保留及独有文件并清理自建目录，见 `.cache/duplicates-ui-evidence.json`。浏览器 mock 不代表本机文件操作。

下一阶段横向推进其他大功能；相似照片、空态/共用提示用词及更丰富的批量选择体验留待统一深化，不在本节点穷尽边角。
