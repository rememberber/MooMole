# 选中项清理的受控闭环

2026-10-20。实现：`src-tauri/src/execution/tests/controlled.rs`。这是清理主线的隔离联验，**不是已开放的清理功能**。

## 目标和范围

把此前分离的计划、移动实验和正式 SQLite 执行记录串起来，验证“确认了哪些项，就只尝试这些项；结果不明时停止并保留证据”。不继续扩大应用关联目录规则，也不把测试通过当作真实清理已经完成。

代码是 `execution::tests` 的子模块，仅在 `cfg(test)` 中编译，没有 IPC、页面按钮或访问用户清理目录的入口。每次测试创建独立私有根目录、临时 SQLite、`source` 与 `recovery`，从 3 个自建普通文件中选 2 个；未选中的文件保持原处。源路径必须是本次私有 `source` 的直接子项，即使新确认的数据库快照包含其他路径也会在建立执行批次前拒绝。

普通测试的恢复目录不是 macOS 废纸篓，不表示释放空间。显式原生测试另用 Foundation 移入废纸篓并取回同一批自建文件，不枚举/清空已有废纸篓，不修改个人缓存、应用数据、用户设置或用户执行历史。

## 接通的流程

1. 从 SQLite 按计划 ID 读取固定选择；确认原型绑定该份完整计划 JSON 的 SHA-256、确认时间和有效期。到期不晚于计划到期或确认后 30 秒，时间回退也拒绝。这个短期确认只是测试契约，没有产品授权效力或已定稿的确认协议。
2. 每项开始前读取当前数据库保护设置、计划有效期、文件及祖先身份与有限权限观察。只考虑未变化、单硬链接的普通文件；目录及其他不支持条件保留。保护读取失败停止，不能回退为空列表。
3. 规则明确区分 `PassedFixture / RetainFixture / UnknownFixture`，缺项为未知。**这些是假规则结果，未调用真实 Mole 模块，不能授权处理真实用户数据。** 意图前再次复核保护、时间、身份、权限和 fixture 规则，取消则不提交此项意图。
4. 原生后端在意图前准备并核对文件对象引用，禁止在意图后从旧名称重新建立引用。先通过正式 `execution::intent` 提交，再最终核对原身份与位置并调用处理 API；已知变化不调用原生接口。私有恢复后端仍是名称竞态的对照实验，使用持有的父目录描述符与 `renameatx_np(RENAME_EXCL)`，不覆盖已有恢复文件。原生后端通过 Foundation 获取实际返回位置，不推测废纸篓名称。
5. 核对实际目标的设备/inode、类型、权限、所有者、链接数、大小和修改时间，补查原位置不存在、原祖先路径仍绑定相同对象。已知未修改的私有移动失败记录 `failed`；无法确认的原生错误或结果变化记录 `uncertain`。目的位置已知时保留观察收据。
6. 取消仅阻止未开始项；意图已提交的当前项必须收集结果。部分失败保留其他实际结果；最后一项完成后才到达的取消不改写完整完成。出现不确定结果立即停止后续项，不自动重放或回滚。
7. 意图写入失败不调用移动；实际移动后结果写入失败保留在途意图，重开数据库后记为待核实，后续项记为未开始。确认快照改变、未知计划或重复计划不能重新执行。

## 验证与命令

普通集成测试覆盖：固定选中范围、确认摘要和有效期/时钟回退、持久计划重排与越界拒绝、未知/保留规则、动态保护、保护损坏、身份变化/链接/硬链接、意图前后的取消、恢复重名、SQLite 写入拒绝、三个操作边界的中断和重启、不自动重放，以及最后源名称/父目录替换。文件名包含中文、换行和 glob 字符，不经 Shell 插值。

```bash
node scripts/cargo.mjs test execution::tests::controlled
```

原生废纸篓联验默认忽略，需显式运行，只操作其自建文件：

```bash
node scripts/cargo.mjs test execution::tests::controlled::native_trash_sqlite_workflow_restores_exact_receipts_and_preserves_collisions -- --ignored --exact --nocapture
```

本机 2026-10-20 已通过：两项完成移入、SQLite 记录和实际目标收据重开后保留；原生移动接口取回时遇到新建同名文件拒绝覆盖，双方均保留，显式移开测试冲突项后两项均取回，设备/inode 与内容核对通过；未选文件保持原处。成功后清理自身测试根。原生操作开始前关闭测试根的自动清理，若失败则保留根、数据库及 `native-workflow-rescue.json`（报告写入成功时）并打印路径；不会盲目删除或从废纸篓自动搜索补救。

这里的取回是测试驱动按确切收据进行的手动恢复，未写入产品恢复记录。没有把最小收据当作完整用户恢复授权，也没有证明 Finder“放回原处”、跨卷、其他账户、干净机器或发布 App 下的行为。

## 当前硬关口及下一步

2026-10-20 后续验证已修正原生引用建立时机，并加入独立的最终验证。源码、7 个原生竞争场景与 SQLite 无修改结果的联验见 [对象引用与并发变化](cleanup-concurrency.md)。只读准备对象进入内部模块，文件修改仍仅测试编译。检查前的已知变化已拒绝；检查后的原选中对象仍可能在位置或内容变化后被移动，因此还不能称作完全防止误移或已开放真实清理。

名称竞争测试故意在意图后把原文件移开，并在同名位置创建替代文件。按名称移动仍会移动替代文件，事后核对可发现、记为待核实并停止；原文件、替代文件与后续文件都保留。父目录替换测试同样证明：持有父目录不会锁住原路径范围，必须撤回成功结论。**发现异常不等于阻止误移，因此受控驱动和原生后端仍须保持测试专用。** 文件引用 URL 也不能单独解决路径授权问题，详见 [原生实验边界](restricted-execution.md)。

当前候选策略已明确为提前绑定对象、最后核对原路径、已知变化拒绝、不确定停止留收据；最终窗口的范围/内容变化继续作为受控 Alpha 的失败路径验收，不声称已有原子保证。下一步为来源明确的用户日志普通文件接入当次真实 Mole 模块/占用条件与确认流程，再验证原生权限、任务控制和逐项结果；不能满足就缩小支持范围或调整处理方式，不开放目录/共享数据或改用全量 CLI 清理。恢复只承诺验证过的方式；移入废纸篓不表示释放了空间。应用卸载和产品目录特例不插到这条主线之前。

当前写入拒绝使用 SQLite `query_only` 故障注入，不是真实磁盘满；驱动边界中断为进程内注入，已有独立进程 SIGKILL 记录层回归见 [崩溃验收](execution-crash-recovery.md)。尚未认证原生操作过程中的强杀、断电持久性、卷消失或最终竞争窗口。
