# 应用清单的保护提示

2026-10-18。本轮提供只读提示，不提供卸载计划或执行资格。入口仍是原清单的“位置与来源”，不在折叠行逐项检查。

## 用户看到的结果

- 命中客户端规则：显示“已命中客户端保护 · 当前仅供查看”，列出原因及实际重叠的保护目录。多个原因可以同时存在。只命中 Mole 系统组件规则时显示“Mole 要求保留”；官方卸载器限制给出厂商与下一步，不解除其他保护。
- 未命中：显示“归属待确认”。Mole 系统组件和官方卸载器规则分别显示本次未命中；后台目录条件单独观察，完整关联文件、共享数据和个人数据归属尚未确认，不能解释为可卸载。
- 新检查开始撤下旧结论，单项规则不可读保留未知及已确认的其他保护；整份检查失败或协议异常则不发布部分结果。正常结果一分钟后标为较早；不会后台逐行轮询。

## 客户端规则

1. 系统目录：应用位于 `/System` 或 `/Library/Apple/System` 的目录组件之下。此为额外的客户端保守限制，不是所有系统应用的完整识别规则，不按 `com.apple.*` 一概判断。
2. 当前客户端：应用路径等于当前可执行文件所在的 .app，或本次本地读取的 Bundle ID 等于当前 App 配置的标识。相同标识仅增加保护，包括其他安装副本；不代表签名、发布者或文件来源已经验证。可执行文件路径不可得时仍保留标识限制；两者均不足时保持未知。
3. 已保存保护目录：应用路径与规则任一方是另一方的祖先/自身即命中，按目录组件比较，避免字符串前缀误判；保护应用中的子目录也保护父应用。匹配结果排序去重，最多沿用设置支持的 100 条规则。已保存但当前不存在/离线的规则仍按原路径保留意图，不为本轮提示访问或改写该目录。

本轮不展开保护目录的当前别名/挂载变化，不判断共享容器、个人数据或关联文件所有权；这些仍须后续的结构化协议和执行前验证。所有文件修改操作继续关闭，未命中与未知都不产生通过状态。

## Mole 系统组件规则

固定 Mole v1.59.1 / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f` 的 `lib/core/app_protection.sh` 中，`should_protect_from_uninstall` 先检查 `APPLE_UNINSTALLABLE_APPS`，再检查 `SYSTEM_CRITICAL_BUNDLES`；数据位于 `app_protection_data.sh`。第四十九阶段将这个单项谓词适配到只读应用观察，保留大小写敏感和允许卸载的 Apple 应用例外优先级。例如普通位置的 Xcode 不因 Apple 标识而自动命中，系统目录客户端保护则继续独立生效。

生产环境不执行 Shell、不 source 卸载入口、不复制规则表，也不解析终端文案。先验证准备好的引擎清单，再对上述逻辑与数据文件核对应用内固定的 SHA-256；有界读取独立普通文件，O_NOFOLLOW/O_NONBLOCK，拒绝最终链接/硬链接、缺失、内容变化及超过 256KiB。系统组件部分仅提取两个数组中的有界双引号 ASCII 字面标识/末尾星号前缀，保留原顺序；其他语法、重复/缺失声明、空数组、未结束或超过 256 项均不适配。逻辑文件与数据文件同时绑定已审查版本，后续引擎升级须显式更新适配和核对证据，不从未知语法猜测未命中。这是固定函数的语义适配，不是生产环境调用原 Bash 函数。

结果为 protected/notMatched/unknown。标识缺失、与原清单不同或资源不可用分别保留身份无法读取、身份变化、规则无法读取的原因；Mole 未提供原标识但本地标识有效时仍可观察此单项规则，标识未比对状态继续显示。规则不可用不会撤下已经确认的客户端目录/自身保护；协议本身异常则整份观察拒绝。规则来源和修订按需展开，日常视图先显示结论及未完成范围。

`bin/uninstall.sh` 的 `uninstall_app_is_currently_eligible` 还检查路径存在及后台应用/搜索根条件；第五十一阶段已补充有限范围的后台条件观察，见下文。Mole 清单会预先排除部分项目，不能从“已出现在清单”推导完整规则通过。完整卸载判定、关联文件、白名单与执行前检查仍未适配。

## 官方卸载器提示（第五十阶段）

适配同一固定逻辑文件的 `official_uninstaller_vendor` 与原 `OFFICIAL_UNINSTALLER_RULES` 数组。输入来自本地有效 Bundle ID、保留的原 apps 清单 name、同一条目的稳定应用路径；不用 Homebrew 的 uninstall_name、前端名称参数或新查询来源，也不把名称当作厂商认证。清单名缺失、异常类型、控制字符或超过 1024 字节时，仅此观察保持未知；本地身份不同/缺失和资源不可用同样保持未知。

遵循原函数的规则顺序：每条先按 ID 前缀匹配，再按清单名称或包名中的片段匹配，首条命中决定厂商。ASCII 大小写归一与 `LC_ALL=C tr` 一致，Unicode 保持原值；包名仅移除末尾大小写可变的 .app。表从已校验资源提取，不复制匹配列表；行仅支持三个管道分隔字段，限制厂商 64 字节、前缀/片段各最多 32 个及每项 255 字节，保留原有空片段字段的合法规则。其他语法/空规则等拒绝，不执行插值或 Shell。

- officialRequired：显示“请使用官方卸载器”，说明 Mole 要求使用的厂商及“按厂商说明操作；组织管理的应用请联系管理员”。若同时命中客户端或系统组件保护，则该保护继续显示，官方提示保留在详情内。
- notMatched：仅说明本次未命中官方卸载器限制，不推荐通用删除，也不等于卸载方式已确认。
- unknown：名称缺失提示重新读列表，身份问题沿用现有原因，资源不可用提示检查引擎；同一原因只显示一次。未知不撤下已确认的客户端保护。

没有新增下载链接、打开网页、启动卸载器、关闭服务、修改组织管理配置或申请管理员权限。真实厂商是否安装、服务/组织管理状态及厂商工具的可用性仍未检查。

## 后台标记与动态目录（第五十一阶段）

已补充后台专用标记和所选应用的精确父目录观察，保留 PlayCover、可读外接卷和同对象排除条件；不枚举所有卷，不按路径前缀推定资格。区分未标记、直接位于搜索根、受目录范围限制和无法确认；规则读取失败或目录变化不作为通过。只读范围、支持类型、元数据/访问复核及上游对照证据见 [后台应用条件](application-background.md)。完整卸载资格继续关闭。

## 协议与时序

沿用 `inspect_application(taskId, index)`，不新增前端路径、标识、规则、PID 或执行参数。在原有两个实际工作器及 5 秒等待预算内先读取引擎规则，再完成本地包身份/运行观察及文件证据复核；随后从 SQLite 读取最新保存的保护目录。锁只用于短时读取，不跨异步文件/AppKit 工作。设置读取失败则不发布这次观察。规则判定不写数据库/历史、不扫描关联文件或申请新授权。引擎资源校验增加有界只读 I/O；等待超时仍由真实工作器持有名额到结束。

当前应用检查协议为 v20。`protection.reasons`（systemLocation/currentApplication/clientDirectory）与 `matchedPaths` 保留客户端命中；空原因仅表示本次客户端规则未命中。`moleProtection` 保留 version=1、固定 revision、code（protected/notMatched/unknown）和 issue（identityChanged/identityUnavailable/rulesUnavailable 或 null）。`officialUninstaller` 保留 version=1、同一固定 revision、code（officialRequired/notMatched/unknown）、vendor（已适配厂商或 null）、issue（原三个原因及 nameUnavailable 或 null）。新增 background 的标记/目录条件观察，结构与约束见 [后台应用条件](application-background.md)。前端校验版本、精确修订、已适配厂商、枚举、原因与身份/结果关系；矛盾结果整份拒绝。客户端目录字段校验不变；主设置 JSON、schema v3、CSP 和依赖版本不变。

父组件将已保存保护目录绑定到观察组件身份。添加/移除保护目录后重新检查，即使列表任务不变；旧请求和旧计时器不能覆盖新一代结果。主题或历史保留天数变更不触发无关重查。设置与文件系统不是同一事务，返回后的变化仍可能发生；这些提示不替代未来真正修改前再次读取规则、身份及归属。

隔离测试覆盖系统目录边界、Xcode 普通位置、父/子/自身目录、中文、根规则、重复/离线规则、当前路径及同标识副本、异常规则与多原因。协议和浏览器覆盖未知不变通过、保护原因、添加/移除、请求竞争、错误/重试和较早结果。真实 App 及打包验收见开发记录第四十八阶段。

Mole 适配新增字面规则、例外优先级、大小写、资源/语法失败和身份未知测试；显式只读对照测试在临时 HOME 下调用准备好的原 `should_protect_from_uninstall`，对两个原数组派生的 702 个标识逐一核对，不调用卸载入口/生命周期。正常测试默认忽略这个依赖真实准备资源的对照项，本机已显式运行通过；原生与打包证据见开发记录第四十九阶段。

第五十阶段为官方卸载器补充顺序/匹配/未知上下文和语法失败测试，同一显式对照项另与原 `official_uninstaller_vendor` 核对 74 组上下文；输入为数据参数，HOME/TMPDIR 是临时目录，不调用卸载生命周期。任务缓存新增名称绑定/异常边界，前端协议与浏览器验证行动提示、来源、保护共存、缺名称/未知/未来协议与重复原因去重；原生与打包证据见开发记录第五十阶段。

应用详情现可按需查看 [21 个精确标识关联位置](application-associations.md)，显示发现、未发现和无法确认；全部保留，不证明归属或提供执行资格。共享、个人数据与完整发现/保护仍待完成。

## 关联位置的逐项保护（第五十八阶段）

第五十九阶段补充 4 个应用组/派生根的一层名称边界扫描，动态候选同样受最新客户端路径保护；不以名称证明成员关系或独占归属，链接与不完整范围可见。自身提示表述为「客户端自身保护」，避免将候选描述成已确认属于当前 App 的数据，见 [应用组与派生位置](application-associations.md)。
