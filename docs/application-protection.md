# 应用清单的客户端保护提示

2026-10-18。本轮提供只读提示，不提供卸载计划或执行资格。入口仍是原清单的“位置与来源”，不在折叠行逐项检查。

## 用户看到的结果

- 命中已检查规则：显示“已命中客户端保护 · 当前仅供查看”，列出原因及实际重叠的保护目录。多个原因可以同时存在。
- 未命中：显示“归属待确认”，明确 Mole 卸载规则、共享数据和个人数据归属尚未检查，不能解释为可卸载。
- 检查失败、规则不可读或协议异常：撤下旧结论，保留无法确认和重试入口。正常结果一分钟后标为较早；不会后台逐行轮询。

## 本轮规则

1. 系统目录：应用位于 `/System` 或 `/Library/Apple/System` 的目录组件之下。此为额外的客户端保守限制，不是所有系统应用的完整识别规则，不按 `com.apple.*` 一概判断。
2. 当前客户端：应用路径等于当前可执行文件所在的 .app，或本次本地读取的 Bundle ID 等于当前 App 配置的标识。相同标识仅增加保护，包括其他安装副本；不代表签名、发布者或文件来源已经验证。可执行文件路径不可得时仍保留标识限制；两者均不足时保持未知。
3. 已保存保护目录：应用路径与规则任一方是另一方的祖先/自身即命中，按目录组件比较，避免字符串前缀误判；保护应用中的子目录也保护父应用。匹配结果排序去重，最多沿用设置支持的 100 条规则。已保存但当前不存在/离线的规则仍按原路径保留意图，不为本轮提示访问或改写该目录。

本轮不展开保护目录的当前别名/挂载变化，不判断共享容器、个人数据或关联文件所有权；这些仍须后续的结构化协议和执行前验证。所有文件操作继续关闭，未命中与未知都不产生通过状态。

固定 Mole v1.59.1 / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f` 的 `lib/core/app_protection.sh` 中，`should_protect_from_uninstall` 先检查 `APPLE_UNINSTALLABLE_APPS`，再检查 `SYSTEM_CRITICAL_BUNDLES`；数据位于 `app_protection_data.sh`。`bin/uninstall.sh` 的 `uninstall_app_is_currently_eligible` 还检查路径存在及后台应用/搜索根条件。Mole 清单会预先排除部分项目，不能从“已出现在清单”推导完整规则通过。本轮没有复制其规则列表、解析终端文案、调用卸载或声称已适配完整判断。

## 协议与时序

沿用 `inspect_application(taskId, index)`，不新增前端路径、标识、规则、PID 或执行参数。先完成原有本地包身份/运行观察及文件证据复核，再从 SQLite 读取最新保存的保护目录；锁只用于短时读取，不跨异步文件/AppKit 工作。设置读取失败则不发布这次观察。规则判定不写数据库/历史，不增加文件系统扫描或授权。

应用检查协议升级为 v2，新增 `protection.reasons`（systemLocation/currentApplication/clientDirectory）和 `matchedPaths`。空原因仅表示本次客户端规则未命中；前端始终补充未完成范围。前端校验枚举、唯一性、目录数量/长度/绝对路径、控制字符及 clientDirectory 与匹配路径的对应关系，异常整份拒绝。主设置 JSON、schema v3、CSP 和依赖版本不变。

父组件将已保存保护目录绑定到观察组件身份。添加/移除保护目录后重新检查，即使列表任务不变；旧请求和旧计时器不能覆盖新一代结果。主题或历史保留天数变更不触发无关重查。设置与文件系统不是同一事务，返回后的变化仍可能发生；这些提示不替代未来真正修改前再次读取规则、身份及归属。

隔离测试覆盖系统目录边界、Xcode 普通位置、父/子/自身目录、中文、根规则、重复/离线规则、当前路径及同标识副本、异常规则与多原因。协议和浏览器覆盖未知不变通过、保护原因、添加/移除、请求竞争、错误/重试和较早结果。真实 App 及打包验收见开发记录第四十八阶段。
