# 执行记录、启动对账与保留规则

更新时间：2026-10-23。实现：`src-tauri/src/execution.rs`、SQLite v4 保留原清理表格式、历史页的 `ExecutionHistory`；新增卸载表和共用准入见 [卸载记录](app-uninstall-journal.md)。

## 使用边界

这是应用内的生产记录层及只读查看接口。受限日志执行器现已调用 `begin`、`intent`、`complete_item`、`skip`、`finish`；唯一修改入口绑定后端短期确认，不提供通用记账或按路径修改 IPC。历史通过 `list_executions`、`get_execution` 查阅；仅保存审阅计划不产生执行记录或触发清理。见 [受限日志执行](log-cleanup-execution.md)。

记录层不检查当次 Mole 模块规则、不获取文件操作权限、不移动或恢复文件。它接收的只读审阅计划不能授权执行；执行器必须独立完成当次规则、用户确认、范围、身份、权限与竞态验证。不能把内部记账方法或收据暴露成通用按路径操作入口。

旧的 `execution_sandbox.rs` 仍使用独立 NDJSON 实验日志，不更改语义。新记录层的集成测试另用临时 SQLite 和临时文件，未向用户数据库写入模拟清理记录。

新增 `execution/tests/controlled.rs` 在这份正式记录层上运行选中项的完整受控循环：按数据库计划及确认快照校验，逐项读最新保护、复核身份/权限，提交意图后才调用处理接口，再保存实际结果。普通测试使用私有恢复目录，显式原生联验使用 Foundation 废纸篓，重开 SQLite 后仅凭确切收据取回自己生成的文件并验证不覆盖。它只在测试中编译，规则证据仍为 fixture；不是正式执行器或用户恢复接口，详见 [受控清理闭环](controlled-cleanup.md)。

受控原生后端已接入意图前的文件引用准备与调用前最终复核，见 [并发变化](cleanup-concurrency.md)。意图后若发现身份/位置变化并在调用 API 前拒绝，记录 `failed`、明确未调用且不生成收据；后续取消只处理未开始项，重开不改写两者。若调用过原生 API 却无法确认结果，仍使用 `uncertain`，不能与已知未尝试混淆。

## 数据与事务

- `execution_runs`：批次 ID、唯一计划 ID、处理方式、批次状态、时间、不可变计划 JSON 和 SHA-256。
- `execution_items`：计划内项目 ID、固定顺序、原始路径、当前状态、原因与实际目标收据。
- `execution_events`：按数据库序号追加的项目转换；与当前状态在同一事务提交，详情按序号显示，系统时间回退不会重排事件。

计划快照包含已有的候选、身份、祖先、影响和目录摘要，不引用扫描/审阅计划的外键，因此旧扫描回收不会级联删除执行证据。SHA-256 用于检测快照损坏，不是发布者签名或数据库防篡改证明。逐项 ID、路径和顺序必须与快照一致，否则详情读取报错并保留原始记录。

写入使用 `BEGIN IMMEDIATE`、SQLite WAL 与 `synchronous=FULL`；App 连接还启用 `fullfsync` 和 `checkpoint_fullfsync`。意图只有在提交成功后才返回成功，执行器必须在该返回之后调用操作系统。任何写入失败都停止后续动作；操作之后结果写入失败，之前的意图仍需按不确定结果处理。这些设置和事务测试不等于断电持久性认证。

收据保存原生 API 返回的实际目标路径和观察到的设备/inode，不推测废纸篓位置。设备/inode 在 JSON 和 IPC 中使用十进制字符串，避免超过 JavaScript 精确整数范围。结果无法确认但已知道目标位置时，也可保留观察收据；它仍是待核实，不能用于自动恢复。恢复需要比这份最小收据更完整的身份/内容核对和独立协议。

## 逐项状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 已固定在批次范围中，尚未开始 |
| `intent` | 意图已提交，尚无最终证据；同一批次最多一项处于此状态 |
| `moved` | 调用者报告实际移入完成及身份核对，附实际目标收据 |
| `skipped` | 意图之前被规则或本地条件拒绝，没有尝试操作 |
| `failed` | 调用者确认失败且未发生修改；无法确认时必须用 `uncertain` |
| `cancelled` | 开始该项前取消，没有操作意图 |
| `notStarted` | 批次中断后未开始的项目 |
| `uncertain` | 发生意图但没有可靠结果，或结果身份无法核对 |

只允许 `pending → intent → moved/failed/uncertain` 或 `pending → skipped/cancelled/notStarted`。未知项目、跨批次项目、重复意图、没有意图的完成记录均拒绝。仍有在途意图时不能取消结算、跳过其他项或开始下一项，必须先收集该项结果。

取消只标记剩余未开始项，已完成结果保持原样。最后一项已完成时才到达的取消，不把完整结果改成取消。全部移入为 `completed`；部分移入为 `partial`；没有修改为 `noChanges`；取消阻止剩余项则为 `cancelled`。移入废纸篓不等于释放空间。

## 重启与并发

启动一次事务完成对账：运行中批次的 `intent → uncertain`、`pending → notStarted`，批次改为 `interrupted`；已有的完成、跳过、失败、收据不改写。重复打开数据库不会重复追加这些事件。对账只修改数据库，不探测、移动、重试或自动回滚目标。

同一计划只能建立一个批次；清理和卸载在写事务中共用准入，任一模块有运行中或 `uncertain` 结果时拒绝创建新修改批次。数据库事务和唯一索引验证了独立连接竞争。生产初始化已在 SQLite 打开前获取应用数据占用权，第二次启动不能把仍在运行的批次当作遗留批次；占用权随数据库与后台任务保留，见 [实例占用](instance-ownership.md)。这不锁清理目标或外部应用。

## 容量与保留

- 清理单份快照最多 8 MiB，批次 1–500 项；与卸载合计最多 64 个批次。
- 原因最多 1024 字节，收据最多 4096 字节；候选 ID 最多 256 字节、路径最多 4096 字节。
- 按快照大小加每项 32 KiB 预留，与卸载累计最多 64 MiB；这是记录负载的逻辑预算，不是 SQLite 文件/WAL 的物理大小或磁盘空间保证。
- 达到上限时拒绝新批次，不为腾空间丢弃已有证据。
- 不含修改、意图或不确定结果的已结束批次，按设置的 7/30/90 天清理。
- 含移入收据或中断证据的记录继续保留；运行中记录也不清理。不能通过修改普通历史保留天数丢弃这些证据。

当前没有解除待核实、主动清除、导出或恢复入口。后续需要有可审阅的人工对账及清除协议，再开放写入；容量满时不能提示用户直接改库。

## 迁移与验证

当前 v1/v2/v3 原库先通过 `VACUUM INTO` 生成 `moomole-before-v4-<uuid>.sqlite`，包含已提交的 WAL 数据；备份失败不迁移。全部缺失表和 v4 在一个事务中升级，失败回滚到原 schema；已有设置、任务、扫描及清理记录保持。全新数据库直接建立 v4，不生成空库备份；v4 重启不重复备份，未知未来版本拒绝打开。旧的 before-v3 等备份独立保留，不自动覆盖；v4 新增独立卸载表，不把 App 包记录混入本文件所述的普通文件清理表。

11 项新增 Rust 测试覆盖迁移备份、备份创建失败、迁移回滚/未来版本、实际选中 fixture 移动与收据、扫描回收隔离、重启幂等、完成后取消、状态转换约束、事务故障、只读连接、独立连接锁、SQLite `max_page_count` 注入 `SQLITE_FULL`、容量和损坏快照。文件移动仅发生在每个测试自身的 `source/recovery` 临时目录，非真实废纸篓。

浏览器 fixture 验证 64 项分页/筛选/搜索、待核实与取消分别展示、长整数身份、事件顺序、读取错误与关闭中的异步结果处理。另有八个实际 SIGKILL 时点，通过独立进程调用生产记录层、占用权与启动对账，验证未开始/待核实/已完成证据及最终完成/取消状态保留，不重放目标操作。界面按现有摘要提示中断与待核实，可定位执行记录，列表刷新失败保留旧证据。详见 [进程崩溃回归](execution-crash-recovery.md)。

断电、事务提交内部任意时点、真实磁盘满、挂载消失、原生操作中途停止及发布包权限矩阵仍待完成。SIGKILL fixture 只在私有恢复目录移动自己的文件，不构成真实废纸篓执行器或删除授权。

生产启动对账现在要求先取得同一数据目录的 [实例占用权](instance-ownership.md)，避免第二个启动把第一个实例尚在运行的 intent 标成中断。记录层的独立连接 fixture 为测试专用，不开放绕过占用权的初始化 IPC。

## 收据定位（2026-10-20）

结果与历史可按批次/项目 ID 从正式记录读取实际收据，重新核对当前文件后请求 Finder 定位；没有按前端路径查找或恢复入口。手动放回不改写历史中的处理事实，旧位置失效明确提示而不自动推断已经恢复。见 [收据定位与 Finder 取回](execution-location.md)。
