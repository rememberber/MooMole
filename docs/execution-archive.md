# 执行历史归档

阶段 164（2026-10-26）补充共享执行容量的用户出口。清理、卸载和维护的活动记录仍共同受 64 批 / 64 MiB 预留限制；不提高额度或因人工核查而丢弃收据。归档将完整证据另行保存，验证后再从活动历史移出，避免正常使用最终无处释放容量。

## 使用流程

在“操作历史”顶部点“归档…”：

1. “检查当前执行记录”读取本次全部三类批次，展示各模块数量及预留容量。
2. 明确确认后，先保存并读回本机完整归档，再移出活动历史。运行中、尚未结束或含未核查未知的批次拒绝归档；须先结束/核查，不能借归档跳过阻塞。
3. 在归档中只读查看逐项结果、当时收据、事件与核查标记。原未知仍为未知，不产生执行 Session、确认草稿、原路径恢复或重试。
4. 可以通过系统保存窗口导出 `.moomole-history`，或选择归档文件重新打开。打开是经验证后保留本机只读副本，不将记录写回活动执行表；同标识但内容不同不覆盖。

归档包含个人路径、当次计划/保护上下文、检查结果、设备/文件身份与恢复收据，不含原文件正文。默认保存在应用数据目录的 `execution-archives`，目录 0700、文件 0600；不自动上传。可在 Finder 管理及另行备份，删除归档会丢失该副本，应先保管导出文件。活动 SQLite 的空闲页不保证立即缩小或安全擦除，归档也仍占磁盘空间。

## 保存、提交与故障边界

读取原三类完整详情/事件/核查并验证后，固定全部十一张执行相关表的原列值；设置、普通任务、扫描及计划表不导出或删除。原始计划快照完整保留，文件标识仍为十进制字符串，未改成 JavaScript 浮点数。准备摘要绑定整个原集合，确认期间任何事实或核查变化均要求重新检查。

提交使用 IMMEDIATE 事务、v7/FULL/外键前提；非预期触发器、其他表引用执行证据、异常类型/预算或损坏记录拒绝。归档以私有临时文件写入、同步，再不覆盖地发布新 UUID 名称，同步目录并再次同步已发布文件；macOS 使用 F_FULLFSYNC。完整读回及原事件/收据/快照验证通过、文件与目录身份保持，才按确切批次删除活动父记录并提交级联。归档工作持有占用/安装与单写入槽直到后台实际结束，前端响应消失不提前释放。

文件发布与 SQLite 提交不是跨存储的原子事务：

- 发布前失败：活动记录不释放。
- 发布后中断或原库提交失败：可同时保留活动记录与完整归档，允许出现重复副本；不自动删除副本来掩盖故障。
- 原库提交后响应丢失：需刷新活动记录及归档，再决定下一步，不能将未收到响应解释为未发生。
- 已发布文件被移动/替换或原目录身份/权限变化：最终复核拒绝释放活动记录。无法承诺消除同账户外部进程在最终复核后的竞争，也未将 API 同步请求当作所有硬件断电矩阵通过。

成功后前端明确重新读取三类活动历史，退下旧观察/核查缓存。保存失败或响应无法核对时消费原确认，先提供“刷新活动记录和归档”，不自动重试。读取窗口可关闭，迟到详情不会重开；存储期间保留等待状态。

## 文件读取边界

格式 v1 保存有界 JSON 文件头及十一表的数据正文，不携带 SQL、程序或可恢复执行权限。摘要用于完整性，不证明发布者身份。导入在应用自己创建的内存 SQLite schema 中参数化插入数据，再调用三类原详情验证器；不执行文件给出的 SQL，不访问记录中的目标路径。

文件头最多 2 KiB，正文最多 128 MiB，最多 64 批 / 32,768 行；父目录/文件链接、共享硬链接、读取中变化、重复/孤立记录、错误版本/摘要/数量及损坏的内部快照/核查拒绝。文件列表只读取头部摘要，完整验证在打开时完成；每次最多观察目录 1,024 项，超出明确提示，可在 Finder 管理或选定确切文件打开。头部无法读取的副本单独计数并保留，不遮蔽其他正常归档。不自动按普通历史保留天数删除归档。
