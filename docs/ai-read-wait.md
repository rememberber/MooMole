# AI 本地预检的超时与取消

2026-10-31：原生窗口验收发现，等待系统下载目录访问确认时，AI 任务停在目录预检，停止按钮进入等待状态。调用栈位于 `inventory::validate_root → AnchoredPath::open → openat`，尚未观察到模型调用或生成报告；原实例已请求停止并正常退出。此项不能计作原生 AI 分析成功。

这次修复只覆盖 AI 的两个本地观察阶段：目录预检前台最多等待五秒，有界元数据枚举最多等待八秒。阶段文案先显示目录访问检查，通过后才显示 Agent 检查。超时返回明确错误，取消停止后续分析；迟到的观察值被丢弃，不会因用户稍后完成系统确认而自动恢复模型请求。CLI 参数检查、模型进程及 Mole 的原有任务控制沿用既有机制，不据此宣称所有本机系统调用都可被强行中断。

系统已进入的只读调用可能继续等待返回。它仍持有共享检查槽和安装更新的活动凭证，直到真正结束：不会因前台已报超时而无限叠加读取，也不会提前允许手动安装升级。两个检查槽都被占用时拒绝新检查并显示访问提示。前台分析任务可以结束，尚未返回的后台观察不写任务、报告、模型请求或文件操作；再次操作仍需用户自行发起。

只读 worker 使用独立取消标志。超时、用户取消或等待 future 被丢弃时均撤销后续枚举；排队后才取得线程的已取消 worker 不再开始读取。正在内核中等待的调用不能靠此标志立即停止，界面和取消说明保留这一边界。helper 仅用于这两个本地观察，不允许将模型调用、持久化或文件修改放入脱离前台等待的闭包。

回归用受控阻塞的真实线程验证超时和取消：前台返回后仍占用检查槽，安装门槛仍关闭，第二次读取被拒绝；释放原调用后资源才恢复，迟到值没有触发后续回调。另验正常返回和开始前取消。全量 Rust 644 项通过、90 个显式忽略样例；AI 页面、范围与个人文件衔接的 WebKit 回归共 12 项通过。三语言、格式和生产 App 构建通过。最终 arm64 release App 位于 `local-artifacts/MooMole-0.2.0-mac-arm64-sR0TOF`，主程序及嵌套引擎的 ad-hoc 签名、架构、资源与解包校验通过，未安装、推送或发布。

原生最初等待系统确认的记录在 `.cache/ai-window-preflight-native.json`。修复后独立验收构建已完成，但再次锁屏，未能进入新窗口验证；不能以受控线程测试替代真实系统授权、取消窗口或完整 AI 处理链路。未重复发起受保护目录访问请求或替用户扩大权限。暂备的普通自建目录未进入模型分析，后续验收记录在 `.cache/ai-window-native.json`；下载目录、真实用户文件及其他系统授权边界的完整验收仍保留在目标中。
