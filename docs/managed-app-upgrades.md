# Homebrew 应用升级

2026-11-02：应用列表中 Homebrew 行提供“通过 Homebrew 升级…”独立入口，展示原已安装 Cask 版本、当前目录声明的新版、下载来源、原 App 发布者线索及管理命令位置。默认不勾选，单独确认后请求 Homebrew 下载并替换；不会转交普通 App 手动换包或卸载入口，也不因请求失败自动重试。

## 范围与确认

沿用已安装包卸载的原 Mole 清单/确切索引、唯一 App 声明、当前账户所有权、原安装收据和 appdir、完整包快照、停止状态、Mole/用户保护和后台组件限制。当前第一条可用路线限定有可比较的纯数字新版和 SHA-256、明确 HTTPS 来源、没有其他 Cask/公式包依赖、未禁用、未固定且非自更新声明的简单 Cask；`auto_updates` 的已知 JSON null 表示没有该声明，不将缺失字段等同 false。`latest`、复合版本、多个 App、脚本/pkg/附属对象、后台/特权应用、未知字段或保护状态仍需原管理工具。该范围不代表 Homebrew 全部包或更多管理器已完成。

准备只读取，保留两分钟且一次性的计划。新版须高于安装登记和 App 实际版本；确认绑定当前完整包、原安装收据、目录元数据（含版本、URL 和摘要）、原发布者签名要求及工具脚本。提交前再次核对相同包元数据和原包；过期/时钟回退、来源或保护变化均需重查。显示的是这次 Homebrew 当前目录声明，不自动执行 `brew update`，不声称已经刷新到所有上游的最新状态。外部进程仍可能在最后核对后改变 Homebrew 目录；没有跨独立包管理器的原子事务，事后版本/身份不符一律未知。

签名基于当前原包冻结 `SecRequirement` 数据，升级后严格验证所有架构/嵌套代码与资源，并与原指定要求匹配；不把目录显示名代替发布者。ad-hoc 只能检查代码完整性与相同 Bundle ID，不能认证发布者，界面会单独说明。完整签名和实际新版的最终核对发生在 Homebrew 替换之后，失败或取消也可能已经改变安装状态；没有应用内自动回滚或个人数据迁移承诺。

## 执行与历史

固定调用 [Homebrew upgrade](https://docs.brew.sh/Manpage#upgrade-options-installed_formulainstalled_cask-)，当前命令为 `brew upgrade --cask --require-sha --no-quit <已核对标识>`。保留既有环境清理、禁用自动更新/自动清理/依赖自动移除；不传 force、greedy、跳过依赖或关闭隔离的选项，不自动退出应用、提权、运行替代 Shell 或删除应用目录。当前 Homebrew 7.0.6 已移除旧 `--quarantine` 选项，正常升级保留隔离属性并可能继承相同签名身份已有的用户批准；MooMole 不自行改写安全属性，也不把正常 Homebrew 行为描述成安全评估或 Apple 公证通过。

先 FULL 同步检查记录，再请求 Homebrew fetch 下载并按当前必需摘要校验；下载后重新核对原 App、停止状态、安装收据、目录声明和保护，成功后才持久化替换意图并启动受监督的 upgrade。下载时间计入原确认期限，下载失败或期间启动/改变 App 会保留原 App，Homebrew 下载缓存可能保留，需重新审阅，不续期旧确认。命令成功仍不足以报告完成：重新读取必须恰有对应新版包登记，实际 App 版本符合声明、Bundle ID 保持、签名完整性及原发布者要求通过，原安装位置的新收据与目标一致，核对期间包保持未变。成功保留结构化的新版、发布者标签、完整包证据摘要与安装收据摘要。摘要是本机证据，不单独证明发布者身份或应用能正常运行。

意图之后停止、超时、命令失败、核对失败或完成记录丢失都保持未知，并要求查看实际状态；原诊断只作有界文本展示，不据终端文案决定文件操作。关闭/重开接回原请求，不重放；终态后要求刷新应用清单。升级、卸载在同一 Homebrew 历史中分别标记，未知核查不会改成成功或执行其他操作。本模块不提供废纸篓收据或版本恢复。

升级记录仍使用既有共享活动容量，可经统一归档释放。包含升级记录时使用 v5，固定十六表和 v4 的预算保持，拒绝把升级降级为旧版本归档；旧卸载和其他 v1–v4 归档的原字段/字节保持。只读归档明确显示 Homebrew 升级和版本变化；导入不创建执行计划、重新调用 Homebrew 或取得版本回滚权限。新记录需要包含本功能的客户端读取，旧客户端不得覆写未知数据。
