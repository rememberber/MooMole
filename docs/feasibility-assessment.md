## 结论

**指定技术栈可行，适合完成学习研究用途的 macOS 桌面工具。** 推荐 React + Vite + TypeScript 构建界面，Tauri 2 的 Rust 层负责任务、权限边界和 SQLite 访问，通过受控子进程适配固定版本 Mole CLI。逐步建设可供 GUI 调用的结构化接口，无需将清理引擎整体重写为 Rust。

需要先确定两个产品条件：

- **接受开源发布**：可以考虑基于 GPL-3.0 代码继续开发；分发时履行适用的许可证义务。
- **计划闭源商业化**：应先确定可用的授权或独立实现路线，不能把直接复用 GPL 代码作为默认前提。

另外，**Mole 已有官方桌面 App**。官方说明公开仓库是 CLI，Mole for Mac 是单独的专有产品。学习研究项目不需要以商业差异化作为启动条件；如果以后转向公开产品，仅“给 Mole 加图形界面”不足以构成明显差异。[仓库说明](https://github.com/tw93/Mole/blob/ba3a0f57f78e4c22818fda701219cc3dd4d6953f/README.md)、[官方 App](https://mole.fit/zh/)

如果目标只是个人获得图形化体验，先试用官方 App 更经济；如果目标是学习、开源社区工具或开发者专用空间管理，继续做有合理价值。

## 技术路线

技术栈按指导文档确定，以下评估其职责与适配成本，不再进行桌面框架选型。

| 技术 | 职责 | 适配判断 | 主要注意点 |
| --- | --- | --- | --- |
| React + TypeScript | 页面、组件、类型化事件、任务状态展示 | 适合参考图中的侧栏、卡片、设置和列表 | 大目录用虚拟列表；不把海量文件记录全放进 React 状态 |
| Vite | 前端开发服务、构建静态资源 | 与 Tauri 的前端构建流程匹配 | Node 仅用于开发构建；应用运行不需要常驻 Node 服务 |
| Tauri 2 + Rust | 桌面窗口、类型化命令、任务调度、子进程与本地存储 | 作为前端到引擎的统一入口 | 异步读取输出；校验命令输入、调用来源及任务归属 |
| SQLite | 设置、保护规则、任务记录、短期扫描与计划元数据 | 足以支撑本地单用户应用 | 迁移、事务、过期清理及中断恢复；数据库不是文件系统的实时真相 |
| Mole Go/Shell | 既有扫描、监控、清理规则和安全检查 | 选择性复用，固定版本打包 | Shell 资源完整性、外部命令依赖、引擎协议和架构构建 |

Tauri 支持通过 `bundle.externalBin` 打包外部二进制，并按目标架构匹配文件；适合携带 Go 辅助进程。Mole 本身还包含 Shell 入口与 `bin/`、`lib/` 等资源，需要一并保留其相对目录关系，并从应用资源目录解析路径，不能只复制一个 `mo` 文件。[Tauri 外部二进制文档](https://v2.tauri.app/develop/sidecar/)

建议通过 Rust 暴露 `start_scan`、`start_status_watch`、`create_cleanup_plan`、`execute_plan`、`cancel_task` 等窄接口；这些是待实现的应用接口，并非 Mole 现有命令。前端不直接执行 Shell、不直接写执行计划数据库，也不接收通用命令执行能力。

建议架构：

```text
React + TypeScript 界面（Vite 构建）
    ↓ Tauri commands / 类型化进度与结果事件
Rust 应用层（普通用户权限）
    ├─ 任务调度 / 输入校验 / 协议适配 / 取消与退出清理
    ├─ SQLite：设置 / 保护规则 / 任务记录 / 扫描和计划元数据
    └─ Mole 执行适配层
         ├─ Go 分析与监控二进制
         ├─ 固定版本 Shell 入口及完整资源
         └─ 经改造的扫描 → 审阅 → 执行接口
后续需要系统操作时：受限的 macOS 特权 helper
```

首版可以先使用 JSON 子进程；并行读取 stdout/stderr，配置超时和进程退出清理。应用退出或任务取消时，必须处理整个子进程组以及可能已发生的部分操作。监控采用长驻采集进程，分析按任务启动；采集事件合并后更新界面，避免逐文件触发 React 渲染。

Tauri capabilities 用于限制窗口和 WebView 可以调用的能力；自定义 Rust 命令仍需正确注册并校验输入，Rust 端启动的进程也要自行限制。Tauri 权限、操作系统文件授权及管理员授权应分别处理。[Tauri capabilities](https://v2.tauri.app/security/capabilities/)

执行环境应使用受控 PATH、参数数组和明确工作目录，不依赖登录 Shell、用户别名或开发机 Homebrew 状态。对缺少的外部工具返回具体不可用原因；用户运行时无需安装 Node、Rust 或 Go，但系统/外部命令依赖仍需逐项验证。

建议把首版系统下限定为 macOS 14，作为项目取舍，而非 Mole 的强制要求。是否支持 Intel 应明确列入发布测试矩阵。

## SQLite 数据与任务设计

建议数据库放在应用专属的数据目录，由 Rust 统一访问，采用带版本号的迁移。Tauri 官方 SQL 插件支持 SQLite 和迁移，但它提供前端 SQL 接口；本项目优先使用 Rust 侧数据库访问封装，避免把任意数据库写入能力暴露到界面。[Tauri SQL 插件](https://v2.tauri.app/plugin/sql/)

| 数据 | 建议内容 | 持久化边界 |
| --- | --- | --- |
| 设置与保护规则 | 主题、展示偏好、用户保护路径及规则版本 | 长期保存；引擎执行前必须加载，不能只影响界面勾选 |
| 任务与操作结果 | task_id、引擎版本、状态、时间、按项结果、错误原因 | 区分 App 任务记录与 Mole 原始操作历史，避免重复统计 |
| 扫描记录 | 范围、测量大小、完整性状态、扫描时间、候选项 | 短期缓存、分批写入、分页读取；重新执行前必须验证 |
| 清理计划 | 选中 ID、目标属性、规则/协议版本、过期时间 | 重启后先标记待重新验证；不得因为存在数据库记录而自动继续删除 |
| 监控数据 | 当前状态及有限时间窗口的聚合数据 | 实时样本优先留在内存，首版不逐秒持久化 |

任务状态建议为 `queued → running → succeeded / failed / cancelled / interrupted`；逐项结果另外记录，确保“部分项目完成后取消”能够准确呈现。启动时把未正常结束的运行任务标记为中断，而不是显示完成。

执行计划不能仅凭 SQLite 中的路径决定删除资格；数据库可能过期或被本机用户修改，真正的边界是执行时的身份、路径和规则检查。涉及文件路径的日志应支持保留期限和清除，不保存密码、令牌及文件正文。

## 决定项目难度的四件事

### 1. 扫描、选择与删除必须对应同一份计划

推荐流程：扫描生成计划 → 用户确认候选项 → 执行选中 ID → 执行前重新验证 → 按项返回结果。

计划至少包含规则版本、文件身份或可验证属性、规范化路径、可测量大小、理由、影响、权限需求、删除方式及受保护原因。前端只提交计划 ID 和选中项 ID，执行端不应接受任意 Shell 或任意路径删除命令。

不能确认一份预览后再重新运行整个 `mo clean`，因为两次扫描之间目录内容、应用状态或规则可能变化。执行时要再次检查符号链接、路径祖先、目标身份和保护规则。普通路径字符串比较不能消除全部竞态。

### 2. “可恢复”和“释放空间”需要诚实表达

可恢复的删除优先进入废纸篓；清空废纸篓与永久删除是独立动作。移到同卷废纸篓通常不会立即增加磁盘可用空间。

因此应区分“选中大小”“已移动大小”和“实际可用空间变化”。APFS 克隆、快照、硬链接及扫描期间写入也会影响这些数值。不要承诺所有操作都能一键撤销；部分维护动作没有可靠逆操作。

分析输出中的 `partial` / `unavailable` 应传递到界面，不能把未读到的目录显示成空目录，也不能让预计可回收空间看起来完全精确。[扫描状态实现](https://github.com/tw93/Mole/blob/ba3a0f57f78e4c22818fda701219cc3dd4d6953f/cmd/analyze/json.go)

### 3. 系统权限需要单独设计

文件隐私授权、Full Disk Access、管理员权限和 App Sandbox 是不同层面的限制。权限不足时，应给出具体受限范围，并允许用户使用已经可用的功能。[Apple 文件访问说明](https://support.apple.com/guide/mac-help/control-access-to-files-and-folders-on-mac-mchld5a35146/mac)

上游有终端 sudo 和无终端时的 AppleScript 密码输入处理，但这不等于桌面端已经具备完整的权限服务。建议 MVP 先覆盖用户权限范围；后续必要的系统操作通过受限 helper 完成，采用系统授权流程、验证调用方、限定操作及参数。`SMAppService` 可用于 macOS 13+ 的服务注册与生命周期管理，但它本身不替代操作授权和 IPC 验证。[上游授权实现](https://github.com/tw93/Mole/blob/ba3a0f57f78e4c22818fda701219cc3dd4d6953f/lib/core/sudo.sh)、[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)

### 4. 上游更新与分发

发布包内固定执行引擎版本和接口版本，记录上游提交；升级时审查清理规则、协议变化及安全修复，回归后随 App 发布。运行时拉取 `main` 或完全依赖用户本机 Homebrew 版本会增加行为不确定性。

首发采用无需付费 Apple 开发者证书的 DMG 分发，使用适合 Tauri 的 ad-hoc 签名并验证内嵌可执行文件，通过 GitHub Releases 提供下载。Developer ID、公证和 Mac App Store 不作为当前发布前提。首次打开的系统提示和用户确认流程需要实测并写入文档，不能保证 ad-hoc 签名能消除 Gatekeeper 提示。[Tauri ad-hoc 签名](https://v2.tauri.app/distribute/sign/macos/#ad-hoc-signing)

Tauri 发布流程需要验证 App、Go 辅助二进制、Shell 资源路径及目标架构的完整性。参考 MooTool Electron，由 Rust 检查更新、下载匹配 DMG 并校验大小/SHA-512，用户打开 DMG 手动替换应用；新版启动时检查数据库迁移和引擎协议。公开 Beta 包含免费发行安装、系统确认和更新流程验证。特权功能也要在无付费证书前提下验证授权与辅助程序路线。

## 建议首版与产品定位

按用户最新补充，当前定位为**学习研究用途的 Mole CLI 非官方可视化客户端**。功能围绕清理、卸载、分析、维护、状态和工程产物等 CLI 能力展开，增加易理解的结果、逐项审阅、保护列表、任务控制和历史记录。下列有限规则范围是初始实现阶段的取舍，不将整体产品限定为开发者缓存工具。若以后转向公开产品，再验证与官方 App 的具体差异。

首版建议：

1. 用户指定目录的空间分析、目录下钻与 Finder 定位。
2. 基础系统状态和应用列表。
3. 3～5 类经过审核的可重建缓存/构建产物规则；跳过无法确认安全的状态。
4. 扫描、逐项审阅、确认执行、取消和明确的部分失败结果。
5. SQLite 持久化的设置、保护列表、操作日志及中断任务识别。
6. 参考图风格的设置/关于页，以及 README 和 App 中的学习研究、风险和官方产品说明。

完整应用卸载、系统级维护、自动定期删除、风扇控制和跨平台支持留到后续阶段。用户创作数据、凭据、会话、活动数据库和活动开发环境不能仅凭“旧”或“大”判断为垃圾。

## 开发顺序与验收范围

以下是后续开发计划，不表示已执行这些步骤：

1. **首先创建 `.gitignore`**：覆盖 `node_modules/`、`dist/`、Rust `target/`、本机 IDE 状态、环境密钥和运行时数据库文件；保留需要复现构建的依赖锁文件、迁移及测试数据。随后初始化 React + Vite + TypeScript + Tauri 项目。
2. 建立主窗口、侧栏、卡片、设置弹层及主题变量；先用模拟数据验证参考风格和任务状态。
3. 建立 Rust 命令、事件和 Mole 协议适配，接入磁盘分析、监控和应用列表；验证长输出、部分结果、超时与取消。
4. 加入 Rust 侧 SQLite 访问、迁移、分页读取、历史和中断恢复，明确数据清理策略。
5. 为一类规则打通扫描计划、逐项审阅、执行前验证、执行与结果记录，再逐步增加规则。
6. 补齐 README、首次使用和关于页文案，以及实际依赖的许可证声明；需要对外分发时完成架构构建、ad-hoc 完整性、免费分发安装和手动升级验证。

MVP 的核心验收是：用户能看清要处理的项目及影响，执行范围与勾选一致，任务可以取消，失败和中断可识别，历史记录不夸大实际释放空间。仅完成页面或展示 CLI 日志不算完成 MVP。

## 工期与验证

以下为更新后的工程估算，按 1 名熟悉 React/TypeScript、Rust/Tauri、macOS 与 Go/Shell 的全职开发者计算，包含基本测试与约 30% 余量；各阶段为从项目开始计算的累计时间。比初版估算增加了参考界面组件、Rust 适配层和 SQLite 迁移/恢复的明确交付范围，不代表 Tauri 本身必然更慢。未包含额外授权谈判、商业支付系统、Windows/Linux 引擎和大规模应用兼容库。

| 里程碑 | 累计时间 | 交付与边界 |
| --- | --- | --- |
| 只读验证原型 | 约 1 周 | `.gitignore`、脚手架、参考风格主框架、JSON 接入和 SQLite 迁移最小验证 |
| 可用 MVP | 5～8 周 | 上述有限规则、完整审阅执行闭环、用户权限范围清理、本地存储及说明文案、内部安装包 |
| 小范围公开 Beta（可选） | 10～14 周 | 免费发行 DMG、系统确认、下载校验/手动升级、数据库升级及更多真实机器验证；选择性增加卸载或特权操作 |
| 接近完整综合工具 | 3～6 个月或更久 | 覆盖多类维护、更多机型和应用，长期维护规则 |

不应把这些估算当成交付承诺。团队经验不足、闭源引擎独立实现或扩展系统兼容范围时需重估。

建议先投入第一周验证以下条件：

- Tauri 能可靠携带并启动指定架构的 Mole 二进制和 Shell 资源，界面不具备通用 Shell 执行入口。
- SQLite 迁移、任务记录写入和启动时的中断识别可行；参考图布局在真实窗口中正常工作。
- 在普通权限和受限权限下，能否准确呈现完整/部分扫描结果。
- 能否在隔离样例目录中为一类缓存生成结构化计划，验证只执行勾选项目的路线；这不等于完成生产清理接口。
- 许可证和公开名称的处理方向是否清楚；研究阶段按需求落实官方产品引导。

MVP 阶段重点验证取消、文件被替换、符号链接、权限拒绝和部分失败；删除验证应先用隔离测试目录、假数据和命令替身，再安排真实机器受控试用。发布前覆盖 Apple Silicon/Intel（若支持）、最低/最新系统、外接卷、异常文件名、运行中应用、重复启动、数据库迁移及完整安装包内的资源定位等场景。

## 立项建议

建议按指定技术栈推进学习研究项目：先用一周完成只读原型、SQLite 最小验证和单规则隔离验证，再进入 MVP。首版采用 macOS、React + Vite + TypeScript + Tauri 2 + SQLite、固定版本 Mole 本地引擎、有限用户目录清理；Rust 负责统一执行与存储边界，Go/Shell 负责已有引擎能力。

后续开发首先创建 `.gitignore`，随后初始化项目。README 和 App 按指导文档加入学习研究、风险及官方产品提示。公开分发前明确 GPL 与品牌方案；如以后商业化，再单独评估授权、产品差异和长期维护投入。
