# 只读任务的状态查询与界面恢复

2026-10-16。覆盖目录分析、系统快照、应用列表、开发缓存检查、Mole 清理预览及 Mole 历史读取；规则复查和未来修改操作不在此协议范围内。历史读取结果仅短期缓存，不导入原始日志，见 [历史读取](mole-history.md)。

## 后端状态

- 前端用任务 ID 查询 `get_task_snapshot`，不能提交 Shell 或结果路径。任务 ID 必须是 UUID，未知 ID 返回错误。
- `start_task` 成功接受后，SQLite 已有运行记录。结束时先保存最终历史、发布短期结果快照，再移除运行句柄并发送完成事件。
- 查询先查看结果缓存，再结合 SQLite 和运行句柄；结束边界再次查缓存。历史先写入完成、快照尚未发布的极短间隔仍返回运行中，避免误报结果已丢失。
- 无运行句柄但历史仍为运行中的任务显示为中断，不重新启动。原生进程重启仍使用既有的 SQLite 中断恢复逻辑。

## 结果保留

结果仅在当前原生进程内临时保留，最多 10 份；单份 JSON 序列化大小不超过 8 MiB，总计不超过 16 MiB。10 分钟后在读取或新增时淘汰。超大结果先计量，不额外复制完整结果入缓存；保留最终状态及“结果未保留”的解释。

这些是序列化数据预算，不等于进程内存硬上限。完成事件仍可直接交付大结果。缓存淘汰或原生进程重启后，历史状态继续可查，但不凭空恢复已丢失的分析/状态数据；界面提示重新检查。已有清理扫描和审阅计划仍按原 SQLite 策略独立保存。

空间分析成功结果现包含客户端附加的 `mooObservation` v1，记录当次引擎调用的开始/完成时间、单调耗时与引擎来源。事件和临时快照保留同一记录，接回任务不更新为接收时间；SQLite 不保存完整分析及这份记录。该时间不代表上游缓存的原始测量时间，缓存是否命中仍为未知。字段与解释见 [空间分析](disk-analysis.md)。

## 前端跟踪

- 事件用于即时更新；快照用于补偿监听建立失败、晚到及遗漏。快照默认每 1.5 秒查询一次，一次查询完成后才安排下一次。
- 很快完成的事件会等启动请求被接受后再交付；按任务 ID 和种类匹配，其他任务事件不会完成当前等待。
- 连续 3 次状态查询失败，或总跟踪超过 10 分钟时结束此次等待并提示从历史继续跟踪。停止跟踪不等于取消本机任务。
- 启动接受后立即刷新历史；页面刷新后，从历史中的运行任务重新建立跟踪，禁止自动重复启动同类任务。接回任务时不额外自动启动系统快照。
- 历史中的运行任务提供“继续跟踪”；当前已有前台跟踪时禁用。任务结束后刷新对应历史和必要的审阅计划列表。
- 卸载界面或 `pagehide` 时停止本页观察、清理计时器及事件监听；迟到的监听注册完成后也会清理。取消仍通过原 `cancel_task` 显式请求。

这里只恢复观察，不持久化或自动重放任务结果；没有修改任务恢复或“断点续删”的含义。

历史页现可搜索/筛选客户端检查任务并查看完整记录，详情按 ID 随最新列表更新；打开或刷新记录不启动任务。最近 200 条、记录用时、未知状态与旧结果边界见 [客户端任务历史](task-history.md)。

## 空间分析任务反馈（2026-10-17）

分析页现独立显示请求目录、不确定进度和取消请求状态，取消操作集中在固定工具栏；其他页面继续使用原全局任务提示。接回时目录来自任务记录；不会把重新编辑的输入框当作运行目标。成功、取消、失败、中断和结果未保留继续由同一事件/快照决定。

结果转换保留结构化的任务 ID、种类与终态错误；取消按状态识别，不解析错误文本。分析取消是中性提示，失败保留原始诊断。观察丢失或跟踪超时为“待确认”，不是确认取消/失败，指向历史重新接回。确认终态后可主动重新分析原目录，原返回/前进请求的历史位置一起保留；不自动重试。旧取消请求的迟到拒绝按请求代次忽略，不影响后来任务。

没有新增 IPC、进度事件、数据库字段或进程停止机制。原生取消确认仍以既有终态为依据，不能据此扩大为对任意脱离进程组后代的停止保证。

## 进程停止与正常退出（2026-10-16）

运行器现已在主进程回收前完成进程组信号操作，以互斥注册及独有 lease 避免旧任务清理后续进程；普通取消先 TERM、等待 3 秒再 KILL，输出/回收另有等待上限。正常退出应用先关闭新任务准入并取消后台任务，最多等待 6 秒后结束。任意脱离组的后代、强杀和未来修改任务不在完成保证内，详见 [进程生命周期](process-lifecycle.md)。

## 受限日志执行观察（2026-10-20）

独立日志执行器现通过 SQLite 执行记录接回运行状态，不复用只读任务结果缓存。请求进行期间及 bootstrap 返回运行批次后，客户端持续读取列表；历史打开运行详情时读取逐项状态，串行 1.5 秒查询、失败退避上限 15 秒。失败保留上次证据并显示待确认，恢复读取后撤回提示。取消或观察结束不丢弃已完成的逐项结果，过期确认不会触发重放。

历史中的停止入口只接批次 ID，匹配一次绑定的活跃 Job；旧批次迟到取消不能影响后来任务。关闭详情停止本页观察，页面重载重新查询现有批次，不新建执行。完整权限/强杀/跨卷矩阵仍待完成；见 [受限日志执行](log-cleanup-execution.md)。
