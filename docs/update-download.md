# 手动下载更新包

2026-10-18。设置 → 关于支持检查后手动下载、进度、取消、校验和“打开 DMG 安装”，也可在 Finder 中查看。保持单产品、精确架构与手动替换 App；只有用户确认“打开并退出”后才准备安装。默认手动下载；可选择在手动检查后自动下载，不自动覆盖 App。检查协议见 [更新检查](update-check.md)。

## 用户流程

检查发现匹配安装包 → 下载更新包 → 下载进度 → 校验保存的文件 → 更新包已下载并校验 → 打开 DMG 安装 → 确认打开并退出 → 检查任务/保存状态 → 重新校验文件 → 系统接受打开请求 → 退出 MooMole → 用户手动替换应用。

- 下载在后端独立运行，关闭设置不会取消；重新打开通过本地快照恢复观察，不重新联网检查或重复下载。只有关于页打开时每 700 ms 串行读取一次本地状态，下载本身不依赖前端事件。
- 下载与校验期间禁止重复下载或重查。取消先显示正在取消并清理，后端清理结束才显示已取消；若完成先于取消，则以实际后端结果为准。
- 收到全部字节不代表完成，显示校验阶段；流中的字节数/SHA-512 与保存后重新读取的文件均通过，才显示已下载。验证失败可重试，状态读取失败明确显示尚未确认并禁用 Finder 入口。
- Finder 入口先重新核对文件身份、普通文件/私有权限/单一链接、大小、SHA-512 及系统隔离元数据，再请求 Finder 显示。变化后的文件取消已下载资格，要求重下；只查看文件，不打开或执行 DMG，也不退出 App。
- 没有匹配资产、没有有效检查、检查超过 15 分钟时不启动下载。前端不传 URL、版本、摘要、文件名或保存路径；后端只使用本次运行内最后一次成功检查选中的资产。

## 可选的自动下载

更新区提供“手动检查后自动下载”，默认关闭。保存开关不会检查更新或立刻下载已显示的版本；仅在后续手动检查成功、精确选到当前架构新版且没有可复用的完整包时，由 Rust 启动现有下载任务。启动、进入设置及定时维护都不会因此自动检查更新；安装继续要求“打开并退出”确认。

- 本次检查先尝试复用本地包，再在数据库锁内读取最新偏好并决定是否接受下载。关闭在决定之前保存则不自动开始；已经接受的下载不会因关闭开关而取消，可用进度区的取消按钮停止。失败不自动循环重试，保留版本、错误和手动重试入口。
- 下载使用同一固定来源、精确选择、大小/SHA-512/保存后复核、隔离属性、进度/取消与任务生命周期。不会在偏好中存入来源、路径或资产数据，也不会从旧检查或缺架构结果推测下载目标。
- 偏好保存在本机 SQLite 的可选 update_preferences 单行附加表，只有用户保存开关时才创建，默认读取不写表。与现有 v3 表和 settings JSON 分开，不改变 user_version；兼容原有 v3 JSON 解码及已知旧设置 SQL。保存用事务提交，失败保留原值，读取失败按关闭处理并显示说明。此格式兼容测试不代替全部旧版本安装/升级矩阵。
- 本面板正在检查、已观察到本地复核、保存或安装准备时暂时禁用开关；保存成功才改变显示值，关闭设置后从后端快照恢复。设置写入参与安装准入，安装准备时不能并发改变它。浏览器预览禁用此开关。

## 手动打开与退出

- 只在已下载并校验、观察状态可确认时显示“打开 DMG 安装”；先在更新区确认“打开并退出”，也可暂不安装。设置保存未完成时禁用安装；继续提供 Finder 查看，不新增独立安装器页面。
- `install_update` 不接受 URL、路径、文件名或退出参数。后端安装入口与检查任务、规则复查、设置保存、计划保存、诊断文件保存和更新检查/查看共用准入屏障；已有工作时拒绝安装并保留工作，不替用户取消任务。安装准备期间拒绝新增上述操作及重复安装。
- 后端核对 SQLite 无运行/排队任务及运行中的修改批次，确认无未提交事务，并完成 FULL WAL checkpoint；失败或仍被读者占用时停止准备，保留应用和已下载包，允许重试。当前生产修改执行器仍未开放，此处预留对已有运行记录的阻断。
- 保存检查通过后重新读取已下载包，验证身份、普通文件/0600/单一链接、大小、SHA-512 和系统隔离属性；复核到系统打开请求结束之间持有更新会话占用，检查/维护不会使包失去保护。文件变化时取消已下载资格，要求重新下载。
- 只调用固定 `/usr/bin/open -a /System/Library/CoreServices/DiskImageMounter.app -- <已复核路径>`，5 秒预算、子进程关闭时停止、不使用 Shell 或调用前端路径。启动失败、非零退出或超时均保留 App 和包；错误保存在当前后端会话，关闭设置后再打开仍可查看。
- 系统命令成功只代表接受打开请求，不代表映像已挂载、用户已通过系统安全确认或新版安装成功。成功后关闭任务/保存入口，标记退出并请求正常结束；安装准备由后端独立拥有，关闭设置不会取消已明确确认的操作。
- 用户按系统提示打开映像，将 App 手动拖入“应用程序”替换，再启动新版本。没有静默复制、提权、移除安全属性或关闭 Gatekeeper。后续出现的系统确认/挂载错误可能发生在旧 App 退出后，应在系统界面处理或重开旧版；当前不监控挂载完成，也不宣称已安装。

## 连接与保存

清单请求仍不跟随重定向。下载只从已校验的本项目 GitHub Release 精确资产地址发起，最多接受三次 HTTPS 重定向：原 github.com 完整资产路径，或 release-assets.githubusercontent.com 的 /github-production-release-asset/ 路径。非默认端口、URL 凭据、片段或其他主机/路径拒绝；CDN 查询只用于其签名链接，不显示或记录到下载元数据。此名单是当前实现边界，尚未用本项目公开资产跑通真实 CDN 下载，不保证将来 GitHub 不改变来源。

下载连接预算 10 秒、单次读取 30 秒、网络传输总预算 30 分钟；只接受 HTTP 200 完整响应，不续传，拒绝 206。声明大小存在时必须与清单一致，实际分块不得超过预期；中断、超量、大小/摘要不符或写入失败都不发布为已下载文件。GitHub/CDN 和所用代理可见 IP、请求与 MooMole 版本 User-Agent，不附带本地任务、路径或诊断；不发送应用账号或 cookie。

系统应用缓存目录下使用专属 `pending-updates`，例如 `~/Library/Caches/io.github.rememberber.moomole/pending-updates`。目录要求当前用户所有且 POSIX 权限私有，创建为 0700，文件为 0600；目标目录拒绝符号链接。缓存目录持有文件描述符，临时创建、发布和清理通过 openat/linkat/unlinkat 定位，不跟随临时文件链接。发布前及展示前复核目录设备/inode 未变化。

下载使用随机 UUID 的 `.download` 临时文件、排他创建；校验和 sync 后，通过同目录不可覆盖的链接发布，再删除临时名字。最终文件名保留版本/架构并带随机后缀，避免覆盖既有下载。新下载预留额外 16 MiB，最多允许 32 个目录条目、预计缓存总字节不超过 2 GiB，单包继续限制 1 GiB；达到限制提供发布页兜底。只计直接子项，不递归，不删除无法归属的文件。

正常取消与错误路径清理自身临时文件，Drop 提供尽力清理；强杀、系统崩溃或异常内核 I/O 可能留下临时文件。正常退出请求取消下载，与现有 Mole 任务共享最长 6 秒退出等待；这不是对挂起系统调用的强制终止保证。App 重启不自动联网或信任缓存；用户手动检查后，可重新校验并复用与本次清单匹配的完整包。未完成下载不续传，仍需重新下载。已下载资格保存在当前进程，完成文件留在缓存内；重新检查清空旧选择，再按新清单复核，不删除旧文件。可选自动下载偏好见上文。

### 重启后复用完整包

启动和进入设置仅读取本机会话，不自动联网或扫描出一个可安装结论。用户点击“检查更新”，成功获取并校验固定清单、选出当前通道/主机架构的新版资产后，才在专属缓存查找精确同名版本/架构的完整包；不读取本地旧清单或额外恢复元数据，不按文件名认定可安装。当前版本无需更新、未发布、缺架构资产或检查失败时均不恢复旧包。

- 仅查规范 UUID 后缀的完整 DMG，保留期内、当前用户所有、0600、普通文件和单一硬链接；忽略临时文件，不续传。重新读取大小、SHA-512 和已有公开系统隔离属性，目录及名字身份再验通过才恢复就绪；不重写隔离属性、修改时间或内容，也不新增 SQLite 表/元数据文件。
- 最多扫描 512 个直接条目、4 个精确匹配名字，以选中包大小累计预留最多 2 GiB 的复核预算，并在操作/读取块之间检查 30 秒单调期限及取消。优先复核最近文件，损坏副本不删除，可在预算内继续找到另一份有效副本；目录/链接/权限/未来时间/文件变化或预算不足均不当作已下载。
- 界面显示“正在复核本地更新包”，没有虚假的网络下载进度；成功显示“已找到并校验本地更新包”，直接使用现有安装/Finder 入口。没有匹配文件时正常提供下载；无法复用时保留新版信息，说明可重新下载，不把本地失败描述为没有新版。
- 检查与复核由后端独立管理，关闭设置不停止或重复请求；复核期间禁止重复下载/安装，并阻止周期维护。正常退出请求停止复核，并纳入现有退出等待；系统挂起的 I/O 不受用户态期限强制中断。恢复后当前包继续受自动维护保护，Finder/安装前仍须再次复核。

### 自动维护更新缓存

参考 MooTool Electron 的保留策略，由 Rust 在取得本机数据库占用权后异步维护，启动一次、之后每 6 小时尝试；下载创建临时文件前也尝试清理。没有额外联网或界面操作，维护失败不会阻断启动。缺失目录不创建，错误只记录固定提示，不打印用户路径；操作系统挂起的 I/O 不受用户态 2 秒预算强制中断。

- 以文件修改时间计算：完整 DMG 满 7 天、中断的 `.download` 满 24 小时才纳入；未来时间和不可读取时间跳过。重启后需手动检查并重新复核才恢复资格，超过保留期不参与复用。
- 只接受 `.moomole-{规范小写 UUID v4}.download` 和 `MooMole-{严格 SemVer}-mac-{arm64|x64}-{规范小写 UUID v4}.dmg`；普通文件还须当前用户所有、0600 且只有一个硬链接。不递归目录，不跟随链接，不处理用户下载目录或其他文件。
- 一轮最多扫描 512 个直接条目、删除 64 个文件，并在操作之间检查 2 秒单调时间预算。扫描未完成、超出条目上限或发现目录替换时不开始删除；删除阶段被打断时保留已完成结果，其余留待后续尝试。
- 清理与检查、下载启动、Finder 复核串行；有活动下载时定时维护跳过。当前进程的待安装包始终排除，不因超过 7 天而删除；下载前维护时还没有本次临时文件。退出会停止继续清理，并把活动维护纳入退出等待。
- 删除前重新打开并比对 inode、设备、大小、mtime/ctime、权限及单一链接，最后用不跟随链接的 fstatat 复核名字，再对持有的目录 fd 使用 unlinkat；目录移动/替换、候选变化或无法确认时保留。

工作区及系统提供的应用缓存父目录假定属于受控用户环境。上述身份、摘要和 POSIX 检查不是文件系统事务或针对同用户恶意并发进程的持续锁定，也不是完整 ACL 或所有卷行为的保证；仅为被检查时的证据。无法写入、空间满、只读卷、挂起 I/O 和最低系统仍需进一步真实故障验证。

## macOS 下载隔离

普通 Rust 网络写入不会自动得到浏览器的隔离处理。本实现通过公开的 CFURLQuarantinePropertiesKey / LaunchServices 属性为新文件设置下载类型、MooMole agent、原始公开资产地址及固定发布页，系统补充时间等信息；保存后和 Finder 展示前再读取该属性。没有硬编码/删除私有 quarantine xattr 格式，也不清除系统已有安全标记。设置或读取失败就停止进入已下载状态；不回退为无隔离文件。

CoreFoundation 字典使用标准 CFType 回调维持对象所有权，由 Rust 调用系统框架，不引入额外进程/helper、Electron 或付费证书。设置隔离不代表 Apple 公证、发布者认证或 Gatekeeper 已验收；实际下载、用户系统确认、映像内 App 的隔离传播及权限迁移仍需在干净系统测试。

依据：[Apple DTS 的隔离与公开 API 说明](https://developer.apple.com/forums/thread/706442)、本机 SDK 的 LSQuarantine.h、[GitHub Release 资产](https://docs.github.com/en/rest/releases/assets)。本地传输测试确认当前 macOS 的属性写入和读取，不代表 macOS 14/Intel 已通过。
