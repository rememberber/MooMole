# 日常功能的原生窗口验收

2026-10-30：窗口可操作后，横向补验个人文件、影音预览、归档、恢复和搜索维护的首条实际 App 流程。所有点击、文本输入、系统目录选择器和 Finder 操作使用原生界面工具；没有用浏览器 mock、测试执行器或命令行调用代替 App 的确认与执行。

## 环境与证据

- 基于 `c5afa3a`，另含本节点的确认有效期与首次使用说明修正；arm64 优化构建、正式内置 Mole 1.65.0、生产 CSP 与执行器。临时构建配置只修改产品名称与标识，使用独立的 `io.github.rememberber.moomole.consumervalidation` 数据目录，不迁移或替换现有安装。
- 主程序与两份嵌套引擎均完成最终 ad-hoc 签名、架构及资源核验。初始样本为 `local-artifacts/consumer-native-xxhnhf/`，修正后的样本为 `local-artifacts/consumer-native-fixed-yfRamI/`；均未公证、安装或发布。
- 在账户下唯一自建目录中创建三份文本、一份自生成三秒 H.264 MP4，以及独立搜索目录中的一份文本。处理前保存 SHA-256 与设备/inode；处理后核对全部五份文件内容与身份。只对明确选中的自建文件操作，未扫描用户下载目录。
- 私有记录位于 `.cache/consumer-ui-evidence.json`，包含确切样例目录、SQLite 计划/逐项收据、任务记录及文件检查结果，未随源码分发。构建与测试日志同在忽略目录 `.cache/`。

## 已实际走通

| 主流程 | 原生窗口结果 | 独立核对与边界 |
| --- | --- | --- |
| 本地视频预览 | 文件整理扫描 → 预览 → 加载三秒时长 → 手动播放 → 可见视频画面与进度 → 停止后定位 → 返回列表 | 使用真实 `moomole-media://` 协议和 WKWebView；默认不播放，返回后仍为零选择。只证明本样例，未覆盖全部格式、大视频及生命周期。 |
| 同卷移动与批量恢复 | 明确选择两份文本 → 完整路径确认 → 两项真实移动 → 历史中勾选两项 → 独立确认 → 两项移回原位置 | 全部内容与设备/inode 保持，目标目录为空；原处理记录保留，恢复另有同一批次的两项收据。这里的恢复源是普通目录，不是废纸篓。 |
| ZIP 归档 | 选择两份原件 → 填写自建目标 → 检查 → 单独勾选确认 → 真实创建，显示 2 / 2 项生成并校验 | 系统 `ditto` 独立解压，恰好两份所选文本且内容一致，原件与未选文件保持。首次发现的确认期错误已修正、重建并从头验证本链路。 |
| 个人文件废纸篓处理 | 清空旧选择 → 单独选择一份文本 → 独立确认 → 真实移入 → 历史显示 1 moved / 0 unknown | 保存真实废纸篓位置。当前权限下应用内恢复准备被拒绝，没有发出恢复执行；在 Finder 仅定位该收据文件并用“放回原处”取回，内容与身份一致。**Finder 取回不能算作应用内恢复成功。** |
| 搜索维护 | 问题入口 → 系统目录选择器 → 自建 Search 目录 → 审阅影响 → 确认 → 真实提交 Spotlight 索引 | App 显示索引命令完成，历史保留目录与任务；原文件保持。没有声称文件已能被搜索到，也没有清空整卷索引或修改隐私排除。 |

中途正常退出独立 App，再用修正后的同标识独立包重开；此前移动、批量恢复和索引任务仍在历史中，没有重放。其余模块、菜单栏、定期任务整周期、睡眠唤醒、真实卸载、取消/中断矩阵与正式安装/升级身份继续分别验收，不以本节点替代首发全部门槛。

## 本节点修正与自动化

1. 实际归档窗口复现：派生计划把十五分钟扫描有效期作为确认期返回，前端按三十秒合同拒绝，未执行修改。同样的问题存在于跨卷移动派生确认。现统一使用原计划创建时间加三十秒、受扫描截止时间约束的有效期；准备耗时计入，不在发布时重新获得三十秒。服务端消费同时检查单调截止与墙钟范围，过期/回退拒绝并消费，不改变执行中已开始任务的工作预算或历史格式。
2. 批量恢复异步准备完成后，旧定时 tick 曾短暂早于计划创建时间，误报过期。改用当前渲染时钟判断，保留定时刷新；浏览器新增“新返回确认立即可用”回归，不再以提前一秒的 fixture 掩盖此差异。
3. 首次使用说明删除已失实的“暂无应用内恢复”，改为说明可靠记录的适用范围与其他取回/重建边界，中英日同步。
