# 日常功能的原生窗口验收

## 2026-11-18 个人文件废纸篓、操作历史与恢复

基于 `82041be` 及本次界面修正，在 Apple Silicon 上先后运行同一验收标识的原版与修正版 arm64 优化 App。外层与两份 Mole 1.65.0 内嵌程序均通过 ad-hoc 签名验证。测试目录在项目的受控构建目录，使用两份自建文本文件和独立 SQLite 数据。

- **移入和恢复。** 文件整理扫描仅包含两份样例。第一轮只选择一份，核对确认、真实废纸篓收据、所选和已移入的大小、磁盘变化缺少可比较观察的提示。未选文件内容和身份保持。由「查看处理历史」进入「最近操作」，启用「只看可申请恢复的文件」，从逐项结果核对当前及原始路径后单独确认。文件真实移回，检查原处理记录和新增恢复记录。
- **保护和重试。** 自建同名目标使恢复确认禁用，目标内容和身份保持，SQLite 中没有新增执行批次。撤下冲突后重新确认并恢复。再次请求已取回的收据时，App 拒绝确认。批量复验中，首项文件的属性变更时间在确认后发生变化，App 将该项记录为跳过并完成另一项。重新检查后单独恢复被保留的文件。两份稳定样例的下一次批量恢复显示 2 / 2 项完成。
- **修正并复验。** 旧界面要求手动刷新才能看到刚写入的恢复记录，确认说明也只指向 Finder。修正后，单项、部分完成和全部完成的批量结果立即进入列表，中英日确认说明指向操作历史中的合格恢复项。正常退出并重开后，界面仍显示七批记录，SQLite 三张执行表摘要一致，两个文件的设备、inode 和 SHA-256 均与初始值吻合，核对过的废纸篓位置为空。
- **验收范围。** 个人文件移入废纸篓与应用内恢复完成实机验证。概览的完整 Mole 清理验证到永久删除范围、未勾选时禁用执行和空历史。系统缓存的授权执行、正式安装身份和跨盘恢复的窗口验收另有待办。

前端 285 项单元测试、41 项相关 WebKit 回归通过。Rust 默认回归 755 通过、117 显式忽略，另单独运行并通过真实废纸篓恢复和四类软件文件恢复测试。生产构建、三语目录和改动文件格式检查通过。独立构建与样例均已回收，精简结果进入 `.cache/verification/native-evidence.json`。

## 本节点修正与自动化

1. 实际归档窗口复现：派生计划把十五分钟扫描有效期作为确认期返回，前端按三十秒合同拒绝，未执行修改。同样的问题存在于跨卷移动派生确认。现统一使用原计划创建时间加三十秒、受扫描截止时间约束的有效期；准备耗时计入，不在发布时重新获得三十秒。服务端消费同时检查单调截止与墙钟范围，过期/回退拒绝并消费，不改变执行中已开始任务的工作预算或历史格式。
2. 批量恢复异步准备完成后，旧定时 tick 曾短暂早于计划创建时间，误报过期。改用当前渲染时钟判断，保留定时刷新；浏览器新增“新返回确认立即可用”回归，不再以提前一秒的 fixture 掩盖此差异。
3. 首次使用说明删除已失实的“暂无应用内恢复”，改为说明可靠记录的适用范围与其他取回/重建边界，中英日同步。
