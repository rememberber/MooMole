# 应用更新包的校验下载

2026-11-03：应用声明来源的更新发现增加“下载并校验更新包…”：用户检查来源后选择确切版本，再选择保存目录，下载完成后显示文件位置和 SHA-256。只保存交付物，不自动打开、挂载、解压或安装。展开 ZIP 或打开 DMG 后，可以继续已有的“使用已下载应用包…”流程，另行核对实际版本、完整签名、发布者连续性、保护、运行状态和替换范围。

首条路线要求已安装副本声明有效的 `SUPublicEDKey`，当前 appcast 完整包提供可解析的 `sparkle:edSignature` 和已知正数长度，大小不超过 256 MiB，地址为 ZIP 或 DMG。密钥来自原副本的有界 plist 读取，原副本身份继续绑定 Info.plist 与主程序；不接受前端传入密钥、签名或下载 URL。请求仅携带当前来源、候选、请求 ID、明确确认及所选保存目录。应用声明了 `SURequireSignedFeed` 的情况保留给原更新器，本轮没有实现签名源协议或密钥轮换；该键即使值为 false 或无法解释也保守不提供下载入口。

使用严格 Ed25519 验证原始完整包字节，不把摘要签名或 DSA 当作该协议。拒绝弱公钥、无效编码/长度、包字节或大小不符；相同构建/地址的签名或大小声明冲突也撤下应用内下载资格。密钥匹配只说明下载包对应此已安装副本声明的公钥，不等于 Apple 发布者认证、公证、包内容可安装或来源版本声明已签名。协议依据 [Sparkle 的发布与公钥说明](https://sparkle-project.org/documentation/) 和 [appcast 包签名字段](https://sparkle-project.org/documentation/publishing/)；严格验签使用 [ed25519-dalek](https://docs.rs/ed25519-dalek/2.2.0/ed25519_dalek/struct.VerifyingKey.html#method.verify_strict)。

网络沿用来源检查的公开 HTTPS/标准端口、无账户信息、公网解析结果限制、固定连接地址、系统 TLS 校验和禁用代理。包下载最多跟随四次重定向，每跳独立校验地址和全部解析结果，不把原域名的核对沿用到新域名；不发送 Cookie 或本机文件内容。拒绝非 200 的最终响应、内容编码和声明大小不符，流式计数也不得超过期望长度。连接五秒、每跳请求九十秒，整体等待最多四分钟，来源本身仍受五分钟有效期约束；系统 DNS 或文件操作等待不提前释放实际 worker、安装互斥及请求登记。停止检查会中止后续下载和保存，已开始的系统调用可能稍后返回。

网络暂存采用系统自动回收文件。验签成功后，在明确选择的普通、本账户物理目录内，用持有的目录描述符创建唯一 0600 隐藏文件，复制并保留系统下载隔离属性，再次按文件描述符读回核验完整签名、大小与 SHA-256。发布前重读当前来源/原清单/设置，核对目录父链和暂存文件身份，使用 `RENAME_EXCL` 不覆盖发布为唯一 `MooMole-update-<ID>.zip/dmg`，同步并核对最终身份及隔离属性。原路径、保护和未知位置限制没有放宽；下载源和隔离来源分别记录实际包地址与 appcast 地址。

未发布的失败/取消文件按本次确切身份清理；不按前缀扫描用户目录。成功保存的包是用户明确选择的交付物，故保留在所选目录。发布后故障不删除文件、不自动重复下载，错误说明实际位置供核对；外层等待超时同样提示先核对保存目录。新下载不创建永久缓存、随机验收目录或安装记录，也不改写已安装应用和用户数据。应用安装仍使用既有持久意图和独立确认。

已验证：RFC 8032 独立公开向量与篡改/弱密钥拒绝；自建签名 ZIP 的实际文件保存、0600、系统隔离属性、原暂存/未选文件保持，取消、保护变化、来源撤回和目录替换后的部分文件清理；已安装自建 App 声明密钥的身份绑定及签名源策略拒绝。另显式通过真实公开 Rectangle appcast 下载一份 4,960,820 字节 DMG，以其[上游 Info.plist 的公开密钥](https://github.com/rxhanson/Rectangle/blob/main/Rectangle/Info.plist)验证完整包，实际保存并读回隔离属性；没有挂载、安装或启动该包。此样例证明网络与交付核心，不授予对已安装 Rectangle 的操作权限。全部样例在系统 TempDir，退出后检查目录已消失。
