# 普通 App 的独立卸载计划基础

2026-10-23：已实现后端只读计划、完整 App 包身份快照与重新核对；尚无前端入口、执行确认或实际卸载器。返回值固定为 `readOnly=true`、`canExecute=false`、`state=requiresExecutionReview`。这不是首发卸载功能的交付，验收门槛见 [首发执行验收](first-release-execution.md)。

## 来源与首批范围

计划只能从后端保留的成功 Mole 应用清单，通过任务 ID 和条目索引生成；不接收前端提供的路径、包身份或可执行结论。原清单过期、被撤下或条目变化，检查失败，不从显示文本重建许可。

当前仅准备 `/Applications` 或实际用户 `Applications` 的直接子 App，清单来源必须为 `App`。Homebrew、未知来源、其他位置、客户端自身/同标识、系统或用户保护范围、固定 Mole 要求保留/官方卸载器/保护未知的对象不生成计划。后台专用或后台标记未知的包也不生成计划。`App` 来源不证明没有其他管理方式，未命中这些保护子集不等于完整卸载资格。

范围固定为 `appBundleOnly`；包外缓存、设置、文档及其他关联位置全部 `retainAll`，不扫描或修改关联数据，不声称清除残留或可释放多少空间。

## 包身份与内容清单

- 使用无跟随链接的目录句柄绑定祖先、App 根、`Contents`、`Info.plist` 和主程序；要求本地已落地布局。读取最多 1 MiB 的实际 plist，绑定其 SHA-256、精确 Bundle ID、`APPL` 类型、版本/构建号、后台标记及单个主程序文件名。主程序必须为同设备、单硬链接、带执行权限的普通文件，不读取或执行主程序。
- 独立 `BundleWitness` 按排序后的名称、元数据和子目录记录整个 App 包。预算为 10,000 个检查点、64 层及约 5 秒；超限、变化、特殊文件、普通文件硬链接、跨设备或云占位状态均拒绝。时间预算在检查点核对，不承诺中断任意阻塞系统调用。
- 包内框架链接按 `readlinkat` 的字面值记录（最多 4096 字节），不跟随；外部或失效链接也不读取目标。链接内容或包内对象变化会使快照不同。此策略使用独立类型和摘要域，原清理目录的严格禁止链接规则不变，不能互换执行资格。
- 根目录身份在完整快照中单独绑定；清单摘要不纳入根目录自身的时间戳，仍检查其前后是否变化，子项身份/时间继续纳入。隔离目录改名后清单相同而根快照不同，只证明清单边界，不证明废纸篓收据或恢复通过。

这是元数据与身份文件证据，不是代码签名、发布者认证、文件锁或运行状态证明；不能消除检查与未来操作之间的竞争窗口。

## 生命周期与接口

三个后端 IPC 分别为 `prepare_application_uninstall_plan(taskId,index)`、`recheck_application_uninstall_plan(planId)`、`discard_application_uninstall_plan(planId)`。返回必要的应用/范围/时间/摘要说明，不返回原始 inode、plist 正文或系统句柄。

计划在当前 App 内存中最多保留 8 份、有效期 5 分钟；重新核对不延长原期限。核对实际账户/主目录、固定 Mole 版本、最新保护设置、原清单和完整包快照。检查开始撤下同路径旧计划；按后端代次发布，旧检查的迟到结果/错误不能替代新计划。撤下正在复核的计划后，其完成结果也不能恢复该计划；重启不恢复任何许可。只读计划接口不写入执行表，后续独立记录层的 v4 迁移见 [卸载记录](app-uninstall-journal.md)。

只读 worker 共用两个应用检查名额和更新安装租约。IPC 超时或界面消失不丢弃正在结束的检查及租约；退出后不再发布计划。检查失败保留原因，不返回可执行状态，不触发授权窗口。

## 证据与接下来的执行关口

9 项新增普通 Rust 测试覆盖来源绑定、保护撤回、包内变化、链接/硬链接/特殊文件拒绝、主程序/plist 布局、后台/官方卸载器保留、有效期/数量/重启和检查代次。另显式运行只读实测：本机 `/Applications/MooTool Next Electron.app`，版本 1.3.5，连续两次快照一致，记录 613 项（0.06 秒）。没有启动或移动该应用、读取包外关联数据，也没有由此判断它未运行或允许卸载。

后续已实现 [完整 App 包原生处理核心](app-uninstall-target.md) 与 [独立持久记录](app-uninstall-journal.md)，自建包的原生处理及临时库的事务/重启测试分别通过；仍未接生产执行调用方。下一步贯通一次确认、实际运行/辅助进程/后台服务、管理方式和权限复核、任务排他与更新/退出协调、实际操作/结果串联及历史界面。已有只读主应用观察和后台标记不能替代这些条件；普通日志文件执行器不能直接处理目录包。最终需在实际打包 App 上完成支持范围内的真实卸载、保护/失败/取消、收据和恢复边界验收，才能勾选发布关口。
