# 系统维护：项目说明与执行边界

2026-10-21。当前提供固定 Mole 版本的维护项目说明，以及两项设置、项目级保护、固定偏好文件保护与访问条件的只读观察；尚未连接修改计划或执行。这里的“预览”是作用与影响预览，不是待执行对象列表，也不表示本机需要维护。

## 当前可查看内容

- 侧栏“系统维护”可浏览 Mole 1.59.1 的全部 19 项目录，顶部搜索名称、用途、影响、权限或原始 action ID。
- 默认仅显示项目名称、用途与操作性质；展开后查看范围、执行前条件、权限、可能影响、恢复限制。技术来源按需展开，不重复页面标题和装饰性路径。
- 无论是否能使用引擎，都不报告本机健康结论。引擎不可用或版本/提交不匹配时，额外注明仅为固定版本功能参考。
- 文件系统验证保留上游默认禁用；启动代理、登录项检查说明其只报告问题。删除旧记录、重置设置与刷新服务分别标明，不能笼统称为无风险优化。
- 顶部“检查本机设置”仅按需读取 Finder 两项记录设置和四项 App Nap/映像验证覆盖设置。逐键展示启用、未启用或未知；管理策略标记及维护任务跳过规则单独展示。其余 17 项继续明确未检查，不因这两项完成而推断可执行。
- 检查结果只代表所标时间；重试失败保留旧结果并注明本次未更新。离开页面不接收迟到结果、不自动重新检查。界面不提供中止系统读取的承诺或修改按钮。
- 已检查的两项可勾选并点击“审阅所选”，逐键查看固定维护意图、无需变更或保留原因。原生观察绑定且自检查起 60 秒有效，刷新即作废旧审阅资格；不持久保存、不产生执行任务，详见 [审阅协议](maintenance-review.md)。

## 两项只读检查的语义

`prevent_network_dsstore` 对应 `DSDontWriteNetworkStores`、`DSDontWriteUSBStores`；`legacy_overrides_audit` 对应全局 `NSAppSleepDisabled` 及 DiskImages 的 `skip-verify`、`skip-verify-locked`、`skip-verify-remote`。Rust 使用 CFPreferences 读取有效值及 forced 标记，不调用 defaults 命令、不解析终端文案、不调用 synchronize/set/delete，不枚举整个偏好域或返回无关值。

仅布尔值、0/1 整数和明确支持的有限字符串可转换；缺失和读取不可用无法通过该 API 可靠区分，因此 NULL 一律未知。浮点、异常字符串、嵌入 NUL 等也未知。系统策略管理的设置应保持现状；部分覆盖值已启用而其他值未知时，保留已经观察到的启用证据。即使两个 Finder 键都启用，“无须重复设置”也只针对这两个键，不能视为整机正常或取得维护许可。

维护规则只读适配 `load_whitelist optimize` 的来源优先级：先读 `~/.config/mole/whitelist_optimize`，物理缺失时才读 `whitelist_checks`，两者均缺失才使用固定版本的空默认列表；新文件为空不回退旧文件。两项 action ID 只作精确命中，glob 不用于任务名匹配。**不调用上游 load_whitelist**，因为其旧文件兼容分支会自动保存新文件。清理白名单不替代维护规则。

规则文件限制 64 KiB / 256 条非注释规则，要求完整 UTF-8、无 NUL 且最后一行有换行；无末尾换行虽然上游可能忽略该行，本客户端保守标为未知。通过描述符绑定验证目录链、文件身份、内容时间与本地物化状态；链接、硬链接、非普通文件、非本地/未物化路径、权限异常或变化均未知，不创建目录或迁移配置。读取相对于已持有的父目录打开，只读文件描述符在读取前后核对。

单 worker、单并发；原生 IPC 5 秒等待，内部约 4 秒后不再开始下一个键的检查，单键内的有限次读取仍可能在运行，前端 7 秒等待。系统调用本身不能保证强制中断，超时后实际 worker 继续持有并发槽和安装操作租约，直到真实返回；不因为界面超时就重复启动 worker 或宣称取消成功。无轮询、无自动重试、无数据库保存或维护任务历史记录。前端核对协议、源码基线、两项目/六键完整性、时间及保护/状态一致性；过期响应或迟到观察不替换当前结果。

## 明确偏好域的原值读取证据

六个固定键分别读取当前用户 AnyHost 与 CurrentHost 的明确域，比较两次原始类型和值。只向界面返回域、证据状态与受限类型摘要；原始内容不保存、不外传。未返回值不证明缺失，类型异常和已观察变化分别保留，变化不能被已知有效值掩盖。项目观察与审阅中按需展开，详见 [原值证据](maintenance-originals.md)。

这不建立完整可恢复原值，也不保证缓存刷新或无并发变化。维护执行、持久恢复和冲突解决继续关闭。

## 固定文件保护与访问观察

观察仅覆盖 `~/Library/Preferences/` 下的 `com.apple.desktopservices.plist`、`.GlobalPreferences.plist`、`com.apple.frameworks.diskimages.plist`，不读取文件内容，不扫描其他用户/主机域或备份整个偏好目录。展开“文件保护与访问观察”可见每个固定文件的存在状态、客户端保护、Mole 路径规则及有限文件访问结果。

- 客户端保护目录按路径组件双向包含判断，与已有保护语义一致；设置不合法时未知。检查期间保护目录改变，整份响应拒绝并要求重新检查。
- Mole 路径规则按固定版本 `is_path_whitelisted` 的规范化、直接命中、保护祖先/后代逻辑及 `*`/`?` 子集观察，C locale 按字节匹配，`*` 可跨目录并匹配点文件。规则中的 `~` 或 `$HOME` 不自行扩展，因为该上游函数未作这种扩展。方括号、反斜线或扩展模式不擅自解释，无已知命中时未知；单模式最多 512 字节、目标最多 4096 字节，整批匹配计算上限一百万单位，超额未知。已知命中优先保留。原始谓词的支持子集已用隔离字符串输入对照；不执行优化或白名单加载生命周期。
- 路径白名单来自维护配置。上游旧覆盖修复会检查对应 plist；Finder 设置处理函数本身未检查这些路径规则，本客户端将它们作为额外保守保留观察，不声称上游已提供同样保护。未覆盖其他模块的全部核心规则。
- 描述符绑定路径链、拒绝链接/特殊文件/共享硬链接、要求本地物化路径。缺失只在立即父目录可验证且再次查名仍缺失时报告，不创建文件测试可写性。普通文件观察当前有效账户的文件读写、父目录写入/搜索、所有者、只读卷、不可更改/只追加标记及 ACL；ACL 存在或无法可靠解释时仍未知。前后重查元数据/ACL/卷与路径身份，不声明原子快照。
- `noRestrictionObserved` 仅说明本次有限检查没有发现文件访问限制。CFPreferences/cfprefsd 写入、缓存刷新、TCC、其他主机域、实际改写与回滚另需验证；缺失文件不推断可创建，受限时不自动提权或改权限。未保存原始键值，当前没有精确撤销能力。有效布尔值无法代替原始域、类型、缺失状态、执行前值和写后状态等恢复证据。

协议升级为 v4，包含原生观察 ID 和明确偏好域证据摘要，要求固定三文件记录完整，拒绝旧协议、漏项、未知位置，以及缺失路径却返回“未发现限制”等矛盾结果。任一保护命中优先保留；文件访问受限单独展示，其余缺失/未知不能被已知设置值掩盖。不新增写入或恢复入口。

## 来源与更新约束

`src/lib/maintenance-catalog.json` 是中文解释元数据，固定 `1.59.1` / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f`。19 个 action 与 handler 按 `lib/optimize/catalog.sh` 的注册顺序逐项对应；说明审阅了 `tasks.sh` 与 `maintenance.sh`，并区分上游条件与客户端未来需补齐的保护。

引擎准备脚本在源码归档解包后、编译和资源安装前，检查版本、固定提交基线、catalog/tasks/maintenance/whitelist/base/app_protection 六个文件的 SHA-256，以及完整 action/handler 对应。变动会失败并要求重新审阅。此检查只读文件，不 source Shell，不启动 optimize 或 dry-run，不索取授权。可单独运行：

```sh
npm run test:maintenance
node scripts/maintenance-catalog.mjs .cache/mole-source
```

浏览说明、展开和搜索不会触发 CLI；仅用户明确点击检查才调用无参数 `inspect_maintenance`，后端固定范围、要求首次说明已确认并复核引擎完整性/版本，拒绝退出或安装交接中的请求。已有 App 启动时的系统快照属于原有状态流程，不能作为维护适用性证据。

## 后续开发顺序

原值与恢复的测试专用隔离实验已完成，见 [实验范围与实际边界](maintenance-preference-lab.md)。18 组类型/缺失往返、继承分离和条件恢复已验证，同时复现等价整数/布尔的类型保留问题及最后复查后的非原子写入窗口。App 仍未连接原值保存、修改或恢复功能。

1. 将原始域/类型/缺失状态、持久记录、变更与冲突边界整理为受限计划协议；明确域只读证据已接入，但真实域缺失证明和持久记录仍待解决，不能依赖实验标记或用有效布尔值冒充可恢复原值。保留最后复查竞争用例，不通过反复重查宣称原子安全。
2. 继续适配实际写入条件、其他主机域及其他任务有效规则，不能用清理白名单或客户端保护列表代替。DNS 还需考虑上游旧 `system_maintenance` 规则兼容，本轮不判断 DNS。
3. 为具体项目定义选择范围、证据时效、执行前身份与活动占用复核、按项结果及取消边界；未知不放行。
4. 修改设置需记录原值，删除数据需备份和恢复设计；数据库需处理 WAL/SHM 及服务活动；重建索引启动后系统仍可能继续工作。
5. 免费分发下逐项验证授权路线，不依赖付费 Developer ID 常驻 helper，不关闭 Gatekeeper 或删除文件安全属性。

当前不提供“一键优化”，也不把 `optimize --dry-run` 的文案当作结构化执行计划。上游对目录的自动执行标记不是本机可安全执行的证据。未作任何维护修改、权限请求或性能改善承诺。
