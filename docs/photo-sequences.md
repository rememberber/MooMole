# 连续拍摄候选

2026-10-31：在普通目录相似照片扫描中加入独立的连续拍摄模式。根据照片自身的原始拍摄时间、相机线索与本机视觉特征寻找候选，不读取照片图库，不按文件名或修改时间猜测，不声称已经确认相机的连拍标识，也不自动挑选最佳帧。

读取与完整内容核对使用同一份有界、身份已验证的图片字节。ImageIO 提供 [EXIF 原始时间](https://developer.apple.com/documentation/imageio/kcgimagepropertyexifdatetimeoriginal)、小数秒和时区偏移；相机制造商、型号及存在时的机身序列号仅在内存用于分组，不写入公开报告或执行历史。日期、时间、小数秒、偏移和字符串有严格边界；缺失/异常的必需线索计数显示，不降级为文件时间或将未知时区当成本地时区。

候选须处于同一物理扫描目录中的同一父目录、相同拍摄日期/相机线索/时区信息，每张距本组最早一张不超过两秒，且 Vision 第二版特征距同一参考照片不超过既有 0.15。使用原始小数秒精度比较，不通过时间或视觉的传递链无限合并；公开组跨度以毫秒向上取整。相同型号不证明来自同一实体相机，元数据可能错误，因此始终是人工比较候选。

沿用相似照片的确切扫描 ID、默认零选择、每组保留一张、单独确认、内容摘要、保护复查、真实废纸篓、取消、持久意图、未知与重开不重放，以及共享恢复/归档。选择与保留照片各自完整内容发生变化时拒绝处理；不会因为拍摄时间相近就自动删除。

后端节点已用系统 ImageIO 生成自建 JPEG，实际读取 EXIF 与 Vision 分组，验证不同场景/相机/父目录、超出参考时间窗与无元数据的排除，以及全选拒绝和保留帧变化保护。显式原生样例通过正式 Mole 规则与真实废纸篓处理一张，其他帧和未选内容保留，核对实际收据后取回自建样例，SQLite 重开与归档读回一致；证据 `.cache/photo-sequences-native.json`。该取回是验收清理，不算新的产品恢复证据。

界面模式切换、时间顺序和单独确认在下一节点接入。真实打包 App 窗口、更多相机导出、跨午夜/缺失时间的候选、权威连拍标识、照片图库、RAW 和 Live Photos 仍在完整目标内；不把本流程等同于这些格式或来源已经全部支持。
