## 用户流程与支持范围

系统维护工具栏“刷新预览…”只针对 [Quick Look 两步服务刷新](maintenance-quicklook.md)：缩略图缓存和生成器列表，可选择其中一步或两步。说明影响后点击检查，不会执行；检查通过后还需明确勾选了解预览影响、缓存重建和无法撤销的边界，再点击开始。目录说明仍覆盖完整 Mole 19 项；完整 `cache_refresh` 的目录删除和其他维护写入不因此开放。

首批支持普通账户、可核对的 Apple 系统工具与固定 Mole 引擎、可完整读取的维护配置。命中 `cache_refresh` 跳过规则则保留；其他已知维护任务 ID 不干扰本项。服务级刷新无法逐目录排除，客户端目录保护非空，或维护配置含路径/无法映射的条目时，保留此任务并说明原因。这个额外保守条件不等于 Mole 原 handler 自带相同保护，也不声明已枚举 Quick Look 服务的所有文件操作；不自动改保护、不把未知当作未命中。

确认绑定固定两步选择、计划/确认 UUID、引擎提交、原始维护规则、客户端保护/首次说明/账户上下文和物理系统工具身份。原始墙钟与单调时钟共同限制 30 秒，不因重查或慢 I/O 续期。确认只能取用一次，关闭未提交窗口会撤销；迟到准备结果不会重开窗口或自动执行。历史和前端 JSON 不能恢复授权。

开始后逐项结果持续保存。关闭结果窗口只停止查看，后台继续收集；取消只停止后续步骤并请求停止本任务拥有的命令组，已经发生的刷新不撤销。正常零退出显示系统命令已完成，不把它写成预览已修复或性能提升。缓存由系统重建，没有原缓存备份或统一回滚；对启动后的非零/停止/收集异常保留未知，不自动重复调用。

## 封闭后端

| IPC | 边界 |
| --- | --- |
| `prepare_quicklook_refresh(selected)` | 仅一个或两个固定枚举；只读检查并返回短期确认。独立检查槽和更新租约持有到真实 worker 结束，超时不放弃仍在进行的读取 |
| `discard_quicklook_refresh(confirmationId)` | 撤销未取用确认；不影响已提交 worker |
| `execute_quicklook_refresh(planId, confirmationId, requestId, rebuildConfirmed)` | 只接标识及明确影响确认，不接程序/路径/参数/前端资格；原请求 UUID 即持久会话标识 |
| `get_quicklook_refresh(requestId)` / `list_quicklook_refreshes()` | 结构化记录与最多 64 份摘要，只读、不重放；没有句柄/记录时明确返回空观察 |
| `cancel_quicklook_refresh(requestId)` | 仅取消相同请求的 MaintenanceRefresh 任务，迟到取消不跨任务 |
| `acknowledge_quicklook_refresh(requestId, snapshotSha256, reviewed)` | 原 worker 已结束、原记录/摘要一致且用户明确核查后，单独记下核查，不改步骤结果或触发系统命令 |

MaintenanceRefresh 纳入日志清理、App 卸载和权限探针的双向排他，通用任务入口拒绝启动。专属 worker 持有任务、数据库目录占用和更新操作租约至结果收集/故障整理结束；RPC 观察者消失不丢失所有权。退出通过现有取消/限时整理流程，超时退出仍留下意图，不能将其称为操作已完成。

Quick Look 子进程已登记到共用退出控制器使用的同一 Job，超时最后强停可以触达，最后信号和注销先于回收。登记冲突只停止本次新建子进程，保留实际刷新未知；不停止另一个已登记进程。该修正已有受控进程回归；阶段 157 补齐实际 App 命令启动后 ⌘Q 和 15 秒命令超时，6 秒退出强停期限及系统服务完整行为仍待验收。

每步真实调用前重新读取当前上下文/规则、核对原期限和工具身份，提交 SQLite FULL 意图，再复查并核对已提交意图；任一拒绝均不启动命令。命令输出不参与资格或结果判定，不提供 Shell、任意参数、域/键或直接目录删除。结果到达后不因晚到取消、过期或墙钟变化丢弃。worker 只有完全结束/展开后才可将剩余意图对账为未知。

## 未知、历史与数据升级

UI 按原请求读取，不自动重发提交。启动 bootstrap 提供维护摘要；即使 WebView 会话存储丢失，也能发现未核查的中断记录并展示下一步。完整步骤/计数/事件链/原选择、摘要、请求和期限均严格解码；迟到观察不能把已提交成功变回运行/未开始，也不能悄悄更换原计划或身份。历史重开同一请求保留已知事实。

维护未知记录会阻止新修改。用户查看实际预览表现与逐项结果后，可明确记录已核查。SQLite v6 的独立 `maintenance_reviews` 保存原记录 SHA-256 和核查时间，原状态仍是 unknown/interrupted；这只解除新任务准入，不是恢复、成功证明或重复执行许可。新任务仍要重新选择和确认。已核查记录按保留期限处理，未核查、中断、意图、未知或损坏证据不会静默清除。

v1–v5 升级前生成独立 `moomole-before-v6-<UUID>.sqlite`，包含已提交 WAL；旧维护步骤、清理和卸载结果保持。v5 意图先备份、再迁移/启动对账的测试通过；旧版仅识别 v4/v5 的 App 不可直接打开 v6，不能复制旧库覆盖新版结果来降级。
