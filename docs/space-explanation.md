# 云文件与系统数据解释

2026-10-31：空间分析工具栏的说明入口无需先扫描；当前选中项目还可进入“解释空间占用”，读取该确切路径当前的文件逻辑大小、本地分配量和占位标记。说明页连接常用清理候选、完整设备备份、个人目录分析和可用空间趋势。进入处理模块仍需该模块的扫描、选择、保护与独立确认；不会从说明页直接删除文件。

## 实现与计量

`inspect_space_item` 是单项目、无状态的只读观察，不产生执行计划或恢复收据。路径最多 4096 字节，拒绝控制字符、相对路径、点路径段、链接祖先、特殊文件、共享硬链接及不可核对的非本地卷；复用描述符相对的 `AnchoredPath`，普通文件使用 `O_EVTONLY`，不打开正文供读取，不递归或枚举目录。读取后复查路径见证、分配块与文件标记，变化返回错误；仍是有时间点的观察，不是原子磁盘快照或后续操作许可。

文件逻辑大小取 `st_size`，本地分配量取 `st_blocks × 512`，超出前端安全整数的值保持未知。[Apple stat 文档](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/stat.2.html)定义了两种口径。目录自身的 inode 大小不代表其内容总量，故目录的两个大小均返回未知；不会在说明弹窗内追加递归扫描。分配量不代表独占 APFS 块、删除收益、快照总量或系统可清除空间，不进行这些数值的推算或汇总。

占位线索取当前目标的 `SF_DATALESS` 标记，按 [Apple TN3150](https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files) 的元数据方式观察，不请求 provider 下载、驱逐或删除。与文件处理的准入不同，此观察允许本地 dataless 对象，因此不复用会排除占位文件的 `local_materialized` / `directory_probe::local`。没有标记不证明同步完成、云端有备份或可以处理；软件仍可能在后台自行同步，此节点不保证冻结其状态。

固定云位置仅按实际账户目录的路径组件提示 `Library/Mobile Documents` 或 `Library/CloudStorage`，不是完整 provider 枚举，不用文件名推测云状态。其他位置同样可能由同步软件管理。账户 Library 和系统管理位置另给明确说明，不将位置归类当作已证明的 macOS 储存空间分类或清理许可。

接口共用两个检查槽，前台最多等待五秒；超时 worker 继续占槽直到真实返回，不在失去观察时重试、扩展范围或进行处理。界面关闭即丢弃迟到结果；重新读取先撤销旧值，失败不会保留旧属性冒充当前结果。前端核对协议、确切返回路径、有限枚举、数字及目录未知值，再显示结果。没有自动刷新、后台扫描或新持久化表。

## 解释与下一步

系统数据按 [Apple 的分类说明](https://support.apple.com/en-sg/102624)解释为无法归入其他类别的系统和应用数据；不提供“一键删除系统数据”，不把目录差额伪装为该分类数值。本节点未枚举 APFS/Time Machine 快照，未读取系统数据总量。

云文件说明区分删除文件与减少本机下载副本，并提示在 Finder 或 provider 软件核对同步状态。[Apple iCloud 储存空间说明](https://support.apple.com/en-gb/108922)指出 iCloud Drive 删除会反映到其他设备。MooMole 此处不实现云文件驱逐或线上删除；原有个人文件操作仍沿用占位、保护、权限和独立确认门槛。

系统设置按钮只以固定 bundle ID `com.apple.systempreferences` 打开设置，用户自行进入“通用 → 储存空间”；不用未承诺稳定的面板 URL，不改变系统偏好。打开失败或超时明确保留错误，不宣称已显示储存空间分类。没有自动申请系统授权。
