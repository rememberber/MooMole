# 更新后保留应用包的空间管理

2026-11-02：在应用更新记录中选择“检查保留版本与占用…”，重新检查后显示当前安装版本、保留版本、逻辑大小和完整位置。更新后保留的是旧版；可靠恢复旧版后保留的是新版，界面按实际收据展示。默认不勾选，单独确认后才把这一份保留的完整 `.app` 移入废纸篓。当前安装包、下载源和包外数据保持，不自动退出或打开应用，不清空废纸篓，也不承诺立即释放空间。

只接收原更新记录 ID 和请求 ID。原更新必须可靠完成并有双端收据，恢复后的方向还必须有唯一、可靠完成的恢复收据；不能按目录名、版本名称或重新观察现有包来补造权限。核对原两份包的完整内容/元数据摘要、根身份、版本、签名连续性、当前保护和普通账户、管理来源、后台标记及运行状态。专用目录必须仍对应原 `.moomole-app-update-{原更新 ID}` 身份且仅包含原保留包，出现未知内容时整份保留。继续使用完整包 10000 项、64 层、8 GiB 和有界读取的既有限制。

确认保存于内存，墙钟和单调计时两分钟、单次消耗；新的更新、恢复或整理准备撤销其他未使用确认。执行复查原更新/恢复指纹及当前条件，先写独立 SQLite FULL intent，再用既有原生 App 身份引用执行真实系统废纸篓 API。实际返回收据保留原生目标路径及十进制设备/inode，不猜测位置。处理后再次核对当前安装包；仅在移动已确认且未停止时，检查专用目录仍是原目录并且为空，再执行非递归 `unlinkat(AT_REMOVEDIR)`。有额外内容或目录变化时不删除目录。

系统操作前取消保留原包；操作后停止不会撤回已发生的移动，并停止后续空目录清理。检查槽、安装互斥与请求所有权跟随真实线程直到结束；响应等待超时请求停止，不能把线程尚在运行当成已结束。历史最多 64 条、每条 32 KiB，记录检查/意图/完成与实际 moved、retained、cancelled 或 unknown。重启或失去完成写入的任务对账为 unknown，不重放。未知需要用户检查安装位置、保留目录和实际废纸篓位置后另行记录核查；核查不把未知改成成功。运行中、已移入或未知的原收据永久停止提供旧版恢复或再次整理，防止沿用过期位置。原更新和恢复记录保持原样。

界面提供两个阶段的停止、结果和位置定位、独立整理历史、未知核查、已有运行请求接回。重连只读取现有请求，不自动准备或执行；缺少旧收据的历史不自动获得入口。逻辑大小与实际可释放空间分开说明，中英日保留同样的确认与恢复限制。

## 已验证及边界

- Rust 默认全量 **695 通过、107 显式忽略**；新增默认测试验证持久中断、精确请求所有权、人工核查不恢复源权限、路径重定向、伪造成功、期限及 FULL 同步要求。
- 显式原生验收用系统临时目录内自建并临时签名的 Mach-O App，经过真实更新，并覆盖更新后/恢复旧版后各自的正常和完成写入丢失，以及移动后停止。真实移入废纸篓后按确切收据取回，独立核对全部文件名、文件 SHA-256、相对链接及静态签名；当前安装包和下载源的完整树、包外数据、原更新/恢复记录保持。数据库重开读到 moved/unknown，不重放，旧恢复收据被阻断。所有样例和精确废纸篓位置均已收尾，不在 home、下载或文稿创建验收目录。
- 准备过期/墙钟回退、保护变化、系统操作前取消、intent 写入失败和保留目录有额外内容均拒绝且保留原包。验收代码最初遍历废纸篓父目录被拒绝，随后也观察到系统移动期间元数据变化；这两次的确切自建收据已取回、签名及内容核对，已知临时根已清理。最终验收按精确收据取回后独立检查内容，不把废纸篓属性保持不变算作验证结论。
- 前端全量 **256 通过**，新增 12 项 WebKit 与更新/恢复 17 项、应用清单/控制/卸载/更新发现/使用线索 41 项，共 **70 项页面回归通过**。覆盖两种版本方向、默认不选、精确源 ID/单次执行、过期/错绑、两个阶段停止、结果错配不重试、缺失收据、未知核查和精确运行请求接回；中英日 960×780 截图已检查。构建、语言目录和格式检查通过。
- 精简原生记录与正式前端协议读回结果在 `.cache/verification/native-evidence.json` 中按 `retained-app-native.json` 和 `retained-app-protocol.json` 键保留，清理时替换而不堆积截图和样例。浏览器 IPC 验证不替代实际系统调用或 App 窗口。
