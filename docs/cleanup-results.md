# 清理容量结果

2026-10-29：速战速决、软件清理和原清理入口共用的结果弹窗、历史详情与归档查看增加容量摘要。属于 [日常使用路线图](consumer-roadmap.md) 的一键清理结果阶段，不代表八个方向或完整清理验收已经完成。

## 用户看到的结果

- **本批所选大小**：最终确认范围内各项在不可变扫描/计划快照中记录的大小，包含未处理项。
- **确认移入废纸篓**：仅累计具有实际 moved 结果和收据的项目，沿用扫描估算。取消、跳过、失败和待核实项不计入。
- **磁盘可用空间变化**：清理对象处理前后，当前用户主目录所在本地卷的文件系统可用块之差。增加、减少和零变化均如实显示。

大小未知、异常数值或合计超过精确整数范围时，单独标出未知项，不当作完整零大小。项目估算不等于物理分配或可释放大小。移入废纸篓不会立即释放空间，磁盘变化还可能来自其他软件、系统缓存和快照，不能将差值归因于本次清理。详情提供时间、格式化大小和确切字节数，避免较小变化被 GB 舍入掩盖。

没有完整前后观察、卷标识/总容量变化或时间无法与批次核对时，不计算差值。旧记录未记录空间观察也不推算；原计划中可读取的扫描大小仍可展示。

## 记录与生命周期

逐项扫描大小从原执行快照派生，不改写计划、事件、收据或原处理状态。原生空间观察不接收前端路径，只检查当前 HOME 所在本地卷；使用现有 no-follow 路径句柄和 `fstatfs`，核对可用块范围及精确整数预算。保存的卷标识使用设备信息与挂载来源的摘要，不额外保存挂载路径。

观察在阻塞线程完成，最多等 1 秒；超时线程继续持有唯一观察槽位，实际结束前不叠加后台读取。它不发起管理员授权，不请求新隐私权限，也不扫描目标内容。观察/补充记录失败时，处理结果和恢复收据仍可读取，不将清理结果改为失败或成功，不自动重复文件操作。

第一次实际清理时按需创建可选 `cleanup_space_observations` 表，外键绑定执行批次；数据库仍为 v7，读取旧库不为此创建表。每条观察 JSON 最多 2 KiB，属于原有每项 32 KiB 记录预留范围。开始时保存前观察，执行正常结束或取消并收集结果后保存后观察；崩溃/异常缺少后观察则保持缺失，重启不重新采样来伪装成当时结果。

补充观察损坏时降为不可比较，仍保留原始行供归档，不遮住逐项结果。未知结果的核查、任务准入、取消和退出规则继续沿用原执行器。

## 归档兼容

不含空间观察行的归档继续使用原 v1、11 表格式；包含观察行时使用 v2，在原表集合末尾增加这一张补充表。新客户端同时接受 v1/v2，版本必须与表集合一致。发布、读回、摘要、外键验证和容量释放保持同一事务边界；归档保留原始补充行，随执行主记录一起释放活动容量。

原 v1 归档导出/导入后字节保持；新增字段仅在读取原计划时派生，不重新写入旧归档。此前发布的 0.2.0 不支持 v2 归档，含新观察的归档须使用包含本功能的客户端读取。旧客户端遇到引用执行记录的未知补充表会拒绝归档，不级联丢弃该表。
