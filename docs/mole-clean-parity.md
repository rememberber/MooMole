# 完整 Mole 清理

2026-11-01：用户要求概览“一键清理”与内置 Mole 的无参数 `mo clean` 功能一致。本轮固定 Mole 1.65.0 / `308bf9911179ddfa40e5df9fdc42095a18ba5cfc`，直接复用其 `start_cleanup` 和 `perform_cleanup`，不再把少量用户缓存、日志的处理当成完整清理。

## 操作范围

这是独立的**完整命令范围确认**，不是逐项勾选预览的执行端。结构化计划绑定账户目录身份、引擎清单、Mole 白名单、客户端保护列表、是否使用管理员权限及永久删除方式；确认有效期两分钟且只能使用一次。运行时由同一份上游代码重新判断当前符合规则的对象。不会接收前端路径、任意 Shell 命令、旧扫描 ID 或所选文件 ID，也不把另一份已确认的逐项计划替换成全量清理。

| `mo clean` 模块     | 本轮完整入口                                                   |
| ------------------- | -------------------------------------------------------------- |
| 系统                | 选择系统项目后按次授权，使用原系统缓存、过期日志及系统模块条件 |
| 用户基础项目        | 用户缓存、日志、当前账户废纸篓；沿用上游永久删除语义           |
| 应用缓存            | 标准应用与沙盒缓存                                             |
| 浏览器              | 上游支持的浏览器、进程保护、配置与网站数据保留规则             |
| 云盘与办公          | 上游支持的缓存、下载与日志规则                                 |
| 开发工具            | 包管理器自己的清理命令及源码中的文件清理规则                   |
| 应用与实用工具      | 上游专项缓存模块                                               |
| 虚拟化              | 上游的可清缓存；Docker 等仅提示的内容继续只提示                |
| Application Support | 上游日志范围                                                   |
| 应用残留            | 原归属、共享、服务与空容器条件，不按显示名称推断               |

| 工程产物            | 沿用上游的审阅提示，不擅自运行 `mo purge`                      |

这里对齐无参数 `mo clean` 的能力与执行规则，不宣称已提供 `--external` 的外接卷专项或 `--whitelist` 终端编辑器。外置磁盘在概览正常展示，不代表默认清理它们；上游默认废纸篓范围也是当前账户的 home Trash。运行结果仍受本机软件、文件活动、权限和上游预算影响。

## 删除、授权和保护

完整入口在确认页明确说明永久删除和废纸篓处理，并要求主动确认。它不会先移入废纸篓，没有 MooMole 撤销功能；停止只能阻止后续操作。原逐项审阅、计划和移入废纸篓流程继续独立保留。

系统权限是明确选择。整份 Mole 始终以普通账户运行；选系统项目时使用本次私有控制终端和标准 `sudo -A` 授权。独立原生 askpass worker 只把输入交给 sudo 的私有管道，输入关闭回显；密码不进入 argv、环境变量、文件、日志、历史或设置，不上传。每次真实 askpass 请求只接收一次输入；错误或取消不自动执行下一次清理。没有使用 root App、常驻特权 helper、付费证书或修改 Gatekeeper/PAM。未选择系统项目时，不主动取得 sudo 权限，并拒绝调用 sudo 的模块入口。

所有源规则与删除函数保留。适配器只包装固定版本的函数边界，保留所有实参、返回值及原来的动态 guard 上下文；实际方法仍由上游执行。Mole 白名单照常读取；客户端保护额外在 Shell 和原生意图入口核对祖先、后代及可确认的实际位置。所有者命令的作用范围无法核对时保留，不把路径级检查当成全部模块已通过。

## 过程、取消和历史

固定函数边界通过 NUL 字段协议连接本次私有 Unix socket。原生端把执行意图同步写入 SQLite，回复后 Shell 才能进入原始修改函数。结果关联本次意图 token；原始终端输出仅作为诊断，绝不用于决定删除对象。普通删除、系统批处理、空容器、包管理器/Go/GitHub CLI、Homebrew 链接修复、Bun/Tart/Time Machine、simctl 及旧版分析缓存等所有者命令均有对应边界。第三方命令内部没有提供的逐文件明细不会伪造。

必须收到单独的完整结束标记才算本轮结束，不能仅依赖进程退出码；上游 EXIT trap 可能让脚本内部异常以 0 退出。丢失回复、未完成意图和不确定结果保留待核查状态，停止后续处理。取消只信号通知当前持有且未回收的进程组；退出应用沿用共享退出排空流程。重启只把运行中记录标成中断，不重放。

完整清理共用其他修改模块的准入与容量门槛；运行中或未核查的不确定记录会阻止新修改。每批预留 12 MB，事件最多 20,000 条且受 8 MB 文本预算约束，诊断最多 256 KB。页面最多显示最近 2,000 条，导出保存全部结构化事件；核查与清除都绑定最后事件序号。清除历史不恢复文件，也不再执行清理。

前后磁盘可用空间单独观察，不按命令成功或候选大小推算释放量，也不排除其他程序同期写入的影响。
