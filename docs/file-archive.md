# 个人文件归档

2026-10-30 原生窗口补验：已在独立优化 App 中选择两份自建文件、检查并明确确认，真实生成 ZIP，再用系统 `ditto` 独立解压核对。修正了确认误用扫描有效期导致界面拒绝的问题；原件保留。确切环境与未覆盖边界见 [本轮原生验收](consumer-native-acceptance.md)。

2026-10-30：从“文件整理”的当前扫描结果选择普通文件，点击“归档为 ZIP…”，选择现有目标目录和名称，检查结构化计划，再单独确认创建。完成后可在 Finder 显示归档，并从“操作历史 → 文件归档记录”核对结果。归档保留原文件，不自动执行后续删除；归档本身不会释放原文件占用。

服务端只接收当前扫描 ID 与所选项目 ID，从原生扫描存储取出原路径和身份，不接受前端指定归档源文件。每批最多二十项、合计 16 GiB、十五分钟预算，按扫描根目录的相对路径保留层级和重名文件。当前只支持普通物理目录中的本账户单链接本地文件，沿用个人文件敏感路径及保护规则，排除应用/图库包、别名、硬链接与云占位。内部路径含反斜杠或冒号时拒绝，避免跨平台解压路径歧义。

ZIP 使用原生 Rust 流式读取和 Deflate，逐项 SHA-256、ZIP 内容解码/CRC 与原始读取摘要核对，再检查全部源文件、用户保护、目标及祖先身份。临时文件由目标物理目录描述符相对创建，600 权限、排他名称；同步完成后检查临时文件身份、内容和属性未变化，以 `renameatx_np(RENAME_EXCL)` 发布，不覆盖、不复用已出现的名称。发布后再核对真实文件身份和整个 ZIP 的摘要。目标可为本地物理目录，外接卷及不同文件系统的实际行为仍待专门验收，不将路径可选择等同全部支持。

只保存文件内容和相对路径，ZIP 不加密；Finder 标签、扩展属性、资源分支、原始权限及原始时间尚未保存。原文件保留，不能把 ZIP 当作完整 Mac 元数据备份或验收过的迁移替代品。目录整体打包、加密、元数据保留、更多格式及归档后的独立清理继续待补。

## 执行与记录

确认三十秒有效、单次使用且有单调时间期限。新 `personalarchive` 任务使用专用入口、互斥注册、更新租约与归档槽位，阻止更新或其他修改任务与其竞争。请求观察者丢失不会终止后台所有权，也不会让界面自动重复提交。

独立 `personal_archives` SQLite 表在首次执行时创建，使用既有 FULL 同步连接，在创建临时文件前保存结构化源计划、目标、临时路径和意图；发布前保存逐项摘要和预计归档身份，之后持久保存最终结果。本轮容量六十四条，不静默删除历史。它与原有清理/移动/恢复日志分开，不伪装成文件已移动，也不改变现有 SQLite v8 执行记录；独立表的导出与容量管理仍待补充。

读取及校验循环可取消。发布前停止不发布最终 ZIP，尝试按持有的目录及确切临时身份清理本次临时文件；不会清理替换物或其他文件，清理失败可能保留临时文件，可按记录路径核对。发布边界之后的取消、变化或落盘结果无法核对标为未知，不把已存在目标误称未修改，也不自动移除它。

重启仅把未结束意图标为中断，保留目标、临时路径和原记录，不自动删除、重放或继续发布。未知/中断记录未核对前阻止新归档；用户在历史中核对目标和临时路径后可以记录“已核对”，原结果继续保持未知，不改成成功，也不会补发任何操作。尚未提供临时文件的应用内清理、完整磁盘故障矩阵或归档恢复工作流。

## 验证边界

自建普通目录验证真实 ZIP 创建、嵌套路径、不同目录同名文件、空文件、原文件保留、逐项与整包校验、临时文件回收、同名目标不覆盖、源文件变化、复制开始后取消、持久记录、重开中断和核对标记。显式原生样例调用固定 macOS `ditto -x -k` 独立解压，只比较自建源文件与自建解压目录的字节，验证其他工具可读；不会让归档内容决定任意解压位置，产品本轮没有自动解压入口。

页面回归验证确切选择、目标与确认、同名阻止、取消结果、历史、重启后不重放和核对后结果仍未知。原生样例和浏览器传输模拟分别证明其对应范围；实际打包 App 新入口窗口、系统目录权限、外接卷、大体积与完整故障矩阵继续待验收。未安装或公开发布新版本。
