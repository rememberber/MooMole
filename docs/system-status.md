# 系统状态与进程样本

2026-10-17。当前使用固定 Mole 1.59.1 / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f` 的单次 JSON 快照，不是实时监控流。

## 查阅方式

系统状态页的进程快照支持名称/PID 搜索，以及 CPU、驻留内存、名称和 PID 排序。同名进程按各自 PID 保留；搜索按字面文本匹配，不执行命令。列标题明确显示 PID、CPU 和驻留内存，不靠位置推测数值含义。

默认按进程 CPU 从高到低排列。零值保持为零；缺失、负数或非有限指标显示“未知”，数值排序排在已知值之后，不把它们当成零。不将超过 100% 的进程 CPU 压到 100%，也不根据内存百分比补算缺失字节。

搜索和排序只作用于本次已经返回的样本，不发起新采集。显式刷新期间继续显示旧样本并提示“正在刷新”；失败或取消保留旧列表、搜索及排序，成功后才更新数据。同一页面刷新保留查阅偏好，离开状态页后重置；没有跨启动保存或 PID 身份/进程控制能力。

## 上游范围及指标

核对固定树中的 `cmd/status/metrics.go:snapshotFromMetrics`、`metrics_process.go:collectProcesses/parseProcessOutputStrict/parsePsAuxOutputStrict/processRanksBefore`：

- 上游通过 macOS `ps` 采样，优先使用 `pid/ppid/state/pcpu/pmem/rss/comm`，失败时尝试 `ps aux`；实际参数和解析由内置 Mole 负责，前端不重新解析终端输出。
- `top_processes` 只保留 CPU 优先排序的最多 5 个样本，CPU 相同时比较内存百分比及 PID；不是所有进程。客户端内存排序也只是这份样本内的排序，不代表全机内存排名。
- 进程 CPU 沿用 `ps` 的报告值，与整机 CPU 采样口径不同，不能相加或据此推算剩余 CPU。驻留内存沿用上游 `rssKB * 1024` 字节，不代表所有关联内存、可回收或可释放空间。上游字节字段 `omitempty`，未提供时保持未知。
- `process_stale === true` 表示复用较早样本；`false` 仅表示采样当时为新样本，不代表当前实时数据；未报告时显示新鲜度未知。
- 进程时间只读 `process_collected_at`，缺失或不可解析时显示未知，不用整份快照的 `collected_at` 替代。时间不用于判断进程是否仍在运行或识别 PID 重用。

有效空数组、列表未提供及搜索无匹配分别说明；数量未知不计为零。详细范围和单位说明默认折叠，样本数量、较早/未知状态和“并非全部进程”保持直接可见。没有结束进程、提权、后台轮询、自动刷新或额外 IPC。
