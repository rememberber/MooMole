# 系统状态、趋势与速率

2026-10-22。固定 Mole 1.59.1 / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f`。现有手动 JSON 快照之外，系统状态页可显式开始单个 warm collector 的 NDJSON 持续采集。

## 查阅方式

系统状态页的进程快照支持名称/PID 搜索，以及 CPU、驻留内存、名称和 PID 排序。同名进程按各自 PID 保留；搜索按字面文本匹配，不执行命令。列标题明确显示 PID、CPU 和驻留内存，不靠位置推测数值含义。

默认按进程 CPU 从高到低排列。零值保持为零；缺失、负数或非有限指标显示“未知”，数值排序排在已知值之后，不把它们当成零。不将超过 100% 的进程 CPU 压到 100%，也不根据内存百分比补算缺失字节。

搜索和排序只作用于本次已经返回的样本，不发起新采集。显式刷新期间继续显示旧样本并提示“正在刷新”；失败或取消保留旧列表、搜索及排序，成功后才更新数据。同一页面刷新保留查阅偏好，离开状态页后重置；没有跨启动保存或 PID 身份/进程控制能力。

## 上游范围及指标

核对固定树中的 `cmd/status/metrics.go:snapshotFromMetrics`、`metrics_process.go:collectProcesses/parseProcessOutputStrict/parsePsAuxOutputStrict/processRanksBefore`：

- 上游通过 macOS `ps` 采样，优先使用 `pid/ppid/state/pcpu/pmem/rss/comm`，失败时尝试 `ps aux`；实际参数和解析由内置 Mole 负责，前端不重新解析终端输出。
- `top_processes` 只保留 CPU 优先排序的最多 5 个样本，CPU 相同时比较内存百分比及 PID；不是所有进程。客户端内存排序也只是这份样本内的排序，不代表全机内存排名。
- 进程 CPU 沿用 `ps` 的报告值，与整机 CPU 采样口径不同，不能相加或据此推算剩余 CPU。驻留内存沿用上游 `rssKB * 1024` 字节，不代表所有关联内存、可回收或可释放空间。上游字节字段 `omitempty`，未提供时保持未知。
- `process_stale === true` 表示复用较早样本；`false` 仅表示采样当时为新样本，不代表当前实时数据；未报告时显示新鲜度未知。
- 进程时间只读 `process_collected_at`，缺失或不可解析时显示未知，不用整份快照的 `collected_at` 替代。时间不用于判断进程是否仍在运行或识别 PID 重用。

有效空数组、列表未提供及搜索无匹配分别说明；数量未知不计为零。详细范围和单位说明默认折叠，样本数量、较早/未知状态和“并非全部进程”保持直接可见。不提供结束进程或提权操作；持续采集的协议与退出边界见下文。

## 持续采集与暂停

顶部可选 1/2/5 秒，默认 2 秒；“持续采集”将选定值绑定为内置 `status-go --watch --interval Ns`，每次会话只创建一个 Collector。首份快速/完整快照可紧邻，后续在采集完成后等待所选间隔；“约每 N 秒更新”不是硬实时保证，不以反复运行 `--json` 模拟监控。运行时锁定周期，暂停并等待回收后才能调整；重新开始创建新会话/Collector，不原地改变采集器。选择只在当前 App 会话保留，重载/重启回到默认，不新增 SQLite 设置。

接收后端只保存当前会话的最新快照、递增序号、接收时间和状态。前端每次读取结束后 1 秒继续读取，同一观察器不并发，可能跳过两次读取间的中间快照；没有无界事件/样本队列，不把跳过的记录补造成采样点。后端对显示字段进行类型和数量校验，未知额外字段不传给当前界面。进程仍是最多 5 个 CPU 优先样本，进程采样时间和较早标记不被整份接收时间覆盖。

点击“暂停采集”先请求终止本会话，等待原生进程组回收后恢复开始按钮；旧快照、进程筛选和排序保留。重新开始创建新的 Collector，启动期间旧结果仍可查看；没有把旧流率数据拼接为同一段连续测量。持续采集与单次状态快照互斥，可与其他允许的只读任务共用现有最多 3 个任务预算。

离开状态页、页面隐藏或 pagehide 请求停止；原生最小化/窗口销毁也取消采集。重载时仅停止原有状态流，不自动重新启动；会话读取租约为 12 秒，页面失联不能无限保留 collector，已过期租约也不能由迟到读取复活。前端检测 12 秒读间隔或时钟回退后要求手动开始；这是当前休眠保护策略，不代表已完成不同 macOS 的隐藏/睡眠/唤醒矩阵。普通失焦不触发停止。

10 秒没有收到新序号时提示快照可能过时；通道/格式错误保留最后快照并停止，无自动重试。IPC 等待上限 5 秒，暂停可脱离尚未返回的读取并忽略其迟到数据；迟到准入回复按原会话 ID 再停止。观察协议 v2 返回 intervalSeconds 并与请求核对，旧协议/错配拒绝。开始仅接受会话 ID 及 1/2/5 秒整数白名单，原生映射为固定参数；读取/停止只接受会话 ID，旧 ID 不能操作新会话。

## 趋势与磁盘/网络速率

CPU 使用率和内存占用比例使用本轮已接收的结构化样本绘制，纵轴固定 0–100%，横轴为上游 `collected_at` 的实际时间。前端最多保留 120 份且不超过最近 5 分钟，只有新序号追加；跳号、缺失值及超过 10 秒的采样间隔断开，不补造中间记录，采样时钟回退/重复时间重新开始时间轴。暂停保留本轮曲线，重新开始或成功的单次刷新清除旧趋势，不把不连续会话拼起来；不写入 SQLite。

CPU 沿用固定 `metrics_cpu.go:collectCPUWithOptions` 的整机百分比：完整采集优先 100ms 双快照，快速采集使用上次 CPU 计数差，必要时可能估算。现携带 `per_core_estimated`，为 true 时当前数值显示“估算值”，该样本不进入 CPU 曲线；缺失标记显示估算状态未报告。内存曲线只使用 `used_percent`，不从缺失字节反推。非有限、负数或超过 100% 的整机比例不画点；进程 CPU 仍沿用自己的口径，可超过 100%。上游没有逐指标完整采集成功标记，不能据曲线声称持续可靠的系统空闲。

单次与持续状态共用 Rust 显示字段校验。新增 `disk_io.read_rate/write_rate` 和最多三个名称唯一的 `network` 接口，缺失/空数组分开显示，不把未知变成零；负数/非有限速率显示未知。接口 IP、上游网络历史等未用于界面的额外字段不继续传给前端。

核对固定 `metrics_disk.go:collectDiskIO` 和 `metrics_network.go:collectNetwork/networkTotals`：

- 字段虽以 MB/s 命名，实际由字节除以 1024²/秒，因此显示 **MiB/s**；不再次乘除换算。极小的正数显示 `< 0.01 MiB/s`，区别于确切的报告零值。
- 磁盘读写来自上游报告设备计数的合计，不代表某块盘的测速、剩余空间或性能评级。首次计数、读取失败与无计数都可能得到同样的 0；界面在报告零值时直接说明，不能判断为磁盘空闲。
- 网络上游最多返回三个经过筛选的接口，可能同时包含默认隧道和物理承载接口。`defaultTunnel` 是未公开的内部字段，不能仅凭 JSON 复原其合计口径。界面逐接口显示接收/发送，不重新相加或推算全机流量；缺少接口不表示没有流量。

运行时间与采集时间归入设备摘要，CPU/内存两列直接展示曲线；速率说明按需展开，关键零值/未知边界保持可见。暂停/失败或接收过时后速率明确为最后报告值，不把保存的旧数据标为实时。

## 磁盘与逐接口网络趋势（阶段 109）

磁盘读取/写入与网络接收/发送现复用上述本轮采样缓存，不另启采集器、不额外查询、持久化或积分推算总流量。每份样本分别复制两个磁盘速率和最多三个去重接口的两个方向，仍共用最多 120 份/5 分钟的界限；缺失、负数、非有限值保留 null，不补零。上游报告零值可画在零线上，但仍直接说明磁盘初始化/失败也可能报告零，不据此认定空闲。

每图两个方向共用从零开始的 MiB/s 纵轴，实线/虚线、图例文字与每方向有效记录数共同区分，不只靠颜色。上界按当前保留记录的较大值取整，最低 0.01 MiB/s；全部报告零时使用 1 MiB/s，全部未知不画曲线。不显示百分比、测速评级或合计；缩放文字保持可见，不同图的高度和窗口变动后的比例不能直接比较。极小正值仍沿用 `< 0.01 MiB/s` 当前值说明；极大有限值不导致无限坐标。

网络选择器只切换已接收数据，不发起新任务。默认本次首个接口，此后明确保留选择，不因接口排序或消失自动改到另一个。选项来自本次接口与保留样本（最多 120 × 3 个名称），所选接口已不在这些记录时单独保留“本轮未返回”选项；丢失时显示明确提示，历史曲线仍可查看。按接口名称匹配，不证明同名接口设备身份连续；不相加隧道与承载接口。

两个方向独立按缺失拆段，所选接口消失/重新出现也拆段；全局跳号、超过 10 秒间隔与时钟回退仍沿用原规则。横轴取同一批样本的真实时间，不压缩掉缺失区间。暂停/失败保留最后曲线及“最后报告值”，重新开始和成功的单次刷新清空；样本中未收到的流量不重建。空历史提示显式开始采集，全未知说明无有效趋势，不画假数据。

## 内存压力与交换空间（阶段 110）

内存卡片直接显示固定 Mole `memory.pressure` 的 normal/正常、warn/偏高、critical/很高；缺失、空串或任何未支持的值均为未知，不按 used_percent 或交换用量补算。偏高/很高提示查看下方进程样本，保存工作后由用户按需关闭不用的应用；无自动终止进程或内存释放操作。

源码依据 `metrics_memory.go:collectMemoryWithOptions/getMemoryPressure` 与 `metrics.go:snapshotEnrichment.apply`：完整采集使用上游的 memory_pressure 结果识别字符串，快速样本不重新查询压力，可能复用慢采集注释；上游未提供独立压力更新时间或逐字段采集成功标记。因此即使持续采集中也直接标记“更新时间未知”，暂停/失败后为“最后报告值”，normal 不证明当前仍正常。不新增系统命令、不替换或修改引擎采集语义。

同一单次/持续 JSON 显示字段白名单新增 memory.available/swap_used/swap_total 三个可选 u64，保留缺失/null、报告零与具体数值；不增加 IPC、观察协议版本、历史或数据库字段。格式/类型错误沿用停止并保留最后快照，不发布部分新报告，未知额外字段仍省略。前端只展示非负安全整数字节数；可用值超过已知总量时保留未知，已用交换量超过已知总量时撤回两项并说明字段不一致。单项缺失不抹掉另一个独立已报告值。

“内存指标说明”按需展开可用内存、交换已用与交换总量。固定采集器忽略 SwapMemory 的错误并可能回退零结构，因此出现交换报告零时说明它也可能来自采集失败，不能解释为未使用交换空间。可用内存不是磁盘空间或可清理量，交换用量不是当前交换速率、压力或性能评分；不推算未提供数值。

## 电池、GPU 与温度报告（阶段 111）

系统状态页在进程样本之后增加紧凑的硬件报告，复用单次快照与已有 warm collector，不另启查询、要求管理员权限或安装工具。压力提示所指的进程样本仍优先可见。各组直接显示本次有无报告及核心值；具体电池容量/循环次数和指标来源按需展开，不推算硬件健康、评分或可清理收益。

Rust 显示白名单仅新增 gpu（最多 8 条，name/usage/core_count）、batteries（最多 4 条，percent/status/capacity/cycle_count）与 thermal.battery_temp。每个可选文本仍受 4096 字节、整条记录 512 KiB 限制；超量/格式错误拒绝新记录并保留最后快照，不发布部分新报告。未用的 note、显存、电池健康/剩余时间、系统功耗、CPU/GPU 温度及额外时间字段不传给界面；无新增 IPC、观察版本、历史或数据库迁移。

核对固定 `metrics_gpu.go:collectGPU/readMacGPUInfo/getMacGPUUsage`：静态信息可缓存十分钟，使用率可缓存五秒，负值为未取得有效读数；上游三个固定错误占位名称不作为 GPU 设备。界面保留有效名称、0–100% 报告使用率与正整数核心数，负数/越界/缺失使用率未知，不推算显存或相加多 GPU；报告为零也不能证明当前空闲。

核对 `metrics_battery.go:collectBatteries/parsePMSet/getCachedPowerData/mergeBatteryHealthData`：电量 0–100% 可显示真实零，charging/discharging/charged 转为中文，其他状态未知。最大容量需为 1–100 的整数，但来源可能是 system_profiler 或 IORegistry 比例估算，JSON 没有来源区分，始终标注“可能为估算”；循环次数须为正的安全整数，零值可能是读取缺失/失败，保持未知。样本按本次顺序展示，不具备稳定设备 ID；列表未提供、空列表分别说明，不能据此判断没有电池。

核对 `metrics_battery.go:collectThermal/parseAppleSmartBatteryThermal`：当前代码只写电池温度，明确不合成 CPU 温度；CPU/GPU 默认零不是传感器读数。界面只展示大于零、有限且小于 1000°C 的电池温度报告，其余未知，极小正值显示 `< 0.1 °C` 而非零；这是格式展示界限，不是健康/正常温度范围，不以电池传感器代替 CPU/GPU。

`metrics.go:snapshotEnrichment.apply` 可把较早的 GPU/电池/温度值带入快速快照，且未给出各项独立采样时间。因此持续采集时仍直接标记“独立更新时间未知”，暂停/失败改为“最后报告值”，不把 collected_at 当作每个硬件的测量时间。未增加提权、风扇控制、额外采样或改动引擎；真机设备/权限/缓存矩阵与其余字段仍待验证。

## 磁盘容量与概览一致性（阶段 112）

系统状态在进程样本后直接展示 Mole 已返回的挂载点、报告总量/已用与按字节计算的余量/比例，复用当前快照，不探测挂载点、启动扫描或生成整机容量合计。列表未提供与空列表分别说明；外接字段仅显示为上游线索，false 是“未标为外接”，不直接断言是内置盘。快照可沿用较早的容量修正，独立更新时间未知直接可见；暂停/失败为最后报告值。

核对固定 `metrics_disk.go:collectDisksWithCorrections/shouldSkipDiskPartition`：上游排除部分系统/网络/FUSE 挂载和小于 1 GiB 的卷，按基础设备及文件系统/容量线索去重，排序后最多返回三条；并非完整已连接设备清单。Rust 原有 256 条通用上限同步收窄为这份固定基线的 3 条，超量拒绝整个新记录并保留旧快照。没有增加字段、IPC、观察协议版本或数据库迁移。

展示只接受非负安全整数字节，总量还需大于零；有效余量为 total-used，比例为 used/total，不从 used_percent 倒推字节或将异常比例压成零/100%。已用超过总量时保留已知总量，撤回已用、余量和比例并说明不一致；字段缺失、精度不安全与零总量不补算。真实已用零或满盘余量零可保留，未知不是零。挂载点为有界绝对字面路径，控制/点段/空段或越界名称显示未知，无路径跳转/命令执行。

`correctAPFSDiskUsage` 可能沿用 Finder/diskutil/statfs 修正，报告余量可能包含系统可清除空间，不是目录可清理量或当前可写保证；APFS 多卷也可能共享容量池，不把每行相加成整机总容量。修正来源未逐项暴露，不猜测来源或独占物理空间。

概览复用相同字节校验与计算，仅选择唯一的字面挂载点 `/`，标为“系统卷 /”；缺失或重复时保持未确认，不再退回另一条未标为外接的磁盘当作启动盘。无效容量使用明确未知、无已用色块的圆环，避免把矛盾数据画成 100%；余量改为“报告余量”，保留计算与缓存边界。系统状态中的其他报告仍可查阅，不扩大为外接盘分析/权限/故障矩阵已完成。

## 资源与退出边界

单条 NDJSON 上限 512 KiB，已支持文本字段 4096 字节、最多 3 条磁盘报告、3 个网络接口、5 个进程样本、8 条 GPU 和 4 条电池记录；错误或不完整尾记录停止。stderr 共 64 KiB、45 秒无输出字节停止，会话最长 24 小时；不存在硬实时保障。所用进程监管复用当前 lease/未回收主进程、TERM 宽限、最终强停再回收及输出通道期限，不使用保存的裸 PID 去终止后续进程。

会话在 SQLite 只记录开始/停止或失败摘要，不持久化每个样本；任务历史显示“系统状态持续采集”，不接到单次任务的结果重放入口。启动中断对账沿用原数据库逻辑。采集期间持有安装准入，退出通过现有共享 6 秒取消/排空流程。
