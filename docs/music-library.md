# Music 导出资料库的本地媒体整理

2026-11-03：软件清理 → 附件、下载与离线 → “Music 导出资料库中的本地媒体”。在 Music 中用“文件 → 资料库 → 导出资料库”保存 XML，也可选择 XML 格式的播放列表导出。手动选择后扫描、预览、按大小/时间筛选、逐项选择、独立确认，再真实移入废纸篓；默认零选择。取消选择器保持原来源，更换 XML 或软件来源撤下旧选择，即使位于同一账户目录也需重扫。

[Apple 的导出说明](https://support.apple.com/en-ca/guide/music/-mus27cd5060f/mac)明确导出的是资料库/播放列表信息，实际歌曲与视频不包含在 XML 中。本流程只依据明确本地地址定位文件，不把 XML 当备份或把线索当删除依据。文件可能是唯一原件或含编辑内容，移走可能使 Music 引用失效；确认前明确提示，保留 XML、内部资料库和未选文件，不承诺可重新下载。没有从资料库移除条目、联网下载或操作云端收藏。

当前支持 UTF-8 XML plist、资料库主/次版本 1.1，要求 `Application Version`、`Tracks` 字典及每项一致的正整数 `Track ID`、`Track Type=File`、整数 `Size` 和本地 `Location`。这是经核对的字段子集，不是 Apple 公布的稳定清理 API 或全部 Music/iTunes 版本兼容保证。明确的 `Protected` / `Apple Music` 标志、远程地址、`.m4p` 等未支持扩展、缺失、大小不符、相同本地路径的多条记录保留为未纳入/不完整。不解密或推断重新取得的授权；订阅服务自管下载及完整 DRM 识别仍待适配。

只纳入本账户、同设备、普通本地且已落地的支持影音文件；链接、共享硬链接、保护、隐藏/敏感位置、Library、应用/图库/音乐资料库包沿用原有排除。清单最多 8 MiB、2000 条曲目、XML 32 层/200000 个事件，单键最多 4096 字节，结构化项目最多 7 MiB；十秒读取/遍历检查预算及取消不等同阻塞系统调用的硬实时终止。系统属性列表解码前先预检声明、结构上限及重复字典键（包括未使用元数据），拒绝自定义实体和非标准 DTD，不取回外部资源。原始 XML 和未用的标题、姓名、播放列表等在有界本机解析期间仍进入内存，但不把这些 XML 元数据字段写入报告、计划、历史、预览或 AI。

新的 `musicLibrary` 来源复用软件内容的私有清单见证，旧来源字段及编码含义保持。运行边界复查清单完整身份/时间、文件及保护，变化后保留并要求重扫。沿用单次短期确认、正式 Mole 路径规则、FULL 同步意图、逐项真实收据、停止、中断未知和便携执行归档。新来源记录须使用包含此来源的客户端；导入历史不产生处理权限。应用内恢复本来源仍待补，可按可靠收据在 Finder 核对，不清空废纸篓或承诺立即释放空间。

验证：三项新增默认 Rust 测试覆盖来源/字段/隐私、原件和未选文件、重复/未知/受保护标志、远程/大小异常、链接/硬链接、清单/保护变化、取消、曲目/深度/大小上限及重复未使用键拒绝。一项显式原生测试在自动回收的系统 TempDir 自建 XML、有效 PCM WAV 和模拟资料库，经生产扫描、选择/确认、正式 Mole 和原生废纸篓真实处理一项；核对实际收据与内容后只取回自建文件以清理，原 XML、未选媒体和模拟资料库保持，SQLite 重开及便携归档读回相同。该取回不是产品应用内恢复，也不是实际 Music 导出窗口验收。
