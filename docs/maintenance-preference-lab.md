# 维护偏好原值与恢复隔离实验

2026-10-21。本实验验证“保存原始状态 → 写入固定测试键 → 精确读回 → 条件恢复”的基本路线及失败边界，不代表 App 已支持维护修改或恢复。实现位于 `src-tauri/src/maintenance/preference_sandbox.rs`，仅由 `#[cfg(test)]` 编译，未接入 IPC、App 菜单或运行时开关。另增 [SQLite 与真实子进程恢复实验](maintenance-recovery-journal.md)；下文的 Ticket 仍指原始同进程实验。

## 范围

- 每次由程序生成新的 `io.github.rememberber.moomole.preference-lab.<UUID v4>` 域；不能从环境、命令参数、快照或页面传入目标域。只写该域的三个固定 fixture 键，不写六个真实维护设置、Apple 全局域或其他用户域。
- 使用当前用户，分别验证 AnyHost 与 CurrentHost 的明确域；不把 `CFPreferencesCopyAppValue` 的继承/有效结果当作该明确域的原始值。
- 缺失、布尔、整数、UTF-16 字符串分别保存。字符串保留空串、中文、非 BMP 字符及嵌入 NUL；浮点、无效 UTF-16、过长字符串及未适配类型拒绝，不将所有值简化成 true/false。
- fixture 先建立所有权标记和无关键，检查同步结果、所属标记、键列表与两次读值一致性后，才在该已建立的测试域中确认缺失。**这种缺失证据依赖实验自己的标记，不可直接移植到真实 Apple 域，也不会为探测缺失而向真实域写标记。**

默认 Rust 测试只运行内存类型/私有快照文件验证，写入系统偏好服务的六项测试均显式忽略。手动运行：

```sh
node scripts/cargo.mjs test --locked maintenance::preference_sandbox -- --nocapture
node scripts/cargo.mjs test --locked maintenance::preference_sandbox::live_ -- --ignored --nocapture --test-threads=1
```

实机测试正常结束时核对清除三个测试键；Drop 额外做尽力清理，所有权未知则保留。未清理整个域或目录，系统可能保留空 plist/缓存；此处不承诺完全没有系统缓存痕迹。所有 journal 文件位于测试自己的 TempDir。

## 快照与执行核对

快照绑定协议、随机域、所属标记、明确主机范围、固定键、原始缺失/类型/值和期望值。先以独立新建、0600 的 JSON 文件保存，调用文件及目录同步后才允许写入。读回时限制 32 KiB，拒绝链接、非普通文件、硬链接、错误所有者/权限、篡改、未知字段或目标绑定不符。

Ticket 在内存中持有快照摘要，恢复重新从文件加载并验证，不借用原值对象。这个摘要不是签名，也没有跨进程持久信任根；本节 Ticket 未实现重启后的安全接回、加密、数据库迁移或电源故障验收；新增 SQLite 实验另行验证私有目录下的记录接回，仍非正式 App 信任根。文件同步调用通过也不等于已经验证断电持久性。

写入前核对当前明确域值仍等于原值，恢复前核对仍等于已写期望值。已知变化时拒绝覆盖当前值；恢复缺失时仅删除新增测试键，其他原始值按原类型写回，再次核对类型与值。每轮确认无关 fixture 键保留。

## 已验证与实际发现

1. **18 组原值往返**：两种明确主机范围，每种分别验证缺失、布尔 false/true、整数 0/1/最小 i64、空串、字符串 `1`、含中文/非 BMP/NUL 的字符串。期望值与原始语义有实际差异，恢复后缺失/类型/值逐项一致。
2. **继承与明确域分离**：AnyHost 设置 fallback，CurrentHost 缺失但有效读取可见 fallback；在 CurrentHost 修改后恢复为缺失，AnyHost 与最终有效 fallback 保留，未把继承值复制到 CurrentHost。
3. **复查前的冲突与证据变化拒绝**：模拟其他写入发生在修改或恢复复查之前时保留新值；journal 改变后拒绝恢复，不用猜测原值。写后观察者未收到完成通知的模拟，可在同一个 Lab/Ticket 会话中用已落盘 intent 条件恢复；这是通知丢失模拟，**不是实际 SIGKILL/跨进程重启恢复**。
4. **整数/布尔等价的类型陷阱**：初次实测将整数 1 写为布尔 true 后，同步成功但严格类型读回未匹配。实验没有放宽类型核对、把“值相似”当作成功，也不使用先删再写规避。现在在写前拒绝等价的整数/布尔转换及同值无变化请求；整数 0/1 的原类型保持已验证。该行为仅记录本机测量，不推断所有 macOS 版本的内部实现相同。
5. **最终复查后的竞争窗口仍存在**：隔离注入在最后复查与 `CFPreferencesSetValue` 之间写入新值，复现其被后续写入覆盖，而期望值读回仍通过。此项测试的通过表示成功复现限制，**不是并发安全通过**。常规前置检查、快照摘要、同步或写后核对都没有提供与其他写入方共用的原子比较并写入保证。

6. **同进程字符串核对不证明跨进程恢复**：新增 SQLite/exec/SIGKILL 实验发现含 NUL 字符串由后续进程读取时发生截断，故新持久协议对此只允许归档，修改/恢复前拒绝。原来的 18 组同进程结果仍保留为其有限范围内的证据，不推广成跨进程或断电持久性保证，见 [持久记录边界](maintenance-recovery-journal.md)。

## 对正式实现的约束

当前 App 仍只读；不把这些测试中的 writer 导出为任意域/键写入接口。真实原值捕获需先确定正确的用户/主机域、原始类型及缺失证据，不能使用实验所有权标记替代真实域的读取可靠性。还需要持久操作/恢复记录、用户逐项选择、当次保护/管理状态复核、实际 App 身份验证和结果接回。

最终检查与写入的竞争边界必须在变更协议、用户确认、结果和恢复条件中如实处理；不能承诺不会覆盖并发修改，不能仅靠“再检查一次”宣称关闭窗口。研究可接受的受限操作与冲突处理路线时，保留这项复现用例。缺少原值、证据不可用、管理/保护状态不明或恢复前值变化均不得自动继续。

免费分发路线没有因本实验增加付费 Developer ID 或常驻 helper 前置条件；但测试二进制在本机普通账户成功，不能代替实际 ad-hoc App、Intel、旧系统、TCC、真实 Apple 域或正式更新后的验证。
