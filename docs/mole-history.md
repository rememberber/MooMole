# Mole CLI 原始历史的只读展示

2026-10-16。固定 Mole 1.59.1 / `ba3a0f57f78e4c22818fda701219cc3dd4d6953f`，客户端历史报告 v1。没有修改上游、增加删除/恢复接口或迁移数据库。

## 来源与归属

操作历史页可手动启动“Mole 历史读取”，通过包内原版 `bin/history.sh --json --limit 200` 获取结果。使用上游 JSON 字段，不解析终端文案决定操作对象。固定读取当前应用 HOME 下 `Library/Logs/mole/operations.log` 与 `deletions.log`，不继承终端中自定义日志路径，不查其他账户或轮转归档。

- CLI 会话保留 command、run_id、归属级别、开始/结束时间、汇总项数/原始大小及各类操作计数。上游按 command 与真实 run_id 聚合的结果直接展示；客户端不根据相邻时间或路径重新合并。
- 无 run_id 的 command 归属及上游 ambiguous 标记均明确解释，不生成替代 run_id。没有结束标记显示“未记录结束”，不推断仍在运行或已经成功。
- 删除日志保持独立列表：该 JSON 没有 run_id，也没有可靠的实际废纸篓位置或对象身份，不能与会话按时间猜测关联，不能生成客户端执行收据或恢复按钮。
- `dry-run` 显示“仅预览”；`ok` 只显示“记录为成功”，不证明目标当前状态。未知状态、方式和命令保留原始值。原始路径中的转义文字照原样展示，不反解成可操作路径。
- 项数与大小来自上游汇总；操作计数是日志条数，不能据此声称释放空间或可恢复。旧格式/无效行可能被上游读取器忽略，空结果不表示从未操作过。

原始历史与客户端检查任务、审阅计划、SQLite 执行记录分开展示；不按名称/时间去重或互相冒充来源。Mole 原始日志的保留由 Mole 管理，客户端 7/30/90 天设置不清理它。

## 读取与失败边界

Rust 在阻塞工作线程中只读打开原日志，以 `O_NOFOLLOW / O_NONBLOCK / O_CLOEXEC` 拒绝末级链接与阻塞式特殊文件读取；打开后必须是普通文件。每份最多 1 MiB、10000 行、单行 16 KiB，要求 UTF-8 且无 NUL。大小或 mtime/ctime 在读取期间变化时要求重试，不截断原日志后发布为完整结果。

分别生成私有临时目录内的副本，再将副本路径传入原版 history 的环境变量。子进程清空继承环境，仅配置固定 PATH、HOME、TMPDIR、颜色及两份输入路径，避免继承自定义输入或 Bash 启动脚本。两份副本独立取得，不是跨日志原子快照；并发轮转时也可能读取到已经打开的旧日志版本。时间仅表示本次读取完成时间。

文件未找到显示 missing；无法打开、类型不支持、超限、无效编码或读取中变化显示 unavailable，并保留具体原因。某份不可用时给上游一个空的私有输入，让另一份仍可展示，同时明确“部分历史无法读取”，不会把失败显示成没有历史。副本离开任务后清理，不写入原始日志。

调用继续使用统一的进程组、取消和退出逻辑，命令期限 30 秒、标准输出上限沿用 32 MiB。Rust 校验必需字段、来源路径、limit、每类最多 200 条、归属组合、操作计数总和、有限字符串及 JavaScript 安全整数；未知协议组合、缺字段、截断或不一致拒绝发布。内核文件调用仍可能挂起，字节/行数预算不是网络卷超时保证。

结果通过既有事件和任务快照交付，页面刷新可接回运行中的读取；缓存到期或重启后需重新读取，不自动重放。原始 JSON 与日志副本不持久化到 SQLite，只保存普通任务状态。界面分别提供命令/日志状态筛选、路径/run_id/时间搜索和每次 20 条的展开显示，失败可重试，更新期间保留并标明上次结果时间。

## 验证

普通 Rust 测试只使用临时文件，覆盖缺失、链接、目录/FIFO、无效编码、超限、读取中变化、来源独立状态，以及 JSON 字段/归属/数量/数值校验。两项需要准备引擎的集成测试默认忽略，显式运行：

```bash
npm run engine:prepare
node scripts/cargo.mjs test mole_history -- --ignored
```

这些测试通过生产 `engine::run` 调用固定版 history，仅读取自建隔离 HOME，验证交错 run_id、旧命令级归属、未结束会话、特殊名称、未知大小、仅预览及缺失日志，不写用户日志或数据库。浏览器另验证归属、分页/筛选、部分不可读/缺失/空日志、失败/取消重试、无事件通道及刷新接回。实际 App 验证和计数见 [开发记录](development.md)。

后续仍需自定义日志位置/轮转归档的明确授权与读取策略、其他引擎版本兼容及各模块真实结果协议。本页不承诺历史恢复能力。
