# 产品宗旨与功能边界

2026-10-15：根据用户在开发过程中的明确补充，本文件作为当前产品方向依据。

**MooMole 的宗旨是对 Mole CLI 进行客户端可视化，以及在此基础上提供更多的人性化功能。**

产品功能以 Mole CLI 的能力为基础组织。应用负责把 CLI 的输入、过程、结果和权限状态变成易理解、可控制的桌面流程；开发缓存分析只是补充能力之一，不作为整个产品的定位。

## CLI 能力与客户端流程

| Mole CLI          | 客户端目标                                             | 当前进展                                                                           |
| ----------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| clean             | 扫描、结果解释、审阅、保护、确认清理和逐项结果         | 已适配 dry-run NUL ledger，支持结构化审阅、保护、持久化审阅计划及身份/有效期复核；实际清理未开放 |
| uninstall         | 应用搜索、关联数据审阅、个人数据保留、卸载结果         | 已接入只读应用清单；卸载执行未开放                                                 |
| analyze           | 目录选择、空间可视化、下钻、部分结果提示和 Finder 定位 | 已实现只读分析流程                                                                 |
| status            | 系统状态可视化、缺失/过期指标说明                      | 已接入手动刷新快照；长驻采集流待接入                                               |
| optimize          | 展示维护任务及影响，按需授权、明确跳过原因             | 待适配                                                                             |
| purge / installer | 工程产物/安装包发现、逐项选择及处理结果                | 待适配                                                                             |
| history           | 引擎操作记录与客户端任务记录，来源明确                 | 已有客户端 SQLite 任务记录；Mole 操作历史待接入                                    |

## 人性化功能

优先实现目录选择、搜索/筛选、影响说明、逐项审阅、保护列表、可取消任务、明确的权限与失败提示、历史记录，以及主题和键盘操作。界面不能让未知大小看起来是零，不能把“移入废纸篓”等同于“已释放空间”。

客户端扩展应有明确的使用场景，并保持与 Mole CLI 执行语义一致。已有的路径保护与应用保护规则应继续生效；需要逐项执行的流程先完成适配，不能把用户确认的一份预览替换为另一次全量清理。

## 开发阶段

当前交付只读可视化：真实引擎连接、结构化清理审阅和本地状态管理。后续优先补齐带文件身份和有效期的计划执行，再扩展卸载、维护及工程产物处理。当前不是完整 MVP，也不以开发缓存检查代替完整 CLI 能力适配。

技术栈、开发前创建 `.gitignore`、界面风格参考，以及 README/App 的学习研究用途、风险说明和官方产品引导，继续遵循 [guidance.md](guidance.md)。

## 安装与升级约束

用户没有付费 Apple 开发者签名能力。正式发布以免费分发为前提，参考 MooTool Electron 的“检查更新 → 下载匹配架构 DMG → 校验大小和 SHA-512 → 用户打开 DMG 并手动替换 App”流程。保持 Tauri 技术栈，由 Rust 实现对应能力。

不将 Developer ID、Apple 公证或自动覆盖安装作为发布门槛。采用适合 Tauri 的 ad-hoc 签名与真实安装验证，并如实说明首次打开可能出现的系统提示。方案、参考源码及验收要求见 [distribution.md](distribution.md)。
