## 默认安装方案

1. 为实际支持并验证的架构分别生成 `MooMole-{version}-mac-arm64.dmg` 和 `MooMole-{version}-mac-x64.dmg`；公开名称确定后统一调整命名。
2. 通过本项目的 GitHub Releases 发布 DMG、字节数、SHA-512、版本说明、源码及许可证信息。
3. App 和内嵌 Go 等可执行文件采用经验证的 ad-hoc 签名方案；Tauri 可配置 `bundle.macOS.signingIdentity` 为 `-`。这不需要付费 Developer ID，但也不提供 Apple 开发者身份认证或公证。
4. 用户下载并打开 DMG，将 App 拖入“应用程序”。建议从固定安装位置启动，避免从 DMG 运行后再进行升级或授权。
5. 对实际系统上出现的未验证开发者提示，提供 Apple 官方说明，由用户按系统提供的流程自行确认。不能保证所有系统/组织策略都允许打开，也不将“右键打开”表述为所有版本通用的保证。

初次安装提示属于免费分发的已知体验边界，应在下载页和 README 明示；应用不会自动关闭安全检查或修改安全属性。

参考：[Tauri ad-hoc 签名](https://v2.tauri.app/distribute/sign/macos/#ad-hoc-signing)、[Apple 打开未公证应用说明](https://support.apple.com/en-us/102445)。

## 默认更新流程

```text
检查本产品更新清单
  → 按 SemVer、通道、系统与架构选包
  → 展示版本说明
  → 下载 DMG 到应用专属缓存
  → 校验字节数和 SHA-512
  → 显示“更新已下载，打开 DMG 安装”
  → 用户触发安装，检查活动任务并完成必要的数据保存
  → 成功打开已验证 DMG 后退出客户端
  → 用户将新版拖入“应用程序”，确认替换
  → 新版启动，验证引擎并迁移本地数据
```

- 提供后台下载开关，按 MooTool 方式支持后台下载及手动下载；不自动执行安装包或覆盖 App。
- 修改任务未完成时延后退出安装；有未保存内容时先完成保存或明确取消，不直接终止正在进行的清理。
- 若打开 DMG 失败，保留应用运行，提示重试、在 Finder 中显示安装包或访问发布页。
- 不将打开 DMG 当作安装完成；只有新版启动才能记录新版运行状态。
- 拖拽替换只处理 App 包，SQLite、设置和历史留在应用数据目录；迁移前备份，失败时保留恢复信息。
- 从 DMG、临时位置或不可替换位置运行时说明操作限制，提供重新安装入口。

## 清单、下载与信任边界

- 固定本项目产品 ID、更新源和允许的发布资产来源，不读取 MooTool 的产品节点；前端不能提供任意下载 URL 或任意本地安装路径。
- 清单记录 schemaVersion、版本、通道、说明、发布页，以及每个资产的平台、架构、包型、文件名、URL、大小和 SHA-512。
- 稳定版忽略预发布版本，精确架构优先；没有匹配资产时提供发布页，不回退到错误架构。
- 清单与下载使用 HTTPS，限制响应大小、下载大小、重定向来源与超时；处理取消、断网、磁盘满及重复请求。
- 使用唯一临时文件，完整写入并校验后才变为待安装文件；安装入口只使用后端记录的已校验文件，并在打开前确认文件没有变化。
- 大小和摘要能发现下载损坏，但不能单独证明发布者身份。可采用自行生成、免费保管的密钥为清单/更新包增加独立签名；它与 Apple Developer ID、公证是不同机制。
- 本轮采用 Rust 检查/下载和用户手动安装流程，不把 Tauri 自动安装插件作为必需依赖。若以后采用该插件，保留其要求的更新包签名验证，不尝试禁用验证。

参考：[Tauri 更新器签名要求](https://v2.tauri.app/plugin/updater/#signing-updates)。

## 更新缓存与发布顺序

缓存策略可沿用 MooTool：应用专属 `pending-updates` 目录；完整 DMG 保存 7 天、未完成下载保存 24 小时，启动及定期清理。只处理符合本项目命名规则的普通文件，不跟随符号链接、不递归目录，保护当前下载和等待安装的包；失败不阻断应用启动。

发布顺序：版本与说明校验 → 构建/测试 → 验证 ad-hoc 与嵌套资源 → 上传 Release 资产 → 验证实际可下载资产及摘要 → 发布更新清单。清单不能提前指向不存在的安装包。

CI 明确记录“未使用 Developer ID、未公证”。缺少付费证书不是失败条件，实际发布物验证失败仍必须阻止发布。

## 权限与系统级功能

无付费签名会影响稳定应用身份、文件隐私授权及特权 helper 的设计，需要逐项实测。下一阶段先验证无需付费证书的按次系统授权或受限辅助程序方案；不预设常驻特权服务一定可行。

普通权限功能正常提供；需要授权的任务按实际支持情况提示请求、拒绝、取消和受限原因。应用不保存管理员密码，不让任意前端参数变成 root 命令，不把购买开发者账户作为用户使用产品的前提。
