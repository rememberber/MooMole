# 单 App 卸载执行与结果接回

2026-10-24：已新增 `uninstall_execution`，将一次选择、当次复查、持久意图、普通用户原生废纸篓和结果记录串联。后端有专用提交/读取/取消 IPC；后续已接 [选择/确认、结果与历史界面](app-uninstall-interface.md)，并补实际 App 的自建包正常路径；完整取消/中断/权限矩阵仍未完成，不能据此宣布卸载全部验收通过。[首发三项真实执行门槛](first-release-execution.md) 保持未完成。

## 明确提交的范围

继续使用 [独立计划](app-uninstall-plan.md)，只从本实例保留的成功 Mole 应用清单读取任务/条目，不接收待删除路径、命令或前端可执行结论。首批限 Applications 直接子普通 App 包、当前普通账户所有、本地已落地的原生主程序；系统/自身/保护、固定 Mole 保留/官方卸载器、后台/管理线索、未知或变化保留。包外设置、缓存、文档及关联数据全部保留。

确认协议升为 v2：原最长 30 秒、最多 8 份、一次取用及完整计划/保护绑定保持，增加声明范围 `ordinaryAppDefaultLaunchAndCaskroom` 和必须确认普通 App 的字段。只有新鲜的包内进程及固定范围配置检查通过才提供可提交确认；`canExecute=true` 表示可明确提交，**不保证最终执行**。只读计划、进程和配置报告仍为不可执行，不从历史恢复许可。

`execute_application_uninstall(planId, confirmationId, requestId, ordinaryAppConfirmed)` 要求明确确认首批普通 App 的范围。受其他安装管理工具管理或带专用后台服务的应用应使用其卸载方式；固定范围负面结果不冒充全部 BTM/MDM、外部注册或自定义管理器的证明。界面展示该范围，不能自动勾选或从列表点击直接提交。

后端消费确认后重新取得仍发布的计划、成功源清单、首次使用确认、客户端身份/位置和最新保护；过期、撤下、重放、源回收或上下文变化拒绝。Mole `--list` 的 HOME 已显式绑定传入的后端账户目录，避免清单沿用与复查不一致的进程环境。没有运行通用卸载 Shell、root 修改器或安装常驻 helper。

## 意图、取消与原生结果

一份请求对应一个 App 和一个专属记录；请求 UUID 同时为持久会话 ID，响应丢失仍可按该 ID 查实际结果。执行顺序为：

1. 独立 AppTrash 任务准入并消费确认；创建 [持久 pending 会话](app-uninstall-journal.md)，以共享事务准入阻挡并发清理/卸载及待核实批次。
2. 固定原生对象引用，重新核对完整包、当次后台/管理配置和进程。配置观察与进程观察使用各自原始 5 秒墙钟/单调期限；没有把执行开始时间作为新鲜度来源。
3. 最新计划/来源/保护/确认再次成立后，FULL 同步事务提交意图；写入失败不调用 API。
4. 原生最终检查核对对象、整个包、引用位置及文件系统权限，再核对最新来源/保护/确认、原始运行/配置观察、同一持久意图和取消；随后由系统废纸篓 API 处理这个完整包。
5. 按实际返回对象、原设备/inode、包清单和原位置记录 moved 或 uncertain。API 返回错误、缺少收据或无法证明结果不冒充未修改，不自动重试；已调用后只收集事实，迟到取消不能把实际移动改写为未开始。

意图前取消为 cancelled/无 API；意图后最终检查确定未调用 API 的取消也为 cancelled，事件保留 pending → intent → cancelled。其他已确认调用前拒绝为 failed。只有 worker 已经终止/展开后才整理其故障记录：pending → notStarted，intent → uncertain；不在原生调用仍进行时抛弃意图。意图/结果写入失败保留已有证据，禁止自动重试，启动对账继续使用专属记录。

用户取消只提出停止请求，不能中断已进入的 Foundation 调用，也不承诺撤销已完成操作。系统或 App 被强制结束的边界仍依赖重启对账；没有产品内自动恢复/批量重放。后续恢复必须按确切收据、身份和不覆盖原则分别设计，不跟随旧路径处理新对象。

## 界面消失、退出与更新

工作由独立后台任务持有，WebView/IPC 响应接收者消失不撤销或丢弃 worker。任务、数据库目录占用和更新操作租约保持到原生结果收集、持久化及故障整理结束；先结束更新租约，再撤下同一任务句柄。清理、卸载和权限探针在任务注册表中双向排他；SQLite 继续提供跨连接共享准入。普通读取不因此得到执行许可。

退出沿用现有有限等待：向当前任务提出取消，等待结果收集；超时不声称原生操作完成，意图留给启动对账。更新前数据检查新增卸载 running 记录，不能仅因没有普通 tasks 行就认为数据已静止。

`get_application_uninstall(requestId)` 返回当前任务句柄状态及可用持久详情；准入后尚未创建会话时可能 active=true/record=null。结束恰好发生在读取期间会再次读取持久结果。无句柄/记录返回明确的 active=false/record=null 观察；若查询先于新提交的准入抵达，前端须等待执行响应或该请求的首次有效观察，不能用一次暂时缺失终结提交。任何缺失都不是重新提交依据；`list_application_uninstalls()` 仅读取最多 64 份验证过的摘要，`cancel_application_uninstall(requestId)` 只取消该确切 AppTrash 任务。日志取消接口也限定日志任务，不跨模块借用执行 ID。

## 验证边界

普通回归用自建 App 包和私有目录移动，生产调用前的对象/权限/最终门槛及持久流程保持；正面运行/配置结果和原生移动替换仅存在于测试编译代码，不能作为真实权限或发布 App 证据。覆盖意图/收据顺序、未知/运行保留、各阶段取消、晚到取消、来源/保护/首次使用确认/包变化、写入失败、worker 故障、请求重放和丢失观察者仍保留任务/更新租约。

真实 Mole 清单、真实运行/配置观察、系统废纸篓及确切取回的显式联验另行记录在 [开发记录](development.md)。正式 App 的选择/确认/结果/历史界面、取消/退出/重启与恢复操作，以及声明支持范围的权限/卷矩阵仍待完成；不通过卸载开发者日用应用或修改系统安全属性取得证据。
