# 持续空间观察

2026-10-30：侧栏“持续管理”提供真实容量记录、同卷趋势和低空间提示。这是持续管理第一条可用流程；目录定期扫描、菜单栏与系统通知、定期文件处理仍在后续范围。

- 默认关闭定期采集。可单次“记录当前空间”，或选择十五分钟、一小时、六小时的间隔，明确保存后开启。低空间阈值可选 5、10、20 GiB。
- 只读取本账户所在卷的容量，不扫描文件内容、不上传样本、不自动处理文件。使用既有有界 statfs 观察与单 worker 准入；失败保留旧记录，不把缺失计量当零。
- 定时器随 App 运行，最迟一分钟核对一次到期间隔；休眠后只采集一次当前状态，不回填缺失时段。退出后停止，下次启动按已保存设置恢复。关闭或更改设置后，旧配置的在途结果不再保存。
- 配置和最多 720 条样本保存在独立的可选 SQLite 表中，不修改执行收据、不消耗执行历史容量、不改变 v8 数据库版本。仅展示同一卷且总容量相同的最近六十条观察；时间不递增时不绘制趋势。
- 低空间提示只显示在该页面，可转到空间分析继续处理。旧样本明确标记历史状态；容量波动不等同于清理效果。没有后台常驻 helper、登录项或系统通知权限请求。

基本验证：真实本地卷 statfs 样本保存，个人样例文件字节不变；配置关闭、代际变化、到期/时间回拨、容量上限、重开持久化及未来配置保留有基本测试。默认 Rust 回归 584 项通过；前端 203 项单元测试通过，新增三项浏览器流程验证明确开启、间隔和阈值保存、手动采集不改变关闭状态、历史样本和未知容量，另有 31 项主界面与语言回归通过。arm64 release App 已构建并通过 ad-hoc、嵌套程序及 ZIP 解包校验。

尚待实际 App 的新页面窗口与十五分钟完整周期、睡眠/唤醒、关闭/重开调度验收；当前自动化只证明相应逻辑与原生采样子链路，不扩大为所有生命周期已验收。空间预警、目录任务与其他持续管理能力逐步补齐。
