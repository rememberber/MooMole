# 空间分析结果校验

2026-10-23，阶段 117。验证固定 Mole 1.59.1 的显式目录 JSON，再交给空间图、列表和导航；不从终端文案获取项目，不增加文件处理能力。

## 可展示结果

依据固定源码 `cmd/analyze/json.go:performDirectoryScanForJSON/jsonEntriesFromDirEntries`：根路径、总量、扫描状态和直接子项列表必须存在。原生端还要求返回路径与本次已经规范化、实际传给引擎的目录完全一致；不把概览 JSON 的跨位置条目当成该目录直接子项。原生验证在添加客户端读取来源、保存任务结果和发出事件之前完成。

每个直接子项必须带名称、字面路径、整数大小、布尔文件夹标记及已知扫描状态。路径必须是根下的直接子项，同份路径不得重复；绝对路径不含 NUL、空段或点段，名称不含斜杠。名称匹配路径末段或固定 `scanner.go` 的符号链接显示写法“末段 + 空格 + →”；实际名称本身含箭头也按精确字面匹配，不用显示装饰推断文件身份、链接目标或权限。Unicode、换行、空格、通配符和 Shell 字面字符允许作为真实名称展示，不运行或展开。路径最多 4096 UTF-8 字节、显示名称最多 1024 字节，未知扫描状态或字段类型拒绝整份结果。

大小允许零和 -1 未知哨兵，其他值须为非负且不超过 JavaScript 安全整数；保留 complete/partial/unavailable 的原值，不因数值存在或校验通过就认为完整测量。可选总文件数须为非负安全整数，不与目录项数量或大小强行求和对账。可选 overview 如有提供必须为 false。客户端来源记录仍沿用已有独立校验，无法识别时显示读取时间/来源未知。

直接子项最多 20000 个，超过后整份拒绝并建议缩小目录，不截成“扫描完成”的部分列表；前端列表仍每页 100 项。可选大文件容器允许缺失/null/数组，上限 1000 条；其中的逐条无效记录、未知大小与范围外线索继续沿用既有只读展示和操作禁用，未在本阶段改成完整大文件协议或全量发现保证。上游正常最多 20 条，上限是客户端兼容预算，不表示已发现 1000 个文件。

## 失败与接回

原生校验失败按已有任务失败流程记录；前端还对事件和任务快照经过同一核心校验，防止残留/异常载荷进入界面。原生成功但客户端无法展示时，沿用“分析结果未能显示”，保留任务身份与成功终态，不假装取消或仍在运行，也不改写历史状态。

失败不替换上次结果、筛选、选中项或导航分支；提供原请求目录的重新分析和操作历史入口。重载接回经过相同校验，不为修复展示自动重启旧任务。核心格式异常先显示中文说明与下一步，固定字段诊断放入默认折叠的“查看格式诊断”，新任务恢复折叠；原始错误仍保留在任务记录，未识别的其他错误不按此规则截断。超项数直接建议选更小目录。没有旧结果时保持原空状态，不发布半份新清单。

## 验证与剩余范围

TypeScript/Rust 共用字段接受/拒绝语料，另覆盖必填字段、重复路径、根绑定、UTF-8 长度、数组边界、特殊名称、真零/未知，以及客户端成功结果不可展示的分类。浏览器覆盖保留旧结果/筛选/选中/导航、有效重试、重载接回、异常容器和最小窗口浅深色错误状态；原生只用自建目录验证正常输出、空文件与特殊名称、下钻及返回。

这是空间分析核心字段的第一道运行时校验。其他模块、可选大文件逐项协议、全部未知附加字段、协议版本迁移及系统故障矩阵仍待完成。原有输出 32 MiB 限额、临时结果缓存限额及分页继续生效，但本次数组/字段上限不等于完整解析峰值内存、事件积压或大目录性能验收；拒绝发生在引擎输出之后，未限制引擎扫描自身的资源消耗。详情见 [开发记录](development.md) 和 [发布路线图](release-roadmap.md)。
