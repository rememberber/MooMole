# 空间分析：图表与分页查阅

2026-10-17。使用固定 Mole 1.59.1 的显式目录 `analyze-go --json PATH`，继续只读；没有增加移动、删除或清理入口。

## 用户流程

先查看当前目录的已测量占用、直接子项数量及扫描状态。按名称或路径搜索，筛选文件夹、文件、无法测量项，按已测量占用降序或名称排序。无法测量项在大小排序中置于已知值之后，不把载荷中的占位大小当作可信占用。

结果摘要显示本次读取完成时间、用时和“缓存使用情况未知”。这不是每个项目的原始测量时间；已有结果在重新分析期间保留原时间，失败或取消不会变成新结果。整份返回清单的完整测量、部分测量与无法测量/未知数量始终可见，不随筛选或分页缩小；有未完整测量子项时提示先查阅对应项目，未知大小不代表零。

空间图比较当前筛选范围中已测量的正值项目，最多单列 12 项，其余合并绘制。点击图块显示完整路径、大小及部分测量说明，并定位到对应列表页和行；从列表的详情入口也能选中同一项目。选中后可明确选择继续分析该文件夹或请求 Finder 定位；点击图块本身不触发新扫描。键盘可操作图块，选中详情取得焦点。

无法测量项与测量为零的项目不占图块，但仍在列表中。部分扫描的零值不表示目录为空。小图块可能放不下文字，因此按钮保留完整可访问名称/路径提示，合并数量也显示在图外说明中，不为可读性放大面积或补造未知大小。

列表每页 100 项，支持上一页/下一页，可查看第 201 项以后。分页时列表滚动位置复位并取得焦点；筛选/排序变化重置页码和选中详情，较短的新结果会限制到有效页码。同目录成功刷新会清除旧选中详情；首次进入新目录采用默认筛选，返回已访问目录时可恢复查阅上下文，选中路径仅绑定当次新结果。

## 独立大文件视图

“目录内容 / 大文件”切换按钮将两份结果分开展示：大文件直接使用同次分析 JSON 的 `large_files`，不从目录聚合占用猜测文件，也不触发另一轮扫描。文件可能位于子目录中，完整路径直接可见，同名文件按路径分别查阅，不合并或汇总成可释放空间。

支持名称/路径搜索、按扩展名分类、最小报告大小（全部返回项、至少 100 MiB、至少 1 GiB）及大小/名称排序；仅筛选已经返回的记录，不改变 Mole 发现阈值或扫描范围。类型取路径最后一段扩展名，不读取内容、不确认真实格式；未知大小不当作零，在大小排序中排后，正值阈值筛选不包含未知大小。没有过滤时仍能看到明确零值。每页最多 20 条，较短新结果限制到有效页码。

“分析所在目录”沿用现有分析任务和导航历史；“在 Finder 中显示”沿用原生定位接口。操作前检查字面路径是否处于本次目录范围内，拒绝相似前缀、相对路径、点路径段和 NUL；范围不符的原值仍显示但禁用路径操作。这个检查不是文件身份或处理权限证明，原生接口仍验证当前路径；没有增加删除、移动或清理入口。

刷新任务期间保留旧视图和结果，禁止新的所在目录分析；失败/取消保留结果与筛选。同目录成功刷新更新记录并保留筛选，首次进入新目录默认回到目录内容；切换结果视图保留两份列表各自的筛选、分页和列表滚动。返回已访问目录或从其他功能页回来会恢复会话上下文，不写入持久化存储。此处不缓存多份分析结果。

固定 Mole `constants.go` 的 `maxLargeFiles=20`；`scanner.go:scanPathConcurrentWithLimiter` 从 1 MiB 开始维护有界堆，扫描子目录时可能复用缓存。根层可能调用 `findLargeFilesWithSpotlight`（逻辑大小查询阈值 100 MiB、结果再取实际占用），只在其记录数更多时替换原列表，不合并两份列表。上游按扩展名、折叠目录等规则跳过部分内容，没有给每条大文件提供独立完整性、缓存/Spotlight 来源或原始测量时间。

因此即使目录状态为完整，大文件列表也不保证完整。`large_files` 因 `omitempty` 可能省略：界面如实显示“未提供”和返回数量未知，不据此推断没有大文件；显式空数组、格式无法识别和筛选无匹配分别说明。部分目录扫描仍直接提示可能遗漏内容；缓存、硬链接、APFS 共享块及云端占位的度量边界继续适用。

## 目录导航

顶部工具栏提供返回、前进、上一级、路径输入及目录选择。根据用户后续澄清，结果摘要保留可点击的路径面包屑，可直接分析祖先目录；不展示重复页面名称的全局面包屑。图标按钮保留可访问名称和完整目标路径提示。结果摘要绑定成功返回的实际路径，便于在输入待扫描路径、失败或查看旧结果时辨认当前数据范围。上一级、面包屑、输入路径、目录选择、列表/详情下钻都在成功后统一登记访问。

### 扫描过程与取消

分析页在内容开始处显示本次请求目录、启动/等待/取消请求状态和不确定进度。请求目录绑定提交时的参数或接回任务的历史路径，输入框后续编辑不改变任务目标；历史未记录目录时显示未知，不拿输入框或旧结果路径补写。固定 Mole 仅返回最终 JSON，没有可靠完成比例或剩余时间，界面不显示百分比，也不从日志猜测正在处理的文件。

取消操作位于顶部固定工具栏，滚动查阅旧结果时仍可操作；离开分析页后沿用全局任务提示及取消入口。仅发出取消请求不表示任务已停止，界面等待结构化终态；若任务先成功，仍接受成功结果。取消请求失败继续跟踪并允许再次请求；已经结束的旧请求迟到失败不会污染新任务。

已取消、失败、中断及结果未保留均保留上次成功结果，不覆盖其路径、来源时间或查阅偏好。确认终态后提供“重新分析此目录”，绑定原请求和原返回/前进意图，而非当前编辑框；只有用户主动点击才重试。成功后移除任务提示并显示新结果，部分/未知测量仍沿用结果本身的说明。

状态来自匹配任务 ID/种类的结构化终态，不靠错误文案判断取消。状态查询失败、观察超时或启动请求的交付无法确认时显示待确认，提示从历史继续跟踪，不提供直接重试按钮，也不将停止观察说成停止本机任务。终态提示可关闭；关闭只隐藏说明，不清除结果或历史。原生进程退出及取消边界仍遵循 [进程生命周期](process-lifecycle.md)，状态恢复见 [任务跟踪](task-observation.md)。

返回和前进重新调用 Mole 分析目标，不重放旧的结果数组；Mole 自身仍可能复用缓存，不表示绕过缓存或保证实时。任务进行中禁用导航，并继续明确显示旧结果。失败或取消不移动游标、不覆盖当前结果，也不丢弃前进分支；从返回位置成功访问新目录后才截断旧分支。同路径刷新不新增重复访问；实际规范路径变化时采用返回值，不能把旧路径字符串当作持续有效的文件系统身份。

导航只在当前 App 会话内保存最近 32 次成功访问的路径和游标，切换功能页面后仍保留，重载/重启不持久化。接回运行中的任务时，从实际接收的成功结果开始登记。任务意图绑定当次请求，不增加 IPC 或自动重试、自动扩大扫描范围。

### 会话查阅上下文

离开分析页或成功接收另一份分析结果前，从当前仍挂载的界面捕获最新查阅状态，包括任务等待期间的用户调整。按实际返回目录路径保存：目录/大文件视图，各自搜索、类型、排序、页码及列表滚动；大文件还保留最小报告大小，目录详情仅保存选中路径，另记录页面滚动位置。重复路径共用最近一次上下文，不为每次重复访问另存副本。

上下文最多 32 份，历史截断前进分支或淘汰路径后会移除不再保留的上下文。只保存界面偏好和路径，不保存旧的文件数组、大小、状态、身份、权限或执行判断。恢复的是当前会话视图，重载和重启仍清空，不新增 SQLite、IPC、自动扫描或修改行为。

返回/前进重新调用 Mole 后，按新结果恢复上下文；其他方式重新访问仍在历史中的同一路径也可恢复。页码限制到有效范围；选中路径必须仍出现在本次结果和当前筛选中，否则取消选中并明确提示，不能据此断言文件已删除。若排序改变位置，选中路径定位到它在新列表中的页。路径相同不证明仍是同一文件对象，恢复详情也不构成任何处理授权。

列表与页面滚动按新布局尽力恢复，结果缩短时由有效页和浏览器滚动范围限制；不保证原像素对应同一文件。恢复历史选中项不会主动抢焦点或重放旧的详情滚动，用户新点击图块/详情仍沿用原焦点行为。同目录显式刷新继续清除旧选中详情，保留筛选与当前有效页；如果恢复历史任务失败或取消，则当前上下文与前进分支继续保留。

## 读取时间与来源

Rust 在完成引擎完整性与版本检查后、调用显式目录分析前记录本机开始时间，成功读取并验证 JSON 后记录完成时间；用单调时钟测量耗时，包含本次引擎调用、输出读取及解析，不包含先前的引擎完整性检查。时间使用 Unix 毫秒并在界面按本机时区显示，单调耗时不依赖系统时钟先后顺序。

客户端在结果中附加独立的 `mooObservation` v1：来源 `mole-directory-json`、开始/完成时间、`elapsedMs`、已验证的引擎版本和固定修订，以及 `cacheUse: unreported`。不改写上游 `scan_status`、大小或子项；非分析任务不附加这份记录。来源和完整修订保留在默认收起的“测量范围与图表说明”中。

固定源码 `json.go:jsonOutput` 不提供测量时间、缓存命中或缓存原始时间；`scanner.go:scanPathConcurrentWithOptions` 使用 `scanCacheReuse`，`scanSubdirWithCache` 可能返回磁盘缓存。因此缓存使用情况始终标为未知，不根据耗时、文件修改时间或 App 重读推断新鲜度，也不为刷新而删除/绕过上游缓存。

这份记录随同任务事件和原生短期结果缓存传递；重新接回任务保持原时间，不在前端使用接收时间重盖。没有新增 SQLite 列或持久化完整分析结果，结果淘汰后仍需重新检查。没有记录、未知版本或无法识别的来源/时间字段显示“读取时间未记录”和来源待确认，不套用当前首页版本冒充当时的引擎版本。浏览器演示数据也不虚构本机读取时间。

## 上游及度量边界

- 固定源码 `cmd/analyze/json.go:performDirectoryScanForJSON` 使用 `scanPathConcurrentAllEntries`；`scanner.go` 传入根层 `entryLimit=0`。前端分页解除的是自身的 200 项展示限制，不宣称发现上游未返回的项目。
- 目录内容使用现有 `entries`、`path`、`scan_status`、`total_size`，直接子目录包含内部聚合测量，不等同于递归文件清单；大文件视图独立展示 `large_files`，两份结果不相加。
- 完整性数量仅分类实际返回的直接子项；非法大小或未知状态归入未知，部分测量为零仍归入部分测量。根状态独立保留，不根据子项数量宣称扫描范围之外或未返回的内容完整。
- 图块面积按当前筛选下子项已测量值之和分配，不以目录总量或整盘容量作为百分比分母。根汇总与子项图表分别保留，不用差额推测“其他占用”或空闲空间。
- `partial` 使用 `+`，`unavailable`、未知状态及非法大小不参与绘图；明确零与无法测量分开。单项及总量仍沿用现有字节显示单位。
- 上游可能复用缓存，文件继续变化也会影响结果。图表不是实时或原子快照，不代表唯一物理占用、可释放空间或处理资格；APFS 克隆/硬链接/稀疏文件/快照、云端占位、跨卷和网络卷等完整验证仍待完成。

前端每页仅挂载最多 100 行，图表最多 13 块；完整结果仍由现有后端 JSON 协议接收，排序/筛选也处理整份子项数组。原有输出上限不因分页而扩大，完整的后端分页、内存及事件预算仍是后续任务。

## 验证与当前限制

几何单元测试检查面积比例、全图覆盖、无重叠和边界、合并权重与未知/零排除。浏览器测试覆盖 205 项分页、图表定位到第三页、键盘焦点、类型/路径筛选、部分/未知/零、特殊路径、根目录不可读、新观察清除旧详情，以及现有 App 接收任务结果与下钻回调。

组件和 transport fixture 均仅在浏览器内运行，不访问实际目录或用户数据库；路径回调不冒充真实扫描/Finder 验证。原生验证使用自建 206 项目录及其子目录，实际调用 Mole；图表/分页和导航的构建、验收与边界分别见开发记录第二十四、二十五阶段。

读取来源单元测试覆盖字段验证、未知/未来版本、时间异常与单调耗时独立性，完整性分类覆盖零值、部分、非法大小及未知状态。浏览器任务回归覆盖默认折叠、筛选不改变整份清单统计、失败/取消保留原时间、重新接回及新成功结果更新时间；原生验收记录见开发记录第二十六阶段。

大文件测试覆盖扩展名、特殊路径、未知/零/非法大小、字面范围、空/缺失/非法记录，以及 App 任务结果、搜索/筛选、准确路径操作、45 条隔离输入分页、短列表刷新、失败/取消和新目录切换。超过 20 条的输入仅验证前端稳健性，不作为固定 Mole 会返回更多记录的证据。原生使用自建 3 文件目录，实际 Mole 发现、所在目录与 Finder 验收见开发记录第二十七阶段。

上下文单元测试验证拷贝隔离、重复路径、32 份限制及历史分支清理；浏览器通过 App 任务接口验证新大小/未知状态、选中路径失效/重新排序、页码与滚动恢复、等待中的最新偏好、失败/取消和重载清空。对应原生验收见开发记录第二十八阶段。
