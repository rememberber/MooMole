# 从跨磁盘副本恢复原位置

跨磁盘移动记录已经保存副本、原件废纸篓与完整内容/元数据摘要。新增独立恢复流程：从其中确认完成的一项副本复制并核验回原位置，保留另一磁盘的副本与原废纸篓项目。它不重放原移动、不自动删除任何副本、不覆盖原位置，也不将原处理记录改写为恢复成功。

## 计划与真实恢复

只接受原运行 ID 与项目 ID，服务端读取原私有计划、已结束记录及可靠的 moved 项；部分/不确定批次必须先人工核对。缺少副本身份、内容摘要、元数据摘要或实际原件收据不提供确认。核对原计划的确切源/目标、大小和跨卷关系，再把整份计划与该项记录绑定到摘要。前端不能指定任意恢复源、目标或临时文件。

准备时真实读取当前副本，核对其原保存身份、完整内容和元数据摘要。原位置必须仍是原扫描记录中的物理目录及磁盘身份，属于本账户且未受保护、可写、没有不能核对的 ACL；原文件名必须空闲，不自动重建原目录或编号。挂载/目录变化、卷移除、同名占用、未知、云占位、共享硬链接、权限和保护变化均保留。启用的定期处理规则仍要求先暂停。

确认有效两分钟、一次性消费；准备、复制和复核都使用现有取消任务、文件检查槽及自更新/退出准入。副本内容核验在后台进行，不持有整个数据库锁。确认后重新读取原记录、设置、路径和副本，FULL 同步持久化复制意图，然后复用原跨卷描述符复制与独立摘要/元数据校验、排他发布到原文件名。每项最多 16 GiB，复制时限十五分钟。保留资源分支、权限、时间与扩展属性；隔离属性按现有系统形式核对，不删除或重写安全标记。

恢复结果另存确切收据和原记录引用，旧记录不改写。取消在发布前停止后续步骤；已发布的文件不能据停止请求自动撤回。意图后的错误或收据未完整写入为未知，保存原位置和临时路径供核对，重开不重放。本轮独立恢复记录最多 64 条，未知/中断需要人工核对才能继续本模块恢复；同时沿用共享执行记录准入。不自动清空废纸篓或整理旧副本。

## 原生证据与后续

使用一个新建且由本任务独占的 APFS 稀疏磁盘与内置盘，实际跨两个设备执行正式 Mole 保护下的自建文件移动，再调用生产恢复代码复制回原位置。数据、资源分支、隔离属性、自定义属性、另一磁盘副本、原废纸篓文件及未选文件均核对；原移动记录不变，新的可靠恢复收据可以关闭/重开。

同一实测还验证重名保留、保护变化、取消、过期、意图记录写入失败前不复制；恢复文件已经发布但最终记录被注入故障阻止时，重开保留未知而不重放，并阻断进一步自动恢复。证据在 `.cache/transfer-restoration-native.json`。两个普通回归和显式真实双卷测试均通过；自建磁盘仅用于样例验收，不涉及用户卷内容。

界面已接入跨磁盘移动历史的可靠 moved 项：“从副本恢复原位置…”显示保存的两端位置、大小和范围，重新检查后独立勾选确认，支持核验/复制阶段取消、结果、位置显示及独立恢复历史。准备与执行各自绑定请求 ID；运行中重载只读取与接回，不自动准备或执行。未知/中断需检查实际位置后单独记录核查，原结果不改成成功。页面打开不读取文件正文，点击恢复准备才读取选定副本。

8 项新增 WebKit 流程和既有移动/恢复 6 项回归均通过，包含 StrictMode 下准备只发送一次、960×780 确认布局、过期/错绑、两个阶段取消、结果不匹配不重试、未知核查和运行中接回。前端默认全量 224 项、Rust 默认全量 652 项通过（93 项显式忽略；新双卷实测已经单独主动运行）。中英日文案与确认截图已核对。

自建 APFS 映像按创建时文件 inode、映像路径、挂载点和物理设备身份核对后正常卸载并清理，未触碰其他挂载卷；状态保存在 `.cache/restore-owned-volume.json`。新实际 App 窗口目前缺少原生窗口控制工具，尚未验收，不以浏览器 IPC 夹具替代。

该路线从可靠副本恢复文件，原废纸篓的同卷取回、移除多余副本的再次选择、拔插后的卷身份衔接、其他文件系统、批量恢复/日志导出和实际 App 窗口仍在完整目标内。不能把两端数据保留的复制恢复称为原移动的原子回滚。
