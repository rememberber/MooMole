# 菜单栏持续管理

2026-10-30：在“持续管理”中明确保存“在菜单栏保留 MooMole，关闭窗口后继续运行”后，原生菜单栏提供最近容量、打开主窗口、进入空间趋势、单次记录当前空间及退出。设置默认关闭，未实际创建菜单栏时不改变关闭窗口行为。

容量来自已有的真实空间观察，菜单栏每三十秒读取本机记录，不另行扫描目录。定期采集是否开启、间隔与阈值仍由已有观察设置控制；打开菜单栏不默许开启采集。最近且未失败的容量显示在菜单栏，低于所选阈值时加提示；历史、时间回拨、未来样本或采集失败不显示即时容量数值或低空间告警。展开菜单仍可看历史记录与未知说明，进入持续管理查看记录时间。容量不等于实时值，低空间提示不触发文件处理。

启用且原生入口实际存在时，关闭主窗口改为隐藏，空间观察和已授权任务仍按原有规则运行；可从菜单栏重新显示窗口，Dock 的重新打开事件也会显示现有窗口，不创建第二实例。隐藏时停止高频系统状态观察。菜单栏“退出”沿用现有取消、有限等待及中断对账流程，不能把仍在执行的原生文件操作判作完成。未添加登录项、常驻 helper、系统通知权限、退出后的观察或自动文件处理。

设置保存在独立可选 `menu_bar_preferences` 表，不修改既有空间采集设置、样本和执行历史。未知版本、过大或无法读取的设置不覆盖、不启用；启动时没有可靠菜单栏入口便保留普通关闭行为。保存后原生创建失败会显示“未显示”和错误，不以偏好为真冒充已存在的入口。配置变更和后台刷新串行，避免旧刷新重新打开刚关闭的菜单栏；菜单回调只注册一次，反复开关不积累操作回调。

使用 [Tauri 原生菜单栏 API](https://v2.tauri.app/learn/system-tray/)，没有增加前端 Shell 或文件权限。原生菜单及新设置提供中、英、日文；模板图标由本项目像素代码生成。界面重载只读取偏好，不重新保存或发起采集。

基本回归覆盖默认关闭、首次使用确认、保存与重开、关闭不改变采集、个人样例文件保留、未来版本不覆盖，以及历史/失败/时间回拨的容量展示。页面验证明确保存、重载不重新提交、原生创建失败不声称成功及未知状态禁用。这里的页面传输模拟不代表真实菜单点击。

当前 Mac 锁屏，菜单栏实际显示/点击、主窗口隐藏/重新打开、退出取消和完整睡眠/重启周期仍待原生窗口验收；不将此节点计为完整生命周期已验收。后续已补 [目录定期扫描](folder-schedules.md) 的首条流程；系统通知和明确配置的定期处理仍待推进。
