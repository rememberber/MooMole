# 整理本机执行归档副本

执行归档原有只读查看、导入和导出继续保留。新增单份副本管理：在一份已验证的归档中选择“导出后整理本机副本…”，先由系统保存窗口指定应用数据目录以外的完整副本；成功保存并读回核对后，显示本机/导出两处路径和文件大小，再单独勾选确认，将这一份本机受管归档移入废纸篓。不是删除原执行所处理的文件，也不删除活动 SQLite 历史、其他归档或导出证据。

不会清空废纸篓或承诺立即释放空间。同盘导出会暂时增加占用；希望迁出本机时由用户明确选择外接位置。保存窗口操作会创建用户选择的持久导出文件；取消检查、关闭页面、过期或后续处理失败也保留已明确保存的副本，不以清理临时文件为由删除用户输出。重新打开导出文件使用既有只读导入路线，可能再次产生受管副本，不恢复执行权限。

## 证据和执行边界

后端目标仅来自固定 `execution-archives` 私有目录中的 UUID 归档名。准备命令只接收原归档 ID 和请求 ID，导出路径由系统窗口提供；执行只接收短期确认 ID，不接收任意删除路径。原归档和导出副本均验证完整归档结构、头/正文摘要、字节总摘要、文件/祖先身份、账户所有权/单链接/已落地状态及当前用户保护，副本必须独立且位于本应用数据目录以外。既有导出器不覆盖已有文件，临时发布文件自动清理。

最多保留一份内存确认，两分钟到期、单次消费，关闭/退出不恢复授权。共享归档槽、安装互斥与独占任务登记保持到实际 worker 返回；三十秒只是调用等待上限，系统读取和系统文件窗口可能仍未结束，不释放仍占用的资源或自动重试。

修改前以 FULL SQLite 写入独立意图；使用既有确切文件对象引用的原生废纸篓构件，最终门槛再次核对两份文件与保护。该能力只管理本应用明确选定的内部归档，不授予个人文件或其他 App 数据绕过 Mole 规则的清理许可。API 返回真实位置和身份收据；处理后再次核对导出副本。检查不是文件锁，无法阻止其他程序在剩余窗口修改文件；缺失收据、原生错误、后验失败或完成记账丢失保留未知，不自动重试或猜测成功。

独立结果最多 64 条，每条上限 32 KiB。重开将未结束记录对账为未知，不重放；进行中/未核查未知会阻止新的副本整理。用户可核查本机、导出和废纸篓后记录人工核查，原未知状态保持，不改写为成功。整理结果不从归档文件反向导入活动执行权限。

## 验证与未完成范围

三项默认后端测试通过：独立完整导出、源/副本变化和保护/有效期拒绝、不覆盖已有输出、取消与意图写入失败保留、重开未知与不重放。显式原生验收另真实处理两份各自独立的自建归档，分别验证可靠完成和实际移入后的完成写入丢失；导出副本、其他自建原文件和原归档内容保持，数据库重开分别得到 moved/unknown。只凭各自确切 inode/device/摘要收据取回自建归档后清理临时根，未清空废纸篓或操作真实用户历史。原生结果保留为精简证据，收尾并入 `.cache/verification/native-evidence.json`。

界面已接入单份归档入口、正文容量合计、系统保存请求、两处完整路径与大小核对、独立确认、过期/停止、持久结果、未知人工核查和进行中请求接回。一次执行请求发出后撤下该页面的旧操作入口，不把返回或刷新变成重新执行；关闭时撤销尚未消费的确认，已保存导出文件仍保留。

默认后端全量 692 项通过、106 项显式忽略；原生正常/完成丢失验收已另行主动运行。前端全量 253 项及构建、类型和语言检查通过。新增 10 项与原有归档 4 项 WebKit 流程共 14 项通过，涵盖真实页面入口、准备零自动执行、保存窗口取消/过期/错绑、两个阶段确切停止、独立确认、未知核查、运行接回、中英日与原路径保持。两份真实后端 moved/unknown 结果均通过正式 TypeScript 协议解析器；960×780 中英日确认窗截图已核对，无横向溢出。这些页面测试使用传输夹具，不算打包 App 系统保存窗口验收。

实际打包 App 的系统保存窗口和副本整理链路、真实用户大归档/更多卷、完整取消/断电矩阵、整理结果的便携归档、旧版应用包容量管理及其他日志容量维护继续属于完整目标。本节点不视为全部恢复与持续管理完成。
