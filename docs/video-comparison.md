# 视频并排对比

这是视频人工比较与选择的第一条流程，继续包含在重复/相似文件的完整目标中；不把人工选择称为自动视频相似检测。

## 原生媒体会话

从同一保留扫描的确切 2–4 个项目 ID 准备视频对比。服务端不接收任意文件路径或媒体 URL，不重新枚举目录；只接受已支持的本地完整 MP4/M4V/MOV。沿用原有容器结构、保护、单链接/所有权、路径与祖先身份、来源绑定、当前扫描和时效检查，不启动样例应用、外部播放器或后台转码。

媒体 store 从单个能力改为最多四个能力的一次会话。整个组准备成功并逐项再次授权后才发布地址；只有属于当前单调递增代次的结果可以提交。关闭会话、替换、过期、超时、迟到结果和旧组件的清理都不会重启播放，也不能撤销一个不同的新会话。旧的单文件预览仍替换前一个会话；按单项关闭只撤销相应媒体，不影响其他成员。

GET/HEAD 仍通过确切来源和随机短期能力、每次读取前后核对、单段 Range 每次最多 2 MiB、最多两个并发原生读取 worker。准备最多一个 worker、总等待八秒；超时仍持有检查槽直到实际只读调用返回。不授予任意路径读取、变更或文件处理权限。

## 实际操作与验证

同一轮自建 H.264 样例实际建立多个独立能力，读取指定字节范围并核对原字节；四成员、数量/重复 ID、代次替换、旧清理不影响新会话、到期、保护、内容变化和既有音频/容器回归通过。

显式原生测试从两份自建 H.264 文件的当前扫描准备媒体能力，然后以确切 ID 另行生成移动确认，通过正式 Mole 路径规则和原生文件执行器移动一个样例，核对另一个保持原字节、移动收据内容一致、旧路径不再读取，以及 SQLite 关闭/重开结果。证据为 `.cache/video-comparison-native.json`。它是原生文件与媒体能力证据，不是 App 窗口播放验收；不使用用户视频。

## 页面流程

文件整理、重复文件和支持的软件内容结果中，可逐项“加入视频对比”，最多四段；对比清单独立于处理勾选。满两段才可打开对比。界面先显示实际首帧，不自动播放；可以一起播放、全部暂停、共同定位或使用各自播放器控件。共同定位以最短时长为限，不承诺逐帧同步。默认全部静音，可切换只听一段，显示路径、逻辑大小、像素和时长；未知画面/时长或一段播放失败会停止整组。

对比内默认零处理选择，取消不改变原列表；明确“将选择带回文件列表”才合并这几段的选择，其他项目保持。总数仍最多 20 项，重复组仍必须至少保留一份；保护变化或扫描失效拒绝衔接。这个选择不是删除/移动计划，用户仍须另行点击移动、归档或废纸篓，再经过独立确认和原执行验证。不以对比会话取代内容摘要或保留副本的约束。

关闭、刷新扫描、换目录、过期或错误会停止播放器、移除来源并撤销本会话。迟到结果只撤销所属会话，组件重建不会撤销另一个新会话。过期除墙上时间还受前端单调时间限制。中英日文案与 960×780 的两列四段布局已检查，内部可滚动，无横向溢出。

验证：新增 5 项 WebKit 页面测试使用真实自建 H.264 字节，确认实际时间推进、暂停、共同定位、独立静音、首帧、默认零选择、取消、错绑、迟到、到期和列表到独立确认；既有影音、个人文件与相似照片共 11 项回归亦通过。前端全量 221 项、Rust 默认全量 650 项通过（92 项显式忽略），其中新的真实双视频读取到移动收据测试已另行主动运行，并非用忽略代替通过。

打包 App 的原生并排窗口、系统协议实际多播放器/声音及完整生命周期仍待验收；当前工具没有原生窗口控制能力，不把浏览器传输夹具当作该证据。自动相似视频发现/特征/分组、完整编码矩阵、RAW/Live Photos/连拍和照片图库仍在完整目标内。

2026-11-01：[自动视频候选](video-candidates.md)已接入同一并排播放器，可从候选组或确切所选 ID 发起。新增 similarPhotos 领域的类型准入，仍只使用当前保留扫描，不接受任意路径；选择仍须带回列表并单独确认，至少保留一份。此节点的自动候选是三个位置的采样线索，不表示本并排播放器自动证明视频相同。
