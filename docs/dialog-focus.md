# 弹窗关闭与键盘焦点

2026-10-23，阶段 115。减少关闭弹窗后重新寻找位置的操作，不增加可见导航或快捷键标签。

## 返回位置

- 从侧栏打开设置，关闭后返回“设置”；从清理页打开保护列表，返回原入口。即使系统点击按钮时没有先把焦点放到按钮上，也记住实际点击的入口。
- 在输入框等位置用 ⌘, 打开设置，关闭后返回原位置；在设置内切换分类或再次按快捷键，不用内部按钮覆盖最初入口。原入口被移除、隐藏或禁用时回到侧栏设置。
- 设置仍在加载或加载失败时，可沿用已有的取消/关闭操作，返回入口；较晚完成的模块不因此重新打开。异步返回只在页面尚未取得其他有效焦点时补位。
- 关闭逐项执行详情，返回原记录行。列表更新使记录消失时，回到“刷新记录”，该按钮不可用时回到执行记录分组。读取失败、重试或正在跟踪不改变原入口，不重新运行任务。
- 客户端检查任务已有的原行/搜索框返回逻辑继续生效。

## 公共弹窗

公共 Modal 在布局清理阶段关闭原生 dialog，随后 React 再移除节点，使焦点返回能在原生弹窗仍存在时完成。未指定入口的调用者沿用打开前的有效焦点；指定入口可提供当前可用的回退位置。

仅返回仍属于当前文档、已连接、可见、未禁用且不受 hidden/inert 或其他模态范围阻隔的位置，使用 preventScroll，避免额外跳动。关闭时若焦点已进入另一弹窗，不主动把它拉回旧入口。嵌套弹窗的 cancel 事件不继续传播到外层，Esc 只关闭当前层。没有提供关闭行为的必读说明仍不能用 Esc 或背景绕过。

这些改动不扩大确认、执行、取消或历史权限，也不改变日志处理的记录及停止后续项语义。完整 VoiceOver、所有审阅入口、系统保存窗口和真实加载故障组合仍需按 [发布路线图](release-roadmap.md) 验收。

## 验证

浏览器使用实际 App 与隔离 StrictMode 组件，覆盖 macOS 式点击不聚焦、设置快捷键/分类、保护入口、延迟加载取消/失败/迟到、嵌套 Esc、弹窗替换、隐藏/禁用/移除入口、必读说明和执行详情成功/失败/行移除。相关设置保留、任务历史、执行跟踪/接回、日志确认、维护、诊断保存及延迟视图回归保持通过。

原生构建路径与 macOS 焦点复核证据见 [开发记录](development.md)。本轮不向用户数据库注入假执行记录，也不通过真实清理或变更设置制造测试场景。
