# 客户端检查任务历史

2026-10-17。操作历史页提供客户端检查任务的搜索、状态筛选和只读详情，查阅本身沿用已有 SQLite 记录与状态查询；诊断摘要生成/保存另有专用 IPC，不新增数据库字段。

## 查阅范围

- 后端按开始时间倒序返回最多最近 200 条记录，界面每次展示 50 条；搜索和筛选只作用于已返回记录，不代表全部保留历史。
- 搜索匹配任务 ID、原始及中文类型/状态、完整目录和诊断；按字面匹配，不将路径中的特殊字符解释为正则或命令。状态筛选保留未知状态入口。
- 刷新读取记录，不启动检查；失败保留当前记录和筛选，明确显示读取错误。新任务接受和终态刷新仍沿用 App 原有的请求代次保护。
- 保留期限沿用设置中的 7/30/90 天；启动及保存设置时清理过期记录。当前没有新增清除或跨 200 条查询能力。
- 设置写入与该次记录回收共用事务，失败回滚；保存后读取失败与保存失败分开提示。活动任务与执行凭证的保留例外、数量限制见 [本地记录保留](local-data-retention.md)。

## 详情与状态

点击任务行或用键盘打开详情，展示类型、状态、完整原始目录、起止时间、记录用时和诊断。ID、原始类型/状态及 SQLite 来源按需展开。未知类型/状态保留原值；非法、缺失或倒退的时间显示未知，零用时仍为零。记录用时仅为数据库起止时间差，不等于引擎测量耗时，不用当前引擎版本补写历史来源。

打开详情只保留选中 ID，每次从最新列表中查找记录；任务完成后详情同步终态。记录移出当前列表时说明可能超出保留期或最近 200 条范围，不继续展示过时副本，也不据此声称记录已被删除。关闭详情后焦点返回原任务行；原行已消失则返回搜索框。

只有已支持类型的运行中记录提供“继续跟踪”，已有前台跟踪时禁用；沿用既有任务查询接回，不重新启动、自动重试或重放任务。历史状态本身不能证明任务仍在运行，以接回后的实际查询为准。见 [任务跟踪](task-observation.md)。

## 证据边界

这里是客户端检查元数据，和 Mole 原始历史、逐项执行收据分别展示。客户端任务的成功状态不代表清理、释放空间或恢复成功，诊断文案也不用于决定删除对象。

本记录不包含旧扫描结果；已有清理扫描/审阅计划的独立保留规则继续生效。临时任务结果仍受进程内缓存期限和容量约束，不因打开历史而持久化或重新生成。详情没有删除、恢复或再次执行入口。现提供固定字段的 [诊断摘要导出](diagnostic-export.md)，原始诊断不进入摘要。完整执行记录验收、其他来源的脱敏导出及未来修改任务仍按 [发布路线图](release-roadmap.md) 推进。
