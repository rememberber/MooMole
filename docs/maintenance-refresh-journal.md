## 固定范围和会话

仅记录 [Quick Look 两步刷新](maintenance-quicklook.md)，允许按上游顺序选择其中一步或两步，不接受其他任务/命令/目录。快照固定 `cache_refresh`、引擎提交、计划和确认 UUID、保护上下文摘要、完整步骤选择及原始 30 秒内的确认期限；使用 SHA-256 核对记录完整性，不保存偏好值或任意原始文件内容。

`Selection` 构造器只服务封闭执行器，本身不证明用户确认或规则已通过。只有 `begin` 成功提交才产生内存 `Session`，并绑定原请求 UUID、计划和快照摘要；同一请求或计划不能重复创建批次。历史解码不会返回 `Session`，不能恢复执行或续期确认。实际命令仍必须经过最新保护、原始确认、任务/更新租约及已提交意图的最终检查。

两步各自记录事件和结果，不用一个“维护完成”覆盖部分事实：

| 步骤状态 | 含义 |
| --- | --- |
| `pending` | 已选择，未提交该步意图 |
| `intent` | FULL 意图已提交，尚无可靠结果；不能据此断言命令已启动或未启动 |
| `commandSucceeded` | 拥有的系统命令正常零退出，仅表示命令返回成功 |
| `notStarted` / `cancelled` | 目标核心明确未启动，或后续步骤因拒绝/取消/中断未开始 |
| `uncertain` | 命令启动后的失败/停止，或意图后缺少可靠结果；禁止自动重试 |

开始第二步必须先有第一步明确成功；未知结果停止本次后续步骤。意图写入和对应事件处于同一 `BEGIN IMMEDIATE` / SQLite FULL 事务；事件写入失败会回滚步骤状态。结果写入同样原子，失败则保留意图，不能把批次结束成“没有改动”。结果即使在确认过期或墙钟回退后到达，也要按实际事实收集；事件顺序用 `seq`，新调用仍须有效确认。

批次区分完成、部分完成、无改动、取消、待核实和中断，并返回成功/未知/未启动计数。迟到取消不覆盖已经保存的成功；第一步成功后取消，第二步保持取消，第一步仍成功。缓存由系统重建，没有原缓存备份或统一撤销接口，不保证预览已修复、系统全部后台工作已结束或性能提高。

## 重启、容量和数据升级

- 启动对账把遗留 `pending` 变为未启动、`intent` 变为待核实，已保存的逐步终态保持；不调用命令、不自动继续后续步骤。运行时故障对账只允许在 worker 已完全结束/展开后调用，不能放弃尚在执行的命令。
- 与清理和卸载共享 64 批次 / 64 MiB 预留预算；事务检查其他模块的运行/未知状态。维护运行、意图或未核查的未知记录阻止新修改，独立连接不能绕过该准入。运行中的维护记录阻止更新前数据交接；运行时任务注册表和 worker/更新租约已由专属执行器接入。
- 仅对过期且已知终态或已明确核查的记录应用保留期限，先在同一事务核对全部候选的快照、步骤、事件与核查，再删除；未核查的中断、意图、未知或损坏证据保留。维护记录不依赖清理扫描外键。设置保存及所有模块保留处理保持一个事务，维护异常不会只保存部分新设置或清掉其他候选。
- v1–v5 升级前使用 `VACUUM INTO` 生成 `moomole-before-v6-<UUID>.sqlite`，包含已提交 WAL；按原版本补建维护表和独立核查表，版本变更同一事务完成。备份失败停止，结构冲突完整回滚，已升级库不重复备份。旧卸载、清理和用户设置不重建、不丢弃。
- 未知记录可在原 worker 结束后，由用户核对并明确记录已核查；独立 `maintenance_reviews` 绑定原快照 SHA-256 和核查时间，只解除该记录对新修改的准入阻塞，原未知/中断事实保持。错误摘要、活动 worker 或损坏核查不能放行；不得删除证据、篡改步骤为成功或自动重跑来解锁。

## 验证和剩余工作

普通测试覆盖两步顺序/一次性、逐步成功和取消、未知/过期/时间变化、意图与结果事件故障、独立连接、跨模块准入、容量、保留及设置回滚、事件顺序损坏。另使用真实独立测试进程，在 pending、首步 intent、两步之间、第二步 intent、全部结果已提交五处 SIGKILL 后重开数据库；已完成事实保持，未开始/未知分开，第二次重开不改写结果。

这些子进程只操作私有测试库，已完成命令结果是记录层 fixture，**没有实际刷新系统缓存**。v4 WAL 升级测试另外保存设置和卸载 intent，验证备份保持原 v4/intent、新库对账为 uncertain，重开不重复备份；v5 WAL 维护 intent 到 v6 的升级测试也保留旧快照/事件。结构冲突、备份失败和未来版本测试继续验证迁移保护。实际 v4 用户库升级及正常维护记录重启核对另见 [桌面执行证据](maintenance-execution.md)。

固定选择、规则/保护、一次确认、封闭 worker、实际命令与记录、人工核查及桌面入口已串联。下一步补齐实际 App 的取消、执行中退出/中断和重建边界；不以本层测试替代这些验收。
