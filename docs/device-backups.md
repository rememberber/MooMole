# 设备备份管理

2026-10-30：空间分析工具栏新增“设备备份…”，接通本机 iPhone/iPad 备份及用户选择的备份副本目录、设备与状态说明、整份审阅、真实移入系统废纸篓、停止任务和独立持久历史。默认不扫描、不选择、不处理；这是设备备份管理的首条主流程，不代表已完成全部备份、云空间与系统数据管理。

## 用户流程

1. “扫描本机备份”检查当前账户的 `Library/Application Support/MobileSync/Backup`；“选择备份副本目录…”通过系统选择器检查所选目录的直属备份。不会创建缺失目录、追随链接或修改系统备份配置。
2. 每份显示设备名称、目录位置、目录修改时间、逻辑大小、状态文件的完成标记与加密标记。未知、未完成、权限受限及其他格式保持可见并不能处理；列表不完整也不等同于没有其他备份。这里没有确认备份日期、可恢复性、唯一性或当前空闲，也不以大小或年龄建议删除。
3. 明确审阅一份备份，核对完整路径、独立副本需求、备份/同步任务已结束和恢复边界，再单独勾选确认。每次只处理一份完整目录，不提供内部文件的清理或拼接恢复。
4. 原生执行前重新检查当前保护、目录身份、状态清单、完整目录快照、权限与真实 Mole 路径规则；满足条件才向系统发出整目录 Trash 请求。默认不会运行 Finder/iTunes、断开设备、停止其他应用、请求管理员权限、解密内容、永久删除或清空废纸篓。
5. 结果保存到本入口的“处理历史”，列出原位置、实际返回收据与状态。移入废纸篓仍占原磁盘空间。停止在系统请求前保留原件；请求已发出后不能据取消承诺撤销。未知结果不自动重试，需要核对原位置、实际收据与废纸篓，并独立记录“已核对”；原未知状态保持。

Apple 的 [定位与管理备份说明](https://support.apple.com/en-ie/108809) 提供本机位置与 Finder 管理入口。本功能使用原生目录与 plist 数据模型；不通过 Finder 文案、Mole 终端文本或目录名称推断删除对象。[libimobiledevice 的原始备份实现](https://github.com/libimobiledevice/libimobiledevice/blob/master/tools/idevicebackup2.c) 可核对 `Info.plist`、`Status.plist` 和 `SnapshotState=finished` 的格式线索；**状态标记不是备份完整性验证，也不是正在使用状态的锁。**

## 识别、保护与预算

- 本机固定目录以外，只接受本账户拥有的普通物理本地副本目录；拒绝账户根目录（含相同物理身份的别名）、隐藏/系统/Library/应用与照片资料库位置。固定本机 MobileSync 目录是明确的独立来源，不放宽个人文件扫描的 Library 保护。
- 第一版要求三份可读 plist 字典、可识别的 `Device Name`、普通非空 `Manifest.db` 与完成状态。plist 支持 Foundation 的 XML/二进制格式，每份最多 16 MiB；不读取 Manifest.db 正文、不解析备份中的个人资料。未确认加密标记显示未知，不根据加密状态授予处理许可。旧 `Manifest.mbdb` 等其他格式继续保留。
- 每次最多显示 128 个直属项目；目录清单预算共五十万项、六十秒，最多六十四层。独立备份快照以元数据与名字形成摘要、累计普通文件逻辑大小，支持超过缓存目录一万项的规模；不把共享空间、压缩、克隆或废纸篓占用算作可释放量。极大或缓慢备份不能完整核对时保留，不从部分树生成处理许可。
- 使用持有目录描述符、相对 no-follow 枚举及逐级前后身份核对。链接、共享硬链接、特殊对象、云占位、跨设备后代、其他账户对象、隐藏来源、应用/资料库伪装与用户保护范围重叠时保留整份。所有后代都参与快照，而不是只比较备份根目录日期。
- 扫描可供选择十五分钟；确认三十秒、单次消费，同时检查单调时钟与墙钟。已开始的完整复查有独立预算，不把扫描快照或历史收据作为新修改许可。执行期间仍有外部程序写入的最后时刻竞争，不承诺跨进程原子快照或完整占用检查。
- 真实 Mole 路径级保护和白名单语义继续适用。白名单文件/缺失的物理状态绑定在规则复查和最终关口之间；首次 Mole 初始化造成印记变化时，只允许一次新的只读保护复查，不重试文件处理。此来源不伪装成用户缓存，也不把未运行的缓存模块或全局占用检查记作通过。

## 执行、历史与恢复边界

独立修订 `MooMole.device-backups.v1`，不改变已有个人文件/缓存/卸载历史格式。可取消工作登记到现有全局任务、更新安装准入与退出等待；原生工作返回之前保留工作槽和安装租约。页面读取和 WebView 重载只接回状态与记录，不补发扫描、确认或操作；App 重启后不重放计划。

SQLite 按需创建 `device_backup_runs`，FULL 同步，单条不超过 256 KiB、最多 64 条。修改开始也检查既有清理/卸载/维护的共享准入；本入口另有独立的记录容量及未知结果阻断，不自动删除收据腾出容量。整份计划、目录摘要和识别依据保存在本机，不保存备份正文或传给模型。

系统请求前持久记录意图；请求后根据实际返回位置、设备/inode、目录身份、原路径消失和持有目录下的内容摘要记录结果。无法完整核对、工作异常丢失或收据提交失败时保留未知，而不是宣称未发生；重开后的“已核对”只解除本入口的人工核查阻断，不把未知改为成功。备份记录目前独立保留，**尚未接入通用归档/导入/导出和容量释放流程**，达到 64 条会停止新的备份处理。

**本节点没有设备备份的应用内恢复。** 用户可在 Finder 按实际收据放回整份目录，原位置重名时不要覆盖；不应单独从废纸篓取回部分内部文件。移入后产生的新备份、同名冲突、其他卷、资料库格式及设备恢复可用性都需要独立核对，不能据收据承诺可恢复。
