## Mail 附件副本

来源来自固定 Mole `_clean_mail_downloads`：`~/Library/Mail Downloads` 与 `~/Library/Containers/com.apple.mail/Data/Library/Mail Downloads`。原生扫描绑定账户、目录及祖先身份；仅普通本地单链接文件进入候选，排除正文后缀、图库/应用包、链接、保护与云占位。沿用默认旧文件门槛（超过三十个完整天数）及五 MiB 目录门槛；五 MiB 仅取已核对文件分配量的下界，不把未读范围当零。

现代 Mail 容器位置实际命中当前 Mole `should_protect_path` 的 Apple 数据保护。因此该来源明确标为仅预览，所有处理选择禁用，服务端也不生成确认；不修改 Mole 核心保护、不设置卸载模式绕过。旧目录可形成独立的结构化计划，单独确认后由既有原生废纸篓执行器处理；固定 `/usr/bin/pgrep -x Mail` 的退出状态复查 Mail，运行或未知时保留，不解析终端文案，不结束 Mail。

计划来源独立为 `softwareContent`，保存固定来源、根目录见证和测量下界，处理前核对账户、路径、年龄、保护和变化。使用正式 Mole 路径级规则、FULL 同步意图、逐项结果、取消/中断、实际收据和执行归档。只有此来源的精确目录放宽普通个人文件的 Library 限制，个人文件/重复/相似计划原有范围保持。

实现与验证边界：有界扫描、现代容器不可确认、旧目录选择、保护/目录变化及正文/数据库保留有基本自动化；浏览器验证来源页签、只读路径、现代位置仅预览、旧来源筛选及单独确认。早期真实原生样例首先命中现代位置核心保护，随后旧位置又被当时运行的真实 Mail（PID 1262）保护；样例保留且邮件数据库未改写。没有为验收退出用户的 Mail，早期全部 skipped 不作为成功处理证据。

2026-11-01 补验：确认实际 Mail 已不在运行后，显式执行 `real_mail_attachment_copy_uses_catalog_scope_and_preserves_mail_database` 通过。所有来源均在自动回收的系统 TempDir 内自建账户结构；旧目录中 40 天前的六 MiB 附件经过确切选择、独立计划、正式 Mole 和原生废纸篓实际处理一项，核对收据身份后仅取回该自建样例。近期文件及模拟 Envelope Index 字节保持原样，运行中保护没有绕过，也未结束任何用户程序。精简证据位于 `.cache/verification/native-evidence.json` 的 `software-mail-native.json` 条目。旧位置成功分支现已验证；真实 Mail 数据兼容性、实际 App 窗口/取消中断验收和更多附件来源继续待补，现代容器仍遵循既有保护。

其他软件附件、离线内容与真实附件成功执行继续推进；本节点不标记整个软件专项完成。附件可能包含唯一编辑副本，是否可重新下载未知，必须逐项确认。应用内恢复 Library 来源与更多格式预览仍待补充，当前保留实际收据供 Finder 核对。

## 浏览器下载记录

2026-10-31 已扩展标准浏览器与多配置选择，当前入口及边界见 [多浏览器下载整理](browser-downloads.md)。下文保留最初 Chrome 默认配置节点的实现与验收记录；不再将默认配置描述为当前唯一支持来源。

从本账户固定 `~/Library/Application Support/Google/Chrome/Default/History` 的 `downloads` 普通表读取完成状态且当前路径等于目标路径的记录，只据此定位文件，不遍历整个账户目录。当前只支持默认配置，其他配置、浏览器和离线内容尚待适配。下载记录只是来源线索，不证明文件未编辑、可重新下载或可以丢弃。

原 History 及存在的 WAL 以身份核验和有界读取复制到私有临时目录，所有 SQLite 打开、WAL 恢复及查询发生在副本；原文件从不作为 SQLite 连接打开。读取前后核对身份与变化，主文件上限 128 MiB、WAL 32 MiB、记录上限 2,000、总读取时间十秒；结构未知、变化、超限或取消均保留未知范围。临时副本正常退出自动清理；异常进程退出仍可能留下私有临时目录。仅读取下载记录列，不向页面返回浏览 URL，但临时副本含原数据库字节。

候选限定本账户同卷普通本地文件，排除隐藏/敏感路径、Library、应用/图库包、别名、硬链接、云占位和保护。默认不选；按确切来源和项目 ID 形成独立确认，真实废纸篓操作复用路径与身份复查、Mole 保护、持久意图、逐项结果、取消和历史。Chrome 历史、记录及数据库不修改；移走文件可能令浏览器中的原下载链接失效，实际文件及编辑内容需要用户审阅。应用内恢复此来源仍待补充。

验证：真实 SQLite WAL 样例验证完成/未完成/重复记录、未列入记录的文件与原数据库保留。显式原生样例通过正式 Mole 规则和实际废纸篓处理一个选定下载文件，核对真实收据、归档读取、原 History/WAL 字节和未列入记录文件均保持原样；测试仅按该收据取回自建文件用于清理样例，并非应用内恢复验收。浏览器页面回归覆盖来源、只读范围、预览、选择及单独确认。当前默认 Rust 测试 589 通过、78 忽略，前端 204 通过，相关浏览器流程 12 通过；arm64 ad-hoc App 构建及嵌套完整性检查通过。实际 App 新入口窗口、正式安装身份及其他浏览器仍待验收。

## 影音离线文件：VLC 本地播放列表

选择 VLC 导出的 UTF-8 M3U8 播放列表，按列表明确列出的本地音频/视频文件审阅、筛选和选择，再独立确认后真实移入废纸篓。来源依据 [VLC M3U/M3U8 导出实现](https://github.com/videolan/vlc/blob/master/modules/misc/playlist/m3u.c)：`#EXTM3U` 头、注释、file URL 和相对 URI；同时支持绝对本地路径，UTF-8 BOM 与 CRLF。只解析数据，不执行 `EXTVLCOPT` 或其他指令，不发网络请求，不递归扫描账户目录。

播放列表须为本账户普通目录中的本地单链接 `.m3u8` 文件，最多 2 MiB。只纳入本账户同卷的普通本地影音文件（按扩展名筛选，不保证实际格式或可播放），排除链接、硬链接、保护、敏感路径、Library、应用资料库及云占位。HLS `EXT-X-` 列表整体拒绝；网络地址、缺失/重复/未支持条目不推断为可清理，报告保持不完整。读取上限十秒、2,000 个条目、10,000 行及七 MiB 序列化候选。绑定确切来源、播放列表见证、账户及文件身份；执行边界复查播放列表和文件变化，变化则保留并要求重新扫描。

默认不选，取消选择播放列表不改变原来源，切换播放列表或来源撤销旧选择；不会把同一账户根目录下另一个来源的旧结果作为当前确认。沿用正式 Mole 路径保护、同步持久意图、取消/中断、逐项真实收据、历史及归档。移走文件可能令原播放列表失效；文件可能是唯一原件，不承诺可以重新下载或丢弃。播放列表、播放器数据库和未列入的文件保持原样。

验证使用源格式对应的自建列表，涵盖编码路径、file URL、重复/网络/缺失/别名、保护、HLS、列表变化和结构化确认。自建有效 PCM WAV 经正式 Mole + 原生废纸篓处理，核对收据后仅为测试取回，确认 WAV 内容、列表、未列入文件及归档读取保持原样；这不代表应用内恢复已验收。浏览器流程验证原生文件选择的传输模拟、取消、来源切换、旧选择撤销、确切选择及单独确认；不能替代实际 App 窗口或真实 VLC 导出交互验收。此节点默认 Rust 测试 590 通过、79 忽略，前端 205 通过，相关页面回归 11 通过；arm64 ad-hoc App 构建与嵌套完整性检查通过，未安装或公开发布。

这条流程补齐基于播放列表的离线影音整理入口，不代表完成所有影音软件专项。播放器自管离线索引、Music/Spotify/播客等实际下载库与受 DRM 管理的内容仍需对应来源适配和保护验证，不扫描或删除未知数据库；已补 [影音播放预览](file-preview.md) 的第一节点，外接卷、应用内恢复及实际 App 新入口窗口继续待补。

## 聊天附件：Telegram Desktop 导出包

在来源中选择“Telegram 聊天导出附件”，选择 Telegram Desktop JSON 格式导出的 `result.json`，扫描后预览、筛选、逐项选择，再独立确认真实移入废纸篓。切换清单撤销旧选择，即使两个包都在同一账户目录下也不复用旧确认。取消文件选择不改变当前来源；新来源没有选清单时不能扫描。

Telegram 官方提供 JSON/HTML 导出，见 [官方导出说明](https://telegram.org/blog/export-and-more)。本节点根据 [Telegram Desktop JSON 导出实现](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/export/output/export_output_json.cpp) 适配单个聊天，以及账户导出 `chats.list` / `left_chats.list` 中消息的顶层 `file` / `photo` 相对路径。只定位选定导出包内的普通文件，不进入软件内部数据库，不使用浏览器链接、不发下载或线上删除请求。HTML、未知结构、未导出/缺失内容、富消息内部附件等未支持范围保留；不递归推断其他字段里的文件。缩略图、头像、故事、正文索引和未列入附件保持原样。

只支持本账户普通目录内、同卷、本地已落地的单链接文件。清单须为本账户单链接 `result.json`，最大十六 MiB；每组聊天列表最多二百个聊天，合计最多两万条消息，候选最多两千项、七 MiB 序列化快照。读取和候选观察沿用十秒预算与取消检查，超过格式/消息预算时拒绝，不把没检查的内容视为已清理。排除绝对/网络/越界/歧义路径、链接、硬链接、应用/图库包、隐藏、敏感、Library、保护与云占位。路径取 JSON 原始相对路径，不作为 URL 解码或执行任何指令；已知正文索引名 `result.json`、`export_results.html`、`messages.html` 及其数字分页名整体保留，即使清单附件字段指向它们也不纳入。同名真实附件也会保留，不扩大解释为所有同扩展名文件均安全可处理。

仅提取附件字段，正文、发送者和聊天资料等未知字段在结构化读取中跳过，不向页面、执行计划、历史或 AI 返回这些内容；原始 JSON 字节在有界本机读取期间仍暂存内存。持久计划只保存文件路径、确切 ID、来源与身份观察。候选需要处于该清单所在包内，运行边界复查清单及文件身份；清单变化即保留，并要求重新扫描。新来源沿用 `softwareContent` 结构化确认、正式 Mole 路径规则、FULL 同步意图、逐项真实收据、取消/中断和执行归档；旧来源记录仍按原字段读取，新来源记录需要包含本功能的客户端。

附件可能是唯一副本或含后续编辑，能否重新取得未知。移走附件可能破坏导出包中的对应链接，正文索引不被改写；这不代表线上聊天被清理，也不发送删除消息。应用内恢复本来源尚未接入，可按实际收据在 Finder 核对；清理整个导出包、导出包之外的聊天附件、微信/QQ/其他聊天软件内部附件、富消息与实际聊天软件的导出交互仍在完整范围中继续推进。
