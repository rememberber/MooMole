# 用户登录配置与后台管理

2026-10-30：应用页增加“已安装应用 / 启动与后台”切换。读取当前用户登录配置，逐项查看程序与参数，单独确认暂停或恢复；结果和核对入口同时出现在操作历史。工具栏提供固定的 macOS 系统登录项设置入口。

## 首条实际操作流程

范围固定为本账户 `~/Library/LaunchAgents` 的普通 `.plist` 文件，不接收前端传入的配置路径、程序、参数、服务标签、PID 或其他账户。先发现、审阅并选中确切项目 ID，检查结构化计划，三十秒内单独确认执行。清单五分钟过期，确认单次使用并有单调时间期限。操作后原清单撤销，需要重新读取。

暂停使用同一物理目录内不覆盖的原生更名，把确切文件改为 `.plist.moomole-disabled`；保留原字节、文件身份及属性，不删除或重写 plist。再对结构化状态中与配置标签、程序和参数一致的当前用户后台注册请求 `launchctl bootout`。未观察到注册时只暂停配置；未知结构或标签冲突不推断归属。恢复必须有 MooMole 暂停记录、实际收据、原暂停位置的文件身份/内容见证；先更名回原 `.plist`，再按需要请求 `launchctl bootstrap`，不强行启用系统的禁用覆盖，也不保证应用功能、所有子进程或其他来源已停止。

文件在目录中不表示系统允许它启动，也不证明当前运行。暂停可能中断同步、更新或其他后台工作；恢复可能立即运行当前程序。应用可能自行重建登录配置或重新注册，不能承诺永久禁止该软件运行。原名称占用时不覆盖、不自动换名，后台状态变化时不发出旧请求。

## 保护和来源

仅处理本账户的单链接、本地落地、非别名普通文件及物理目录。配置和目录不得允许其他账户改写；程序须属于本账户或 root，且不可被其他账户改写。排除系统、Apple/客户端标签、本应用位置、用户保护、相对程序位置、特权账户/根目录语义和未知配置结构。对大小写变体也采取保守保护，不以此放宽权限或绕过 Mole 原有规则。

扫描最多二百个目录条目，累计配置读取约八 MiB，每个配置最多 512 KiB；按十秒预算逐项检查，单文件读取也有独立预算。程序读取最多 256 MiB；参数最多 128 项、合计 32 KiB。达到上限、配置未知、权限/本地状态不明或取消均保留未检查范围，不把未发现条目表述成没有登录项。同标签配置同时发现时禁止处理；不把路径线索当作某 App 的独占所有权。

配置由 Foundation 属性列表接口解析。后台状态只读 `SMJobCopyDictionary` 返回的结构化标签、程序、参数和可选 PID；此接口已弃用、返回结构可能变化，因此动态加载系统框架并严格检查，不存在或无法适配时拒绝操作。`launchctl` 仅使用固定系统路径和当前 UID 的 GUI 域，命令退出状态用于请求结果，不解析终端文案决定目标。所有重新验证、确认和实际操作均在原生层完成，不依赖付费证书或常驻特权 helper。

来源依据：Apple 的 [launchd 使用说明](https://support.apple.com/guide/terminal/apdc6c1077b/mac)、系统 SDK `launchd.plist(5)` 对 `.plist` 名称的要求，以及 [SMJobCopyDictionary 文档](https://developer.apple.com/documentation/servicemanagement/smjobcopydictionary(_:_:)) 与系统 SDK `ServiceManagement.h` 的兼容性说明。系统设置入口使用 `SMAppService.openSystemSettingsLoginItems`，存在性和方法可用性按运行时检查。

## 持久记录、取消与恢复边界

独立 `startup_management` 表在首次操作时创建，沿用 FULL 同步的应用 SQLite 连接。更名前保存完整结构化计划与意图，核对更名后保存实际收据与文件见证，后台请求前再次持久保存意图，最后保存配置与后台观察结果。保留用户原文件，未知不自动回滚、重复请求或删除其他文件。

`startupmanagement` 使用专用任务入口、互斥注册、更新租约和受限检查槽位。取消只阻止后续步骤，不能撤销已完成的更名或系统请求；配置已改变而后台请求取消、失败或无法核对时明确为部分完成。重启只将未结束意图标为中断，不自动启动、停止、恢复或继续任何后台任务。

部分完成、未知或中断记录未核对前阻止新的启动修改。用户核对两个配置位置与系统后台状态后，可在历史记录“已核对”，原结果继续保留，不改成成功。之后仍须重新读取、选择和确认；只有可靠暂停收据且当前文件未变时才可应用内恢复。移动后尚未保存可靠收据就中断的情况保留人工核对边界。

本轮最多六十四条独立记录，不静默删除；独立日志的导出、容量管理和更完整冲突恢复仍待实现。该表没有改写原有 SQLite v8 清理/卸载/维护日志，也未纳入原有可携带执行归档。
