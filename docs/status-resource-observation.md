# 状态采集的限时资源观察

2026-10-21。脚本：`scripts/observe-status-resources.mjs`。这是本机开发验收工具，不是用户界面的后台监控或性能评分。

## 使用

1. 运行当前构建的 MooMole，等待首页单次状态任务结束。
2. 在系统状态选择需要验证的周期并开始持续采集，保持页面可见。
3. 从本机进程列表核对 `.app/Contents/MacOS/moomole` 主进程 PID。
4. 将下例 `YOUR_APP_PID` 替换为该 PID，输出使用尚不存在的新文件名：

```bash
node scripts/observe-status-resources.mjs --pid YOUR_APP_PID --seconds 180 --output local-artifacts/status-resource-new.json
```

仅支持 macOS，观察时间须为 5–3600 秒，默认 180 秒。输出父目录需已存在；文件以 0600 与排他新建写入，不覆盖已有报告。`local-artifacts/` 不进入版本控制。

## 核对与终止

工具不启动、切换或停止任何任务，不发送进程信号，也不读取状态快照/用户文件。通过固定 `/bin/ps`、C locale 和有上限的命令输出，约每 5 秒读取：

- 指定 App 的主进程 PID、父进程、启动时间、可执行路径、ps CPU 与 RSS。
- 主进程下与当前 `.app/Contents/Resources/mole/bin/status-go` 路径相符的直接子进程；每次须恰有一个，命令只接受 `--watch --interval 1s/2s/5s`。
- App/采集器的身份在后续观测保持一致，启动时间或路径变化、进程重启/退出、没有或多个采集器、读取超时/输出无法识别时停止观察，报告 interrupted 与原因，退出码为 1。

满足期限且各观测有效时报告 completed；它只说明完成这次受限观察，不是资源质量通过结论。用户暂停、离页或最小化导致采集器结束时，该报告应中断，而不能自动启动新采集器来补足时长。

## 度量限制

RSS 按 KiB 除以 1024 展示 MiB，是进程驻留报告值，不是物理 footprint 或整机内存。ps `%CPU` 保留为报告样本；样本均值不是 CPU 时间积分，也不是能耗。

范围仅包含 App **主进程和直接采集器**，不包含 WebView 渲染进程、GPU、其他助手、系统命令后代或整机耗电/温度。短期内存范围/首尾值不能证明长期无泄漏；不同周期也不能仅凭不同系统负载下的短测断言更省电。完整资源/能耗长测、旧系统/Intel 与休眠矩阵仍是独立发布验收条件。

界面趋势的 120 份/5 分钟上限由普通回归覆盖；真实 App 能否持续达到上限与取消后回收，需结合原生界面和任务记录核对，不能单靠此 ps 报告推断。
