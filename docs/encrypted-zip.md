# ZIP 密码解压

2026-11-03：已有压缩包入口支持为 ZIP 输入密码，先完整读取与核对全部内容，再独立确认解压到新的文件夹。首条流程支持现有存储/Deflate 范围内、整包可用同一密码读取的 WinZip AES 与旧式 ZipCrypto 条目，也允许加密和普通条目混合。空文件、UTF-8 名称、隐藏项和原有目录/容量/链接/越界保护继续适用；TAR 输入密码会被拒绝。没有新增加密压缩包创建、密码破解、自动猜测或加密中央目录支持。

密码不作 trim 或 Unicode 规范化，接受 1–1024 字节。前端只在本次 `prepare_zip_extraction` 传入，提交后清空输入；执行只发送单次计划 ID、请求 ID 和明确确认，不再次发送密码。更换来源也清空输入。原生侧使用不支持克隆、Debug 或序列化的独立密码类型，持有 `Zeroizing<Vec<u8>>`，只放在实时计划中；撤销、过期、执行结束或失败后随计划释放。临时快照仍是原 ZIP 的密文字节；检查阶段不另写解密正文副本。密码不写入草稿、记录、SQLite、日志或只读归档。不承诺擦除 IPC、JavaScript、依赖内部或操作系统中的所有临时副本，也不将此流程称为凭据保险库。

准备阶段对每项完整解密、解压并读取到 EOF，沿用总量/单项边界和 SHA-256 绑定；WinZip AES 的认证标签与 ZIP 读取完整性由固定 zip 库检查，缺失/错误密码、认证失败或结构错误拒绝整个计划。旧式 ZipCrypto 的校验不能认证来源，弱密码与旧式 ZIP 加密不能提供可靠保密性。密码输入和校验成功也不等于文件可信，不自动打开或执行输出。zip 库自身提示密码 API 未完成独立密码学正确性审阅，本节点未将其描述为经过安全审计；更多真实压缩器兼容和依赖审阅仍包含在发行待办中。

确认仍为两分钟单次有效，执行前继续核对源身份、密文摘要、隔离属性、保护和目标。使用保留的内存密码读取匿名 ZIP 快照，逐项写入目标 FD 下的私有暂存目录，读回正文并核对清单，再不覆盖发布。默认输出仍为文件 0600、目录 0700，原压缩包保留且隔离属性不剥离。Mac 属性恢复仍需另外勾选并通过既有配对/属性规则；本轮没有把任意加密 ZIP 当成完整 Mac 备份。

检查结果、持久记录和历史增加可选 `encrypted: true`，明确说明输出是明文、文件名和历史范围仍可见；该字段不携带密码或解密权。旧记录不含该字段仍沿用原解释。密码解压记录采用 v7 便携归档，完整保留范围和逐项结果；原生与前端都拒绝降级或错配标头，导入只读，不恢复密码、实时计划或执行许可。v1–v6 其他记录的既有格式不变。发布后结果丢失仍在首次历史对账时记为 unknown，阻断后续新操作；不从历史取密码、不自动解密或重放。

原生验证使用系统 TempDir：独立 Python/Apple CommonCrypto 生成的 WinZip AE-2 AES-256 ZIP（UTF-8、加密空文件和普通条目），以及系统 `/usr/bin/zip` 生成的 ZipCrypto ZIP，均经生产检查、真实解压发布、内容读回、隔离属性保留、SQLite 重开和 v7 归档逐项读回。测试生成器仅包含公开固定测试密码/盐，不用于生产加密；系统 zip 参数中的密码也仅为该公开测试值，产品不通过外部命令传递用户密码。错误密码、密文篡改、长度限制、取消、TAR 范围及完成记录丢失另有验证；原 ZIP 和未选文件保持。全部样例同次退出回收，未在 home 或资料目录创建测试目录。

精简证据收尾保存在 `.cache/verification/native-evidence.json` 的 `encrypted-zip-native.json`、`encrypted-zip-lost-native.json` 和 `encrypted-zip-protocol.json`。页面验证默认不确认、明文范围、错误密码清空、密码只传准备、一次执行及中英日说明；浏览器夹具不替代实际 App 原生窗口。实际 App 权限/文件选择器、更多真实加密工具/编码/格式、加密与 Mac 属性组合、最低系统/Intel、大包及完整生命周期仍待补。本节点不打包 DMG、不安装或发布，完整目标继续保持。
