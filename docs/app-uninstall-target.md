# 完整 App 包的原生处理核心

2026-10-24：`uninstall_target.rs` 已实现完整 App 包的原生废纸篓处理和调用后收据核对，现由 [封闭执行器](app-uninstall-execution.md) 串联一次选择、当次条件与 [专属持久记录](app-uninstall-journal.md)。已有后端提交/取消/读取 IPC，[前端入口](app-uninstall-interface.md) 已有自建包正常路径证据，完整实际发布 App 验收仍待完成；[独立卸载计划](app-uninstall-plan.md) 本身继续不可执行。

## 调用前的范围与复核

`PreparedBundle::prepare` 只接收后端持有的独立计划和上下文，先重新核对计划及保护规则，再绑定完整包快照和 Foundation 文件对象引用。原生核心目前只准备当前普通账户所有、已落地的本地目录；其他所有者和权限路线没有因此开放。

处理前再次核对原路径/祖先、对象引用解析位置、完整包身份/主程序/内容清单、计划期限和账户，再观察目标与直接父目录的卷、访问、ACL、锁定属性等条件。任何未知或拒绝都在调用系统 API 前返回错误，不修改权限、属性或保护规则。

调用者还必须提供最终检查：确认未撤销、源计划/保护/运行条件仍成立、任务未取消、操作意图已持久提交。当前内部回调本身不提供这些证据；测试中的放行仅是 fixture，不能作为正式资格。没有无检查参数的便捷执行入口，也没有把普通日志文件目标扩成目录。

## 原生结果与收据

使用 `NSFileManager.trashItemAtURL`，传递绑定的文件引用；仅记录系统返回的实际位置，不猜测废纸篓路径、不搜索替代对象。App 收据使用独立类型，基础设备/inode 沿用十进制字符串编码，另附实际观察到的包清单。

仅当系统调用成功、实际目标为原设备/inode/类型/所有者/权限及原内容、身份文件/主程序/后代清单一致、原父目录身份未变化且原位置不存在时，结果为 `Moved`。同设备移动会改变包根路径及 ctime；仅根 ctime 允许该差异，根的其他已绑定属性和后代证据继续比较。

调用 API 后的错误、缺少位置、身份/内容变化、原位置出现替代包、访问拒绝或超预算，一律返回 `Uncertain`，有观察收据则保留；不能当作已知未修改、自动重试或自动恢复。调用前错误与调用后不确定是不同边界，后续记录层必须分别保存。

## 废纸篓位置的只读观察

本机允许打开确切的废纸篓对象，却拒绝打开 `.Trash` 父目录；此边界也曾见于 [普通文件收据定位](execution-location.md)。源路径仍使用严格逐级句柄 `AnchoredPath`，没有权限回退或放宽。

调用后另用 `ReturnedPath`：逐级读取祖先元数据并拒绝链接/特殊对象/云占位，使用内核 `O_NOFOLLOW_ANY` 打开系统返回的确切对象，前后核对祖先和持有对象。此标志不能与 `O_NOFOLLOW` 合并，本机合并会返回 `EINVAL`；未在错误后降级为允许跟随链接的打开。没有打开或枚举废纸篓父目录，也没有额外请求隐私权限。

包清单从已打开的 App 根句柄相对遍历，仍保留独立摘要域、链接字面值和原数量/深度/时间预算。返回位置的祖先不持有逐级目录句柄，因此它只是调用后只读证据，不能用于源计划、准备修改对象或授权处理。所有核对均非原子锁；最终检查后仍可能发生外部变化。

## 验证与剩余关口

新增 9 项普通 Rust 测试，覆盖实际计划/保护绑定、引用取得期间替换、源包/祖先/深层内容/链接/主程序变化、期限/账户/权限/最终回调拒绝、返回位置缺失/替换/链接/系统错误及整数编码；另验证确切位置打开与持有期间的祖先/对象替换。

显式原生测试只处理新建临时 App，包含框架 `Versions/Current` 链接、包外链接及 Unicode/引号/通配符字面名称。四种情况通过（0.22 秒）：正常移入、调用前变化拒绝、最终检查后原包移位且原处有替代包、最终检查后深层内容变化。后三者分别为调用前拒绝或调用后待核实；未选替代包保留。每个实际移动的原包均按系统确切收据、原设备/inode核对后无覆盖取回，包外数据保持原值。

首轮误将源路径逐级打开用于收据核对，返回待核实并保留测试恢复记录；修正过程还发现上述标志组合问题。两份遗留自建 App 均通过显式测试专用恢复入口核对原身份/内容后取回；此入口只存在于测试编译、必须传入本测试自有记录，不是产品恢复接口。测试记录同步写入自有目录用于失败救援，不是正式 SQLite 执行记录或崩溃验收。

以上原生核心验证没有处理已安装应用、真实关联数据或系统设置，没有新授权窗口。后续已补 [执行器的真实 Mole/系统废纸篓联验](app-uninstall-execution.md)，仍使用自建包；它不代替实际打包 App 的用户选择/确认/历史界面、取消/强杀/重启、Finder 放回/冲突、跨卷或完整权限矩阵。[首发卸载门槛](first-release-execution.md) 保持未完成。
